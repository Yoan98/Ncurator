# UI 整体风格

## 0. 文档边界

- 本文档只定义视觉系统与通用交互 affordance。
- 用户可见功能、操作逻辑、状态反馈和验收标准统一放在 `doc/prd/**`。
- 新增或修改业务功能时，不要把流程规则、业务状态和功能验收写回本文。
- 页面结构可以描述视觉骨架与空间关系，但不在本文定义入口编排、控件顺序、状态流转或业务分支。

## 1. 设计语言

- 全前端统一使用 **文档工作台主题**：浅灰导航、白色主区、细分割线、紧凑控件和轻量浮层。
- 整体气质保持安静、克制、密集、可扫描。层级主要通过留白、文本权重、浅灰状态和稳定对齐表达。

## 2. 布局原则

### App Shell

- 页面骨架采用左侧浅灰 sidebar、顶部细线 topbar、中间白色文档流和底部输入区的结构。
- Sidebar 宽度固定 `240px`，与页面式配置区侧栏保持一致；背景、hover、选中态统一复用同一套视觉规则。
- Topbar 保持紧凑、弱存在感，使用细分割线和轻量图标表达层级。
- 主内容区使用白底文档流。
- 文档流内容居中显示，常规阅读宽度控制在 `760px-920px`，侧边面板与主文档流保持清晰分区。

### 页面式配置页

- 配置型页面使用页面式布局。
- 配置页可以有顶部标题和内容面板，但视觉仍应使用白底、浅灰导航、细分割线和紧凑列表。
- 配置页优先使用分区标题、列表行、table/database 和表单行组织内容。

### 输入区与浮层

- 底部输入区使用轻浮层视觉：白底、细边框、低圆角、轻阴影。
- Focus 状态使用蓝色边框 (`accent-blue`) 和淡蓝色阴影，视觉反馈清晰但不突兀。
- 输入框文字使用 `15px` 字号，`leading-6` 行高，最小高度 `32px`。
- 工具栏控件使用 `text-faint` (`#91918E`) 颜色，包括图标、文字和下拉箭头，保持低调。
- 输入区工具栏保持紧凑：左侧放模式和范围，右侧放状态和动作。
- 工具栏控件使用 `11px` 字号，高度 `22px`，间距紧凑（`gap-1.5`）。
- 选择器类控件应设置最大宽度，防止工具栏因文案过长失衡。
- 状态指示器应优先使用低干扰、可扫描的图形化表达。
- 发送/停止按钮使用圆形（`rounded-full`），尺寸 `28px`（h-7 w-7），图标 `12px`（h-3 w-3）。
- 发送按钮默认使用深色背景 (`#37352F`)，禁用状态使用浅灰背景 (`#EEEEEC`) + 灰色图标。
- 浮层、候选列表和轻通知都应复用白底、细边框、轻阴影、紧凑列表的同一视觉语言。

## 3. 配色

### Token

- `page`：`#FFFFFF`
- `canvas`：`#FFFFFF`
- `sidebar`：`#FBFBFA`
- `surface`：`#F4F4F2`
- `surface-hover`：`#EFEFEE`
- `line`：`#EEEEEC`
- `line-strong`：`#E0DFDC`
- `text`：`#37352F`
- `text-soft`：`#787774`
- `text-faint`：`#91918E`
- `accent`：`#2F3437`
- `accent-blue`：`#0B6BCB` (第二强调色，用于 focus、链接等)
- `accent-blue-hover`：`#0958A5`
- `red`：`#B3261E`
- `red-bg`：`#F8EBE9`
- `green`：`#2F6F4E`
- `green-bg`：`#EDF6EF`
- `blue`：`#2F5F8F`
- `blue-bg`：`#EDF3F8`
- `yellow-bg`：`#FBF3DB`
- `amber`：`#B45309`
- `shadow-float`：`0 16px 40px rgba(15, 15, 15, 0.12)`
- `shadow-soft`：`0 8px 24px rgba(15, 15, 15, 0.08)`

### 使用规则

- App 外层、主阅读区和配置页使用 `page/canvas` 纯白底，侧栏使用 `sidebar`。
- `surface/surface-hover` 用于 hover、选中、弱提示和 tag 等局部层级表达。
- 常规状态优先使用灰阶、图标与文案；可用低饱和绿、蓝、黄 tag 表示成功、信息、待处理。
- 危险、拒绝、错误才使用 `red/red-bg`。
- `accent-blue` 用于输入框 focus、链接和操作按钮悬浮态。
- 状态色使用低饱和表达，彩色元素控制在局部强调范围内。
- 预设模型列表行展示服务商图标、展示名、横向排列的价格档位钱袋图标（较低 1 / 适中 2 / 较高 3）和选中勾；菜单宽度按内容自适应。短介绍、价格档位文案与是否视觉理解放在较窄的 hover/focus 信息侧栏；侧栏固定贴在菜单右侧（约 1px 间距），空间不足时整体左移菜单。自定义模型视图不展示该侧栏。
- Composer 计划进度使用约 24px 的中性环形进度，位于输入框正中上方；hover、focus 或点击展开轻量 Todo 浮层，仅使用空圆圈、勾选圆圈和计划文案。正常完成短动画后隐藏，中断状态保留。
- Thought 与最终回答都使用 Markdown；Thought 字号和标题间距更紧凑，工具聚合、展开详情和红色失败样式保持不变。

## 4. 尺度系统

### 圆角

- 控件：`6px`
- 内嵌块：`8px`
- 输入容器：`10px-12px`
- 浮层：`8px-10px`
- pill / tag：`999px`

### 字级

- 元信息：`12px`
- 正文：`14px`
- 区块标题：`15px-16px`
- 页面标题：`28px-44px`，仅文档式页面标题使用。
- 配置页和面板标题优先使用 `18px-28px`。
- 字级层次保持收敛，避免使用大量相近字号。

### 间距

- 紧凑控件内边距优先使用 `6 / 8 / 10`
- 面板间距优先使用 `12 / 16 / 20`
- 页面级容器优先使用 `20 / 24 / 32`
- 长文档流上下留白可以更大，空状态和首条内容允许使用 `64 / 80` 的顶部空间。

### 阴影

- 层级优先通过留白、细分割线和浅灰状态表达。
- 输入容器、popover、modal 可使用轻浮层阴影：`0 16px 40px rgba(15, 15, 15, 0.12)`。
- 阴影使用中性、轻量参数。

## 5. Surface 层级

- `canvas`：App 外层和主内容区底色，与 `page` 同为纯白。
- `sidebar`：导航和辅助入口。
- `page`：主文档区、表单内容和列表内容。
- `surface`：选中态、用户消息、弱提示、tag、列表 hover 等局部表面层。
- `line`：不同区域之间的弱边界。
- `accent`：主按钮和关键文字动作。

## 6. 组件规则

### Button

- 主按钮只给主动作，深灰底白字。
- 次按钮透明或白底，hover 使用浅灰底。
- 图标按钮使用 `28px-32px` 固定尺寸和 `6px` 圆角。
- 普通交互以灰阶 hover 表达反馈。

### Input / Select / Input Container

- 输入区保持紧凑。
- focus 使用 `accent-blue` 边框和淡蓝色 ring。
- 输入容器使用白底、细边框、底部浮层和轻阴影。
- Select、popover、引用、搜索和候选弹层共享边框、圆角、阴影和紧凑列表样式，并优先保证标签、路径和状态可扫描。

### Tag / Status

- tag 用于短状态、来源词和数量等扫描型信息。
- tag 圆角可保持 pill，但视觉重量要低于正文标题。
- 成功、信息、待处理使用低饱和浅底；失败、拒绝、危险态使用红色。
- tag 文案应短，优先使用状态词、来源词或数量。

### Table / Database

- 表格应使用极淡细线、白底、近白表头和紧凑行高。
- 行 hover 使用 `surface-hover`。
- 列表项保持行式信息组织。
- 当信息主要依赖比较、扫描、排序或批量浏览时，优先使用 database/list row。

### Icon

- 默认使用线性图标。
- 小图标 `14px-16px`，常规图标 `18px-20px`。
- 图标优先承担扫描职责：来源、状态、动作、风险、模式。

### Notice / Empty

- Notice 使用低饱和浅底和小图标，说明当前状态、风险或下一步动作。
- Empty state 使用轻量图标和短标题。
- 空状态标题使用操作导向表达，如“从一个问题开始”。

### Approval

- 需要明确确认的界面应保持信息结构清晰、操作层级稳定。
- 颜色、按钮、tag、边框和间距应服从全局视觉 token。

## 7. 文字与文案

- 页面文案保持短句和高可扫描性。
- tooltip、tag、状态条承载简短补充信息。
- 标题只负责定位，辅助文案只负责补充范围或行为。
- 界面文案优先描述对象、状态和动作。

## 8. 动效与交互

- 默认过渡时长 `160-180ms`。
- hover 使用浅灰底、边框变色或轻微透明度变化。
- 同类元素必须共享同一套 hover / active / focus 反馈。

## 9. Cursor 规则

- 可点击元素统一使用 `pointer`。
- 文本输入、`textarea`、`contenteditable` 使用 `text`。
- 帮助提示使用 `help`。
- 禁用态统一使用 `not-allowed`。

## 10. 辅助功能

- 所有交互元素必须可键盘访问。
- focus ring 必须清晰可见。
- 文本和背景对比度需满足正常阅读。
