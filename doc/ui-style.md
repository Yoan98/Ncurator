# UI 整体风格

## 1. 设计语言

- 全前端统一使用 **文档工作台主题**：浅灰导航、白色主区、细分割线、紧凑控件和轻量浮层。
- 整体气质保持安静、克制、密集、可扫描。层级主要通过留白、文本权重、浅灰状态和稳定对齐表达。

## 2. 布局原则

### App Shell

- 页面骨架由浅灰导航、紧凑顶部栏、白色内容区与按需出现的辅助面板组成；输入区、列表区和阅读区根据内容职责布局。
- 导航侧栏以 `240px` 为常规宽度基准，可调整面板的范围由页面需求确定；同类侧栏的背景、hover 和选中态复用同一套视觉规则。
- Topbar 保持紧凑、弱存在感，使用细分割线和轻量图标表达层级。
- 主内容区使用白底文档流。
- 文档流内容居中显示，常规阅读宽度 `760px`，侧边面板与主文档流保持清晰分区。
- 可调整宽度的分隔线及其透明热区使用水平双向调整光标（`ew-resize`），悬停与拖动时保持同一指示。

### 页面式配置页

- 配置型页面使用页面式布局。
- 配置页可以有顶部标题和内容面板，但视觉仍应使用白底、浅灰导航、细分割线和紧凑列表。
- 配置页优先使用分区标题、列表行、table/database 和表单行组织内容。
- 所有设置页内容居中，统一限宽 `1080px`；页头使用 `24px` 标题和可换行的简短说明，不增加标题图标框。
- 同类设置使用分组面板：组标题位于面板外，白底、`10px` 圆角、浅灰细边框，无阴影；组内用细线分隔。表单行上下留白 `16px`，标题 `14px`，说明 `12px-13px`。
- 行内操作右对齐，常规控件高 `32px`，选择器宽 `160px`；窄窗口允许说明换行和行内控件换到下一行，保持完整可见。树与表格保留各自滚动区域。

### 配置表单

- 伙伴、skill 与定时任务的创建/编辑共用右侧滑出表单：白底、细分割线、相同遮罩和动效，标题与底部操作固定，仅正文滚动。
- 常规表单宽 `480px`，正文编辑表单宽 `720px`；窄窗口不超过可用视口。未保存关闭确认，提交期间阻止重复操作。
- 表单采用文档式布局，所有字段保留可见 label；label 统一为 `13px` 正文色、相同间距与必填星号，不能用 placeholder 代替。名称可使用标题字号。输入默认只有浅底线，聚焦仅底线变蓝，不出现四边框或外圈阴影；选择器、时间控件沿用同样底线反馈，菜单保持轻浮层。
- Markdown 编写区域不套边框，使用紧凑格式工具栏和单栏正文，标题级别提示位于左侧；内容 label 与其他字段一致，不提供源码切换。附带文件用可展开的轻量行组织。
- 用量指示共用 `20px` 容器、`16px` 环形图，常规灰色，达到 70% / 90% 时分别为橙色 / 红色；实际用量超过上限时圆环填满，悬浮内容和可访问名称仍反映实际值。
- 顶栏工具按钮高 `28px`、字号 `12px`、图标 `16px`；表单底部按钮高 `32px`。同区域按钮圆角、内边距和间距保持一致。
- 选择列表按内容撑高，仅空态保留最小高度；超出最大高度后内部滚动，不为单项留下空白区域。

### 输入区与浮层

- 多行输入容器使用轻浮层视觉：白底、细边框、低圆角、轻阴影。
- Focus 状态使用蓝色边框 (`accent-blue`) 和淡蓝色阴影，视觉反馈清晰但不突兀。
- 长文本输入使用 `14px-15px` 字号、约 `24px` 行高；紧凑表单使用 `13px-14px` 字号，保持可读性与稳定行高。
- 工具栏控件使用 `#91918E`（`--notion-text-faint`）颜色，包括图标、文字和下拉箭头，保持低调。
- 工具栏控件使用 `12px` 字号，高度 `28px`（`h-7`），间距紧凑（`gap-1.5`）。
- 选择器类控件应设置最大宽度，防止工具栏因文案过长失衡。
- 状态指示器应优先使用低干扰、可扫描的图形化表达。
- 独立主动作可使用圆形图标按钮；主动作采用深灰底白色图形，禁用态使用浅灰底和弱化图形。
- 浮层、候选列表和轻通知都应复用白底、细边框、轻阴影、紧凑列表的同一视觉语言。

## 3. 配色

### Token

下列为概念 token，对应实现中的 `--notion-*` CSS 变量（如 `page` → `--notion-page`）；阴影对应 `--shadow-md`（soft）/ `--shadow-lg`（float）。

- `page`：`#FFFFFF`
- `canvas`：`#FFFFFF`
- `sidebar`：`#FBFBFA`
- `surface`：`#F4F4F2`
- `surface-hover`：`#EFEFEE`
- `line`：`#EEEEEC`
- `line-strong`：`#E0DFDC`
- `text`：`#37352F`
- `text-soft`：`#787774`
- `text-faint`：`#91918E`
- `accent`：`#2F3437`
- `accent-blue`：`#0B6BCB` (第二强调色，用于 focus、链接等)
- `accent-blue-hover`：`#0958A5`
- `red`：`#B3261E`
- `red-bg`：`#F8EBE9`
- `green`：`#2F6F4E`
- `green-bg`：`#EDF6EF`
- `blue`：`#2F5F8F`
- `blue-bg`：`#EDF3F8`
- `yellow-bg`：`#FBF3DB`
- `shadow-float`：`0 16px 40px rgba(15, 15, 15, 0.12)`
- `shadow-soft`：`0 8px 24px rgba(15, 15, 15, 0.08)`

### 使用规则

- App 外层、主阅读区和配置页使用 `page/canvas` 纯白底，侧栏使用 `sidebar`。
- `surface/surface-hover` 用于 hover、选中、弱提示和 tag 等局部层级表达。
- 常规状态优先使用灰阶、图标与文案；可用低饱和绿、蓝、黄 tag 表示成功、信息、待处理。
- 危险、拒绝、错误才使用 `red/red-bg`。
- `accent-blue` 用于输入框 focus、链接和操作按钮悬浮态。
- 状态色使用低饱和表达，彩色元素控制在局部强调范围内。

## 4. 尺度系统

### 圆角

- 控件：`6px`
- 内嵌块：`8px`
- 多行输入容器：`14px-18px`；紧凑表单输入容器：`10px-12px`
- 浮层：`8px-10px`
- pill / tag：`999px`

### 字级

- 元信息：`12px`
- 正文：`14px`
- 区块标题：`15px-16px`
- 页面标题：`28px-44px`，仅文档式页面标题使用。
- 配置页和面板标题优先使用 `18px-28px`。
- 字级层次保持收敛，避免使用大量相近字号。

### 间距

- 紧凑控件内边距优先使用 `6 / 8 / 10`
- 面板间距优先使用 `12 / 16 / 20`
- 页面级容器优先使用 `20 / 24 / 32`
- 长文档流上下留白可以更大，空状态和首条内容允许使用 `64 / 80` 的顶部空间。

### 阴影

- 层级优先通过留白、细分割线和浅灰状态表达。
- 输入容器、popover、modal 可使用轻浮层阴影：`0 16px 40px rgba(15, 15, 15, 0.12)`。
- 阴影使用中性、轻量参数。

## 5. Surface 层级

- `canvas`：App 外层和主内容区底色，与 `page` 同为纯白。
- `sidebar`：导航和辅助入口。
- `page`：主文档区、表单内容和列表内容。
- `surface`：选中态、弱提示、tag、列表 hover 等局部表面层。
- `line`：不同区域之间的弱边界。
- `accent`：主按钮和关键文字动作。

## 6. 组件规则

### Button

- 主按钮只给主动作，深灰底白字。
- 次按钮透明或白底，hover 使用浅灰底。
- 图标按钮使用 `28px-32px` 固定尺寸和 `6px` 圆角。
- 普通交互以灰阶 hover 表达反馈。

### Input / Select / Input Container

- 输入区保持紧凑。
- focus 使用 `accent-blue` 边框和淡蓝色 ring。
- 输入容器使用白底、细边框、底部浮层和轻阴影。
- Select、popover、引用、搜索和候选弹层共享边框、圆角、阴影和紧凑列表样式，并优先保证标签、路径和状态可扫描。

### Tag / Status

- tag 用于短状态、来源词和数量等扫描型信息。
- tag 圆角可保持 pill，但视觉重量要低于正文标题。
- 成功、信息、待处理使用低饱和浅底；失败、拒绝、危险态使用红色。
- tag 文案应短，优先使用状态词、来源词或数量。

### Table / Database

- 表格应使用极淡细线、白底、近白表头和紧凑行高。
- 行 hover 使用 `surface-hover`。
- 列表项保持行式信息组织。
- 当信息主要依赖比较、扫描、排序或批量浏览时，优先使用 database/list row。

### Icon

- 通用图标从 `react-icons` 选用，不另绘 SVG；优先使用简约细线、轻量轮廓，同组图标使用一致的线条重量、视觉尺寸与对齐。已有类型标识和品牌图标保留其辨识特征，具体映射归业务规格。
- 同一语义图标在列表、输入内容及回显中保持一致；对齐按可见图形和文字基线核对，不能仅比较外框尺寸。颜色用于辅助识别，普通名称仍使用正文色。
- 过程层工具包加载使用蓝色扳手（`#2F5F8F`），skill 加载使用紫色厚书（`#8064A2`），均为 16px。名称使用正文色，标题为「加载 + 名称」；运行微光与失败提示独立于类别颜色，实时和历史保持一致。
- 小图标 `14px-16px`，常规图标 `18px-20px`。
- 图标优先承担扫描职责：来源、状态、动作、风险、模式。

### Notice / Empty

- Notice 使用低饱和浅底和小图标，说明当前状态、风险或下一步动作。
- Empty state 使用轻量图标和短标题。
- 空状态标题使用操作导向表达，如“从一个问题开始”。

## 7. 文字与文案

- 页面文案保持短句和高可扫描性。
- tooltip、tag、状态条承载简短补充信息。
- 标题只负责定位，辅助文案只负责补充范围或行为。
- 界面文案优先描述对象、状态和动作。

## 8. 动效与交互

- 默认过渡时长 `160-180ms`。
- hover 使用浅灰底、边框变色或轻微透明度变化；选择、悬停和焦点必须可区分。需要持续选择的列表由明确选择驱动 active 态，不能用临时 hover 代替。
- 同类元素必须共享同一套 hover / active / focus 反馈。

## 9. Cursor 规则

- 可点击元素统一使用 `pointer`。
- 文本输入、`textarea`、`contenteditable` 使用 `text`；其中的可点击对象使用 `pointer`，拖选或离开对象后恢复编辑控件原有光标。
- 帮助提示使用 `help`。
- 禁用态统一使用 `not-allowed`。

## 10. 辅助功能

- 所有交互元素必须可键盘访问。
- 键盘焦点必须清晰可见；选择行可使用中性灰背景，输入与操作按钮保留 focus ring。
- 文本和背景对比度需满足正常阅读；高亮、选区、状态底色及覆盖层不得遮住正文、图形或焦点。
