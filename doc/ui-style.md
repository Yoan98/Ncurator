## 核心设计语言

你是一个专业的前端开发者，专门使用 **Tailwind CSS**、**Ant Design** 和 **React Icons** 创建符合这个风格的界面。

---

## 配色规范

**背景色系**

- 主背景使用温暖的米色 `#F5F5F4`，不使用纯白色
- 卡片和输入框使用纯白色 `#FFFFFF`
- 悬停状态使用 `#F0F0EF`

**品牌色系**

- 主品牌色使用柔和的橙棕色 `#D97757`（赤陶色）
- 悬停状态使用 `#C66A4A`
- 浅色变体使用 `#F4E5DF`
- 极浅背景使用 `#FBF5F2`

**文本色系**

- 主文本使用深炭黑 `#1F1F1F`
- 次要文本使用中灰色 `#666666`
- 占位符和辅助文本使用浅灰色 `#999999`
- 永远不使用纯黑色 `#000000`

**边框色系**

- 使用 `#E5E5E4` 作为主要边框色
- 深色边框使用 `#D4D4D3`

---

## 视觉风格规则

**圆角**

- 按钮使用 8px 圆角（`rounded-lg` 或自定义）
- 卡片使用 12px 圆角（`rounded-xl` 或自定义）
- 对话气泡使用 16px 圆角，带一个小尖角（非对称圆角）

**阴影**

- 使用微妙、柔和的阴影
- 小阴影：`0 1px 2px rgba(0, 0, 0, 0.04)`
- 中阴影：`0 2px 8px rgba(0, 0, 0, 0.06)`
- 大阴影：`0 4px 16px rgba(0, 0, 0, 0.08)`
- 避免使用过深或过硬的阴影

**间距**

- 使用充足的留白，不要让界面显得拥挤
- 组件之间保持 32px (8) 的间距
- 元素内部使用 16px (4) 的 padding
- 页面边距最小 24px (6)

**过渡动画**

- 所有交互都要有流畅的过渡效果
- 使用 0.2 秒作为标准过渡时长
- 使用 ease-in-out 或 ease-out 缓动
- 悬停时可以有轻微的上移效果（-1px 到 -2px）

## Tailwind 使用规则

**页面背景**

- 使用自定义的米色背景色，配置在 Tailwind 主题中
- 类名示例：`bg-[#F5F5F4]` 或自定义 `bg-claude-bg`

**布局容器**

- 内容区域最大宽度 800px 到 1200px
- 使用 `max-w-4xl` 或 `max-w-5xl` 配合 `mx-auto`
- 充足的水平 padding：`px-6` 或 `px-8`

**文本样式**

- 正文默认 14px：`text-sm` 或 `text-[14px]`
- 行高使用 `leading-6`、`leading-7` 或 `leading-normal`
- 标题使用 `font-semibold` (600)，正文使用 `font-normal` (400)

**卡片样式**

- 白色背景 + 浅边框 + 微妙阴影
- 类名组合：`bg-white border border-[#E5E5E4] rounded-xl shadow-sm`
- 悬停时加深阴影：`hover:shadow-md`

**按钮样式**

- 主按钮：品牌色背景 + 白色文字 + 8px 圆角 + 悬停效果
- 次按钮：透明背景 + 浅边框 + 悬停时背景变色
- 文本按钮：无背景无边框 + 悬停时文字颜色变深

## Ant Design 配置规则

**全局主题设置**

- 在 ConfigProvider 中配置主题 token
- colorPrimary 设为品牌色 `#D97757`
- fontSize 默认 14px
- borderRadius 设为 8px
- colorBgLayout 设为米色背景

**组件使用规范**

- Button 组件默认使用中等密度；只有主操作或空态入口使用更大的尺寸
- Input / Select 默认维持 36px 到 40px 高度，避免在桌面工作台里显得臃肿
- Card 组件启用 `bordered={true}` 和适当的 `hoverable`
- Modal 组件使用柔和的背景遮罩
- Message 和 Notification 使用品牌色

**组件替换原则**

- 优先使用 Ant Design 的表单组件（Button、Input、Select 等）
- 使用 Ant Design 的反馈组件（Message、Modal、Notification）
- 布局和间距使用 Tailwind 实现
- 自定义视觉效果使用 Tailwind 实现

---

## React Icons 使用规则

**图标风格**

- 优先使用线性图标（Outline 风格）
- 推荐图标库：`react-icons/ai`、`react-icons/bi`、`react-icons/hi`
- 避免使用填充型（Filled）图标，除非需要强调

**图标尺寸**

- 小图标：16px (`w-4 h-4`)
- 常规图标：20px (`w-5 h-5`)
- 大图标：24px (`w-6 h-6`)
- 使用 `className` 控制大小和颜色

**图标颜色**

- 跟随文本颜色，使用 `text-current` 或继承父元素颜色
- 需要强调时使用品牌色
- 禁用状态使用浅灰色

## 常见场景设计指南

**对话界面**

- 用户消息靠右对齐，最大宽度 80%
- AI 消息靠左对齐，最大宽度 80%
- 用户消息：白色背景 + 浅边框 + 右下角小尖角
- AI 消息：品牌色极浅背景（`#FBF5F2`）+ 品牌色浅边框 + 左下角小尖角
- 消息之间间距 16px

**表单设计**

- 标签在输入框上方，字号 14px，字重 500
- 输入框高度 48px，内边距 12px 16px
- 输入框聚焦时显示品牌色边框和浅色外发光
- 错误提示使用红色文字，显示在输入框下方
- 辅助文字使用浅灰色，字号 12px

**卡片设计**

- 白色背景，12px 圆角
- 1px 浅边框（`#E5E5E4`）
- 微妙的阴影（`0 2px 8px rgba(0, 0, 0, 0.06)`）
- 悬停时阴影加深并轻微上移（-2px）
- 卡片内边距 24px

**导航栏**

- 背景色与页面背景一致或使用白色
- 高度 64px
- 底部有 1px 浅边框
- Logo 和导航项使用 Flexbox 水平排列
- 导航项悬停时显示品牌色或背景色变化

**统一工作台**

- 首页使用三栏心智模型：左侧轻量历史会话，中间对话主区，右侧内容与审阅面板
- 左侧会话区默认占比小，可收起展开；只负责切换会话与新建会话，不承载运行细节
- 中间 assistant 回复应优先展示最终回答，并以内嵌折叠区呈现步骤 summary、工具 badge、读取文件、修改文件与待确认修改入口
- 右侧默认承载搜索结果、文档查看和审阅差异；不再以时间线、原始 JSON 或调试检查器作为普通用户主视图
- `纯搜索` 与 `AI 对话` 共用同一输入区与页面骨架，只通过模式切换和提示文案强调语义差异
- 资料配置拆分为 `Settings -> 大模型`、`Settings -> 工作空间`、`Settings -> 网页资料` 三个独立工具页，右上角 `setting` 可直达，不再通过单页 tab 中转
- workbench 主区默认走“低装饰、高密度、强层级”路线，优先用字号、留白、分区线表达层级，不靠层层卡片堆叠
- 左侧会话列表使用更紧凑的条目式设计，避免粗重边框和过大的缩略块
- 底部 composer 只能有一个主输入焦点，主输入统一使用 `contenteditable`，禁止再次出现“输入框套输入框”
- `@` 触发的资料插入必须以内联 tag 形式和文本混排，不再额外渲染第二个范围输入框
- `@` 候选只允许来自当前选中工作区下的文件与目录，以及已配置的网页资料；不得返回其他工作区的本地范围
- composer 左下角统一收纳 `模式 / 模型 / 工作区` 选择器，作为低存在感工具条，而不是第二主输入区
- workbench 默认减少解释性文案，优先用 tag、图标、tooltip、状态色表达模式与范围语义
- composer 默认保持紧凑高度，优先压缩垂直留白与控件尺寸，不要为了视觉堆砌过高输入框
- 未实现的能力不要以前置入口或占位按钮出现；例如上传、语音等功能未落地前，不得占据 composer 主操作区
- 右侧内容面板与草稿审阅面板更接近 inspector，而不是一串独立运营卡片；大区块之间用分割和固定操作区组织信息
- 默认窗口尺寸需要服务三栏布局，首开应明显大于传统表单页，避免 workbench 在 1200px 级别宽度下拥挤

**草稿审阅中心**

- 审阅中心默认放在右侧常驻面板中，不使用阻断式弹窗
- 审阅面板默认包含 `差异 / 预览 / 来源` 三个标签页，并提供固定的接受、拒绝和提交操作栏
- 差异渲染按文档格式适配；`docx` 使用块级 before / after，文本类使用 hunk 视图，不强行统一成单一 git diff 形式
- 审阅状态色必须区分 `待审阅 / 可提交 / 提交中 / 已提交 / 有冲突 / 提交失败`
- 提交前校验区域必须始终可见，并明确显示“未决修改”或“源文件冲突”两类阻塞原因
- 提交成功后展示结果列表与打开/定位操作；提交完成后不再继续暴露草稿与预览文件入口

**Workspace 设置页**

- `Settings -> Workspace` 不是宣传页，优先按工具页思路设计：紧凑标题、直接操作、明确状态
- `Settings -> 网页资料` 也按工具页思路设计：来源列表与详情分栏，高级抓取规则默认折叠，不与本地工作空间混排
- `Settings -> 大模型` 以配置列表和当前启用状态为主，不使用大段说明或营销式 hero
- 顶部说明区保持单层结构，不使用过重 hero、过大标题或营销化文案
- workspace 列表与详情使用 master-detail 结构；列表项优先展示名称、路径、状态和关键统计，不再叠加过多内层小卡片
- 目录树、准备控制、网页资料列表保持统一密度，与 workbench 使用同一套字号和圆角尺度
- 全局 header 不再作为固定独立横栏存在；logo 和设置入口应融入页面 chrome 或 workbench 侧栏锚点中

**加载状态**

- 使用 Ant Design 的 Spin 组件
- 或者使用三个点的脉动动画（品牌色）
- 骨架屏使用灰色渐变动画

## 响应式设计规则

**断点使用**

- 移动端：小于 640px
- 平板：640px - 1024px
- 桌面：大于 1024px

**适配规则**

- 移动端：单列布局，内边距减小到 16px
- 平板：可以使用两列布局
- 桌面：多列布局，充足的间距
- 对话气泡在移动端可以占满宽度（最大宽度 100%）

---

## 辅助功能要求

**键盘导航**

- 所有交互元素必须可通过键盘访问
- 聚焦时显示清晰的品牌色外边框（2px）

**颜色对比度**

- 确保文本和背景的对比度符合 WCAG 标准
- 正常文本至少 4.5:1
- 大文本至少 3:1

**语义化**

- 使用正确的 HTML 标签（button、input、nav 等）
- 图标按钮必须有 aria-label
- 表单必须有正确的 label 关联

---

## 禁止使用的样式

❌ **不要使用纯白色 `#FFFFFF` 作为页面背景**
❌ **不要使用纯黑色 `#000000` 作为文本色**
❌ **不要使用紫色渐变**
❌ **不要使用过深的阴影**
❌ **不要使用尖锐的直角（0px 圆角）**
❌ **不要使用 Inter 字体（使用系统默认字体栈）**
❌ **不要让界面显得拥挤（必须有充足留白）**
❌ **不要使用过于鲜艳的颜色**

## 使用方法

### 提示词模板

```
请使用以下技术栈和设计规范创建 [具体需求]：

技术栈：
- Tailwind CSS（用于布局和自定义样式）
- Ant Design（用于基础组件）
- React Icons（用于图标）

设计规范：
- 遵循 Claude.ai 设计风格
- 配色：米色背景（#F5F5F4）、橙棕品牌色（#D97757）、低对比度文本
- 圆角：按钮 8px、卡片 12px
- 阴影：微妙柔和（0 2px 8px rgba(0,0,0,0.06)）
- 间距：充足留白，组件间距 32px
- 动画：0.2s ease 过渡

请严格遵循这些规范，确保视觉效果温暖、简洁、专业。
```

### 快速检查清单

生成代码后，检查是否符合：

- [ ] 页面背景是米色而非纯白
- [ ] 品牌色是柔和的橙棕色
- [ ] 圆角为 8-12px 范围
- [ ] 阴影微妙且柔和
- [ ] 留白充足不拥挤
- [ ] 所有交互有 0.2s 过渡
- [ ] 使用了 Ant Design 组件
- [ ] 图标来自 React Icons
- [ ] Tailwind 类名使用合理
