# UI 整体风格

## 0. 文档边界

- 本文档只定义视觉系统与通用交互 affordance。
- 用户可见功能、操作逻辑、状态反馈和验收标准统一放在 `doc/prd/**`。
- 新增或修改业务功能时，不要把流程规则、业务状态和功能验收写回本文。
- 页面结构可以描述视觉骨架与空间关系，但不在本文定义入口编排、控件顺序、状态流转或业务分支。

## 1. 设计语言

- 全前端统一使用 **Notion-like 文档工作台主题**：浅灰导航、白色文档主区、细线数据库、紧凑控件和轻量浮层。
- 整体气质是本地知识工作台，安静、密集、可扫描。
- 主工作区必须以纯白为主，页面层级优先通过留白、极淡分割线、浅灰 hover、文本权重、列表密度和稳定对齐表达。
- UI 应像一个正在工作的文档应用，避免大面积彩色块、厚重卡片、装饰插画和营销式布局。

## 2. 布局原则

### App Shell

- 工作台采用左侧浅灰 sidebar、顶部细线 topbar、中间白色文档流和底部输入区的结构。
- Sidebar 宽度固定 `240px`，与页面式配置区侧栏保持一致；背景、hover、选中态统一复用同一套视觉规则。
- Topbar 保持紧凑、弱存在感，主要通过细分割线、轻量图标和稳定对齐表达层级。
- 主内容区默认是白底文档流，不使用灰底托白卡的后台页面结构。
- 文档流内容居中显示，常规阅读宽度控制在 `760px-920px`，侧边面板可在不破坏主文档流的前提下占用额外宽度。

### 页面式配置页

- Settings、下载页和其他配置型页面使用页面式布局。
- 配置页可以有顶部标题和内容面板，但视觉仍应使用白底、浅灰导航、细分割线和紧凑列表。
- 配置页不做 dashboard 卡片矩阵；优先使用分区标题、列表行、table/database 和表单行。

### 输入区与浮层

- 底部输入区使用 Notion-like 轻浮层视觉：白底、细边框、低圆角、轻阴影。
- Focus 状态使用蓝色边框 (`accent-blue`) 和淡蓝色阴影，视觉反馈清晰但不突兀。
- 输入框文字使用 `15px` 字号，`leading-6` 行高，最小高度 `32px`，与 Notion 保持一致。
- 工具栏控件使用 `text-faint` (`#91918E`) 颜色，包括图标、文字和下拉箭头，保持低调。
- 输入区工具栏保持紧凑，左侧用于承载模式/范围类控件，右侧用于承载状态/动作类控件。
- 工具栏控件使用 `11px` 字号，高度 `22px`，间距紧凑（`gap-1.5`）。
- 选择器类控件应设置最大宽度，防止工具栏因文案过长失衡。
- 状态指示器应优先使用低干扰、可扫描的图形化表达。
- 发送/停止按钮使用圆形（`rounded-full`），尺寸 `28px`（h-7 w-7），图标 `12px`（h-3 w-3）。
- 发送按钮默认使用深色背景 (`#37352F`)，禁用状态使用浅灰背景 (`#EEEEEC`) + 灰色图标。
- 工具栏不使用分隔线，保持视觉连贯性。
- 浮层、候选列表和轻通知都应复用白底、细边框、轻阴影、紧凑列表的同一视觉语言。

## 3. 配色

### Token

- `page`：`#FFFFFF`
- `canvas`：`#FFFFFF`
- `sidebar`：`#FBFBFA`
- `surface`：`#F4F4F2`
- `surface-hover`：`#EFEFEE`
- `line`：`#EEEEEC`
- `line-strong`：`#E0DFDC`
- `text`：`#37352F`
- `text-soft`：`#787774`
- `text-faint`：`#91918E`
- `accent`：`#2F3437`
- `accent-blue`：`#0B6BCB` (第二强调色，用于 focus、链接等)
- `accent-blue-hover`：`#0958A5`
- `red`：`#B3261E`
- `red-bg`：`#F8EBE9`
- `green`：`#2F6F4E`
- `green-bg`：`#EDF6EF`
- `blue`：`#2F5F8F`
- `blue-bg`：`#EDF3F8`
- `yellow-bg`：`#FBF3DB`
- `shadow-float`：`0 16px 40px rgba(15, 15, 15, 0.12)`
- `shadow-soft`：`0 8px 24px rgba(15, 15, 15, 0.08)`

### 使用规则

- App 外层、主阅读区、Settings 和下载页默认使用 `page/canvas` 的纯白底，侧栏使用 `sidebar`。
- 普通 hover、选中、用户消息气泡、弱提示和 tag 才使用 `surface/surface-hover`，不得把它们作为大面积页面背景。
- 常规状态优先使用灰阶、图标与文案；可用低饱和绿、蓝、黄 tag 表示成功、信息、待处理。
- 危险、拒绝、错误才使用 `red/red-bg`。
- 第二强调色 `accent-blue` 用于交互性元素：输入框 focus 边框、可点击链接、某些操作按钮悬浮态。
- 禁止大面积彩色渐变、彩色阴影和高饱和状态色。

## 4. 尺度系统

### 圆角

- 控件：`6px`
- 内嵌块：`8px`
- composer：`10px-12px`
- 浮层：`8px-10px`
- pill / tag：`999px`

### 字级

- 元信息：`12px`
- 正文：`14px`
- 区块标题：`15px-16px`
- 页面标题：`28px-44px`，仅文档式页面标题使用。
- Settings、下载页和面板标题优先使用 `18px-28px`，不要使用 hero 级标题。
- 避免散落使用过多相近字号。

### 间距

- 紧凑控件内边距优先使用 `6 / 8 / 10`
- 面板间距优先使用 `12 / 16 / 20`
- 页面级容器优先使用 `20 / 24 / 32`
- Workbench 文档流上下留白可以更大，空状态和首条消息允许使用 `64 / 80` 的顶部空间。

### 阴影

- 默认不用阴影，只用留白、极淡分割线和局部浅灰状态表达层级。
- composer、popover、modal 可使用轻浮层阴影：`0 16px 40px rgba(15, 15, 15, 0.12)`。
- 禁止厚重彩色阴影。

## 5. Surface 层级

- `canvas`：App 外层和主工作区底色，默认应与 `page` 同为纯白。
- `sidebar`：导航、会话列表、辅助入口。
- `page`：主文档工作区、表单内容和列表内容。
- `surface`：选中态、用户消息、弱提示、tag、列表 hover，不承载大面积区块。
- `line`：不同区域之间的弱边界，存在感要低于正文和 tag。
- `accent`：主按钮和关键文字动作。

## 6. 组件规则

### Button

- 主按钮只给主动作，深灰底白字。
- 次按钮透明或白底，hover 使用浅灰底。
- 图标按钮使用 `28px-32px` 固定尺寸和 `6px` 圆角。
- 不使用彩色 hover 表达普通交互。

### Input / Select / Composer

- 输入区保持文档工具的紧凑感，不做大宣传页输入框。
- focus 使用 `accent-blue` 边框和淡蓝色 ring。
- Workbench composer 贴近 Notion 输入块：白底、细边框、底部浮层、轻阴影。
- Select、popover、候选列表与输入区共享相同边框、圆角和阴影体系。
- `@` 引用弹层使用白底、细边框、轻阴影、紧凑列表；信息编排应优先保证来源、路径和状态的可扫描性。

### Tag / Status

- tag 用于扫描，不用于长句说明。
- tag 圆角可保持 pill，但视觉重量要低于正文标题。
- 成功、信息、待处理使用低饱和浅底；失败、拒绝、危险态使用红色。
- tag 文案应短，优先是状态词、来源词或数量，不承载解释性句子。

### Table / Database

- 表格应更接近 Notion database：极淡细线、白底、近白表头、紧凑行高。
- 行 hover 使用 `surface-hover`。
- 不把每行做成独立大卡片。
- 列表型页面不使用灰底托白色大卡片的后台布局。
- 当信息主要依赖比较、扫描、排序或批量浏览时，优先使用 database/list row，而不是重复卡片。

### Icon

- 默认使用线性图标。
- 小图标 `14px-16px`，常规图标 `18px-20px`。
- 图标优先承担扫描职责：来源、状态、动作、风险、模式。

### Notice / Empty

- Notice 使用低饱和浅底和小图标，说明当前状态、风险或下一步动作。
- Empty state 允许使用一个轻量图标和短标题，不放长篇使用说明。
- 空状态标题应是操作导向，如“从一个问题开始”，不要写营销式 slogan。

### Approval

- 审核/审批类界面应保持信息结构清晰、操作层级稳定。
- 颜色、按钮、tag、边框和间距应服从全局视觉 token。

## 7. 文字与文案

- 页面不是说明书，不要把状态说明写成长段解释。
- 能放进 tooltip、tag、状态条的文案，不要放成段落。
- 标题只负责定位，辅助文案只负责补充范围或行为。
- 工作台文案优先描述对象、状态和动作，不使用宣传口吻。

## 8. 动效与交互

- 默认过渡时长 `160-180ms`。
- hover 只做浅灰底、边框变色或轻微透明度变化，不做夸张位移。
- 同类元素必须共享同一套 hover / active / focus 反馈。

## 9. Cursor 规则

- 可点击元素统一使用 `pointer`。
- 文本输入、`textarea`、`contenteditable` 使用 `text`。
- 帮助提示使用 `help`。
- 禁用态统一使用 `not-allowed`。

## 10. 辅助功能

- 所有交互元素必须可键盘访问。
- focus ring 必须清晰可见。
- 文本和背景对比度需满足正常阅读。
