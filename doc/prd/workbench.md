# Workbench PRD

## 1. 文档定位

- 本文档是 workbench 用户可见功能的产品规格来源，描述目标、范围、术语、交互、状态、边界和验收标准。
- workbench 的用户可见行为、流程、反馈或阻塞逻辑发生变化时，必须同步更新本文。
- 后续实现、测试、评审和 AI 最终汇报都应引用本文中的需求编号与验收编号。

## 2. 产品目标

- 用户通过对话让 AI 完成搜索、分析、回答、整理和文档处理等任务。
- 用户可以把本地资料作为上下文，让 AI 优先据此完成检索、分析、回答和受支持文件处理。
- 让 workbench 成为“发起任务、查看过程、处理中断、查看修改的文件并按需回退、继续执行”的主工作台。
- workbench 应把任务推进到完成；无法完成时明确说明原因、限制或所需条件。

## 3. 产品原则

- 本地资料是重要上下文，但不是唯一能力边界；未显式选择资料时，AI 仍可完成通用任务。
- workbench 的发送前提是已有伙伴且输入非空。
- 未显式插入 `@` 时，知识库默认覆盖设置页全部已索引文件地址与全局网页资料；`@` 只用于在此基础上再收窄。工作地址列表按设置页现表进入本轮对话上下文，不作为 Composer 选择器。
- 当用户插入 `@` 参考资料时，AI 应优先基于这些范围完成任务，而不是忽略用户给出的约束。
- workbench 不只展示问答过程，还要交付可消费结果，或给出明确失败信息。
- 用户可见能力边界必须明确可见，尤其是哪些资料可检索、哪些格式可直接写回并回退、哪些情况只能查看或分析。

## 4. 范围

- 包含伙伴管理（创建、编辑、切换、删除、置顶、空态）。
- 包含 composer 输入、发送与取消；Composer 只有智能模式。
- 包含智能模式下 AI 推进偏好的选择与本机恢复。
- 包含附件拖放和智能模式下执行权限的选择与伙伴级恢复。
- 包含 `@` 参考资料 token 的插入与维护。
- 包含按天时间轴跳转，以及清空消息记录。
- 包含 AI 运行中的审批与上下文压缩过程提示。
- 包含右侧内容面板中的文档查看与修改的文件回退入口。
- 包含基于本地资料和网页资料的上下文使用。
- 包含定时任务的入口、独立主区视图、任务配置、启用开关与到点触发。
- 包含 AI 写回或回退已打开的 WPS `.docx` / `.pptx` / `.xlsx` 时自动刷新（默认功能，无设置项）。
- 不包含设置页中的资料配置逻辑。
- 不包含视觉风格与基础控件样式定义。
- 不包含 AI 工具协议、operation 矩阵、结果信封或 graph / prompt 细节（见 `doc/ai-harness/**` 与 `doc/test-plan/ai-test.md`）。

## 5. 当前能力边界

PPT 普通预览和审核需完整显示中文及全角标点，换行测量与显示字体一致。新生成的表格需容纳全部文字，不能靠遮挡或自动省略隐藏内容。

- workbench 可使用设置页全部已索引文件地址与全局网页资料作为默认知识库范围；`@` 再收窄本轮范围。
- 当前本地知识库可索引文件类型为 `.pdf`、`.doc`、`.docx`、`.md`、`.markdown`、`.txt`、`.xlsx`、`.xlsm`、`.xltx`、`.xltm`。每个文件索引时都会前置一个「文件名锚点」内容块，保证按文件名可被知识库搜索命中；空文本文件不产生正文内容，但保留文件名锚点。Excel 只索引文件名、文档标题与工作表名等元数据，不索引任何单元格内容，单元格数据仍由 Excel 专用工具按绝对路径处理。`.doc` 只读，不支持直接编辑。
- 未显式选择参考资料时，智能模式仍可处理通用任务。
- 显式选择目录、文件或网页资料后，任务应优先使用这些资料。未显式 `@` 时，默认使用全部已索引文件地址与全局网页；资料不足时，智能模式可用模型通用知识补充通用部分。
- 当前可由 workbench 直接写回并支持回退的受支持文件类型包括 `docx`、`pptx`、`xlsx`、生成的 `png`、`jpg`、`jpeg`、`webp` 图片，以及 Markdown、TXT、配置文件和代码等 UTF-8 普通文本文件；普通文本支持创建、完整改写、唯一文本编辑和全部精确匹配替换。Excel 工具可读取 `xlsx`、`xlsm`、`xltx`、`xltm`，但只允许创建和编辑 `xlsx`，避免写回时丢失宏或模板信息。
- 馆长启动后默认开启本机 WPS 同步服务（加载项由回环 HTTP 提供），无设置开关。已打开 WPS 文档的自动刷新见 `WB-WPS-001`。
- 用户可在右侧面板对真实本地 Markdown（所见即所得）与普通 UTF-8 文本（纯文本）做应用内手动编辑并保存，见 `WB-EDIT-001`；应用内手动编辑不生成修改记录、不进入回退体系。
- Composer 附件不限制文件扩展名、文件大小、数量或目录大小；点击 `+` 直接打开可选择文件或目录的系统选择器，聊天区拖放接受文件和目录。文件及目录附件都保留源路径，不复制、不预解析目录，只把附件顺序、名称和绝对路径交给 AI 后续自行处理。附件卡片使用紧凑布局，仅图片显示缩略图；文件夹使用文件夹图标，音频和视频使用对应媒体图标。图片点击保持图片灯箱，支持右侧文件预览的文档点击打开右侧资源 Tab，文件夹继续用系统文件管理器打开，音视频及其他不支持右侧预览的文件定位到系统文件所在位置。粘贴文件因不保证有稳定源路径，保存副本到当前伙伴运行时目录。AI 工具侧仍有各自格式边界（如 `doc` 只读、`pptx` 可交给 PPT 工具读取和编辑、Excel 工具只写 `xlsx`），无法处理的文件会在 AI 工具层报错。
- 其他格式不保证直接写回和回退。AI 可以在审批边界内尝试处理，但不属于受支持文件能力范围。
- 审核权限下，终端副作用规则未命中的命令默认执行；命中的已知文件增删改、明确脚本/程序运行、系统/进程操作或网络写入先由本次运行主模型审核，模型明确判断操作在用户授权范围内时自动执行，否则再由用户审批。完全访问跳过两层审核。默认工作目录是用户主目录；终端改文件不进入修改记录，也不能从馆长回退。详细规则见 `WB-BLOCKER-001`。
- AI 可通过 `web_search` / `kb_search` 检索；`web_search` 不得自动展开右侧列表。所有 KB 工具（含关键词检索与文档列表）统一要求向量模型已安装，调用时按需初始化本地模型；缺失、下载中、初始化或执行失败只返回工具错误，提示 AI 当前状态下停止调用 KB，不终止 run，不下载、不修复、不静默降级。设置页正在「更新索引」时返回错误；「检查更新」不拦截。模型可用时，空库、空范围和查询无命中正常返回空结果，不扩大显式范围。
- `@` 参考资料不能替代「已创建并选中伙伴」这一发送前提。

## 6. 术语

- 伙伴：一条一直聊下去的对话记录。侧栏只有伙伴列表。
- 参考资料：通过 `@` 插入的目录、文件或网页资料 token。
- 工作地址：设置页添加的本地目录根路径（`workspace_source.root_path`）。
- 智能模式：Composer 唯一发送路径；启动 AI 运行，允许产生阻塞、审批、文件直接写回与回退入口。
- 受支持文件：当前已具备直接写回与回退能力的文件类型；当前包括 `docx`、`pptx`、`xlsx`、生成的 PNG、JPEG、WebP 图片（`.png` / `.jpg` / `.jpeg` / `.webp`）和 UTF-8 普通文本文件。
- 目标文件：用户要求新建受支持文件时，AI 写工具直接创建的文件路径。
- 直接写回：AI 写工具将最终 docx、pptx、xlsx、生成图片或普通文本结果原子写入源文件或创建目标文件的流程；工具成功即代表正式路径已可读取，run 收尾不再提交文件。
- 修改记录：一次 AI run 中由受控文件工具直接写回产生的创建、更新、删除或重命名记录；提供打开文件、适用格式的审核模式与回退本次修改入口。终端造成的磁盘变化不记修改记录。
- 回退本次修改：基于写回前 checkpoint 恢复文件；新建文件回退时删除目标文件，若文件在 AI 写回后又被修改，需提示用户确认会丢失后续修改。
- 清空消息记录：删除该伙伴全部对话消息记录（及对应 `ai_run`），界面回到空对话；不删除伙伴本身，也不删除 `ai_file_change` 文件回退记录。
- 内部引用链接：assistant 回答中使用标准 Markdown 语法 `[显示名](绝对本地路径或 https URL)` 引用的本地文件或网页链接；点击可在右侧工作台预览文件或打开内置浏览器。本地文件做可达性检查，不可访问时展示弱化状态并禁止点击；`http(s)` 网页链接不做可达性检查，默认可点。详细校验与交互见 `WB-COMPOSER-003-AC8`。
- AI 推进偏好：智能模式下用户对资料使用边界的附加约束，界面选项包括“默认”“本地资料·宽松”“本地资料·严谨”。当前“本地资料”范围包含全部已索引文件地址、全局网页资料、工作地址内文件和显式参考资料。宽松模式优先使用这些资料，资料不足时允许补充模型知识或外部网页；严谨模式只能把这些资料作为事实依据，资料不足时必须明确说明，不得把模型知识、外部搜索或浏览器结果伪装成资料内事实。
- 执行权限：智能模式下对本次运行是否等待工具审批的选择，独立于 AI 推进偏好。选项为“审核”和“完全访问”。

## 7. 需求规则

- Workbench 基础需求编号使用 `WB-<模块>-<三位序号>`，验收编号使用 `WB-<模块>-<三位序号>-AC<序号>`。
- 定时任务子需求编号使用 `ST-<模块>-<三位序号>`，验收编号使用 `ST-<模块>-<三位序号>-AC<序号>`。
- 需求编号稳定后不因措辞微调而重排；删除功能时同步移除需求正文与测试计划引用，保留编号空缺，不复用已删除编号。

## 8. 需求明细

### 8.1 核心能力与约束

#### WB-CORE-001 本地资料是可选上下文，不是唯一前提

- 系统行为：workbench 发送前要求已有伙伴；在此基础上，即使用户未显式选择任何本地参考资料，AI 仍可执行不依赖本地文档的通用任务；当存在本地参考资料时，可将其作为任务上下文使用。未创建伙伴时 Composer 为空态，不能发送。
- 验收：
  - `WB-CORE-001-AC1` 用户已创建并选中伙伴但未选择任何本地参考资料时，智能模式仍可正常发起不依赖本地文档的任务。
  - `WB-CORE-001-AC2` 系统不会把“没有显式本地参考资料”误表现为“workbench 不可用”；未创建伙伴时才表现为 Composer 空态。

#### WB-CORE-002 用户显式选择的参考资料或默认知识范围必须影响执行

- 系统行为：当用户插入 `@` 参考资料后，后续检索、分析和执行应优先基于这些显式范围收敛；当用户未显式选择参考资料时，知识库默认覆盖设置页全部已索引文件地址与全局网页资料。
- 验收：
  - `WB-CORE-002-AC2` 智能模式下，系统不会忽略用户已经给出的 `@` 参考资料或默认知识范围；已选资料作为优先缩圈候选，但不自动变成唯一可搜索范围。

#### WB-CORE-003 当前受支持文件的直接写回能力边界必须明确

- 系统行为：workbench 明确区分“可直接写回并支持回退的受支持文件”和“可由 AI 自行尝试处理但不提供同等保证能力的其他任务”；当前受支持文件类型包括 `docx`、`pptx`、`xlsx`、生成的 `png`、`jpg`、`jpeg`、`webp` 图片和 UTF-8 普通文本文件。`xlsm`、`xltx`、`xltm` 只读，不属于可直接写回范围。
- 验收：
  - `WB-CORE-003-AC1` 当前支持直接写回与回退的受支持文件类型列表明确可见，包括 `docx`、`pptx`、`xlsx`、PNG/JPEG/WebP 图片（`.png` / `.jpg` / `.jpeg` / `.webp`）的修改和新建，以及 Markdown、TXT、配置文件和代码等 UTF-8 普通文本文件。
  - `WB-CORE-003-AC2` 不在当前受支持文件类型列表中的资料不会被伪装成可进入同一直接写回与回退流程的编辑或创建目标。

#### WB-CORE-004 资料优先级受 AI 推进偏好约束

- 系统行为：默认或宽松偏好下，当用户已插入参考资料或存在已索引文件地址 / 全局网页时，系统优先基于这些资料完成任务；未显式 `@` 时，默认使用全部已索引文件地址与全局网页作为知识范围。资料不足时，默认或宽松偏好允许补充模型通用知识或外部网页信息，但不能忽略或违背用户已给定的资料。严谨偏好下，只允许把已索引文件地址、全局网页与显式参考资料作为事实依据；资料不足时应明确说明缺口，不得使用模型知识、`web_search` 或 `browser_use` 的外部内容补足事实。
- 验收：
  - `WB-CORE-004-AC1` 用户已有默认知识范围或显式参考资料时，问答或受支持文件结果不会脱离这些资料另起一套无关内容。
  - `WB-CORE-004-AC2` 默认或宽松偏好下，资料不足以覆盖通用部分时，系统仍可补充模型通用知识或外部网页信息，并明确区分资料内事实与补充信息。
  - `WB-CORE-004-AC3` 严谨偏好下，资料不足时系统明确说明资料缺口，不使用默认知识范围和显式参考资料之外的信息补足事实。

#### WB-CORE-005 任务过程中的中间结果必须服务于后续结果

- 系统行为：当任务执行过程中产生搜索结果、文件读取结果、执行结果或其他中间信息后，后续 assistant 回答、分析结论和文件产物应实际使用这些信息继续推进用户诉求；若当前中间结果不足以支撑继续完成，系统应明确说明限制，而不是伪造后续内容。
- 验收：
  - `WB-CORE-005-AC1` 任务过程中产生的中间结果，会体现在后续用户可见回答、结论或文件产物中，而不是只表现为“执行过某些步骤”。
  - `WB-CORE-005-AC2` 当前中间结果不足或执行失败时，assistant 会明确说明为什么无法继续完成、缺少什么条件或当前能确认到什么范围，而不是编造结论或文档内容。
  - `WB-CORE-005-AC3` 用户可见输出优先围绕用户原始诉求组织；若引用中间结果，应使用用户能理解的表达，而不是暴露内部工具或过程标签。

#### WB-CORE-006 用户诉求应被推进到完成或明确失败

- 系统行为：当用户已提供足够上下文且当前能力允许时，workbench 应以“最小可靠返回 × 最少连续决策轮次”持续推进用户诉求直到完成：只读取当前决策所需范围，避免全量或重复读取，独立调用尽量同轮发起，同类批量能力不拆轮。若当前无法完成，也应明确返回失败原因、限制信息或下一步所需条件，而不是停留在搜索结果、工具调用或过程提示等中间过程。
- 验收：
  - `WB-CORE-006-AC1` 用户诉求可完成时，系统会把任务推进到可消费结果、明确产物或可确认的下一步动作，而不是停留在中间态。
  - `WB-CORE-006-AC2` 用户诉求当前无法完成时，系统会明确说明失败原因、限制信息或下一步所需条件，而不是无声中断或只留下过程信息。
  - `WB-CORE-006-AC3` 最终收口默认直接围绕用户显式提出的问题组织；若同时需要说明产物、依据或限制，也应使用用户可理解的语言表达，而不是依赖内部标识、tool 名或固定章节标题。
  - `WB-CORE-006-AC4` 简单任务不强制创建 plan；复杂或多依赖任务才维护 plan，不为汇报进度单独更新。目标满足且必要检查通过后可直接交付。

#### WB-CORE-007 网页信息可用于任务推进

- 系统行为：默认或宽松偏好允许 AI 通过后台 `web_search` 搜索网页、读取指定网页正文，并在需要登录或人工操作时使用 `browser_use` 打开右侧内置浏览器继续任务；严谨偏好不得把外部网页作为资料内事实依据。`web_search` 是 Human 图后台工具，结果只回模型与过程层，不得自动展开右侧列表，也不得替代 `browser_use` 的可见浏览器交互。
- 验收：
  - `WB-CORE-007-AC1` 用户要求查找公开网页信息时，AI 可搜索并读取搜索结果或用户给出的 URL，再用所得内容完成回答或产物。
  - `WB-CORE-007-AC2` 网页搜索、读取或浏览失败时，系统明确说明失败边界，不伪造网页内容。
  - `WB-CORE-007-AC3` 严谨偏好下，外部网页能力不会绕过资料范围限制。
  - `WB-CORE-007-AC4` AI 调用 `web_search` 时，Workbench 不得因工具结果自动打开右侧搜索列表；过程层可展示“搜索网页 / 抓取网页”等状态，但右侧面板保持原状，除非用户手动打开资源或 AI 触发 `browser_use`。
  - `WB-CORE-007-AC5` `web_search` 抓取时用户不得看到带窗框的独立浏览器窗口，也不得让网页内容遮挡主界面。
  - `WB-CORE-007-AC6` `web_search` 读取网页应返回可读正文或明确失败，不得无限挂起。

#### WB-CORE-008 Workbench 窗口层与业务内容分层

#### WB-SESSION-003 标题就是伙伴名称，不因消息改名

#### WB-SESSION-004 删除伙伴后保持可继续操作

#### WB-SESSION-005 同一伙伴里的续做保持任务主线

- 系统行为：用户始终面对同一伙伴窗口。用户在同一伙伴内基于上一轮结果继续提出局部修改、补写或 refinement 请求时，系统继续沿用当前伙伴上下文、上一轮产物和有效文件/回退入口，不把续做误当成全新无关任务。同一伙伴的历史原文会一直带给主模型，直到 compaction 把它折进摘要。若用户要开始一个干净的新话题，使用「清空消息记录」或新建伙伴；界面不出现「新会话」或草稿会话控件，也不会自动丢掉历史原文。
- 验收：
  - `WB-SESSION-005-AC1` 续做请求发出后，系统会复用上一轮相关产物或上下文，而不是丢失已有任务主线。
  - `WB-SESSION-005-AC2` 续做完成后的结果体现的是对上一轮结果的继续修改或补充，而不是简单重复旧输出或重新开题。
  - `WB-SESSION-005-AC3` 用户要换无关新话题时，可通过清空消息记录或新建伙伴得到干净上下文；不自动丢掉当前伙伴里还没压缩的历史原文。

#### WB-SESSION-006 用户消息复制与编辑

  - `WB-SESSION-006-AC1` 复制操作写入消息的可读文本，并给出成功或失败反馈。
  - `WB-SESSION-006-AC2` 只有最新用户消息且当前没有运行中任务时显示编辑入口。
  - `WB-SESSION-006-AC3` 点击编辑先出现确认框；确认后目标消息、关联 run 与该 run 的全部日志从伙伴记录中撤回，原输入、参考资料和附件恢复为草稿；取消确认则消息与草稿不变。

#### WB-SESSION-007 同一伙伴内恢复被中断任务

- 系统行为：智能模式任务因用户主动停止、网络错误、请求超时、应用进程中断、输出截断、达到运行上限或未知异常而没有正常完成时，历史消息日志保持不变。用户之后在同一伙伴发送消息时，系统从该伙伴现有消息日志投影：已经压进摘要的旧对话原文不再发给主模型；还没处理掉的原文照发。历史 User 用 log 里的 `content`（发给模型的原文）；Compact User 用 checkpoint 的 `summary`，发给主模型时再合成。还没压进摘要的原文照发（Compact User 后可跟这段原文，可含多条 User），补齐悬空工具结果，再把新 User 追加一次继续推进。新 User 不抄 Compact User。若压缩后又产生了尚未折进摘要的过程，这些过程前面必须先放 Compact User，不能直接接在 System 后面。气泡仍是人打的字（`ai_run.input`）；Compact User 不当新气泡。每条历史 human user 保留当轮参考资料和附件配置；新 user 只使用 Composer 当前配置。计划与已学习技能均从该伙伴剩余消息日志恢复。重启只标记中断，不自动重新调用模型。
- 验收：
  - `WB-SESSION-007-AC1` 用户停止、模型请求失败（含网络/超时/鉴权/余额等定案后）、进程中断、输出截断、达到运行上限和未知异常后，下一条消息可只靠消息日志继续（含计划与已学习技能）。
  - `WB-SESSION-007-AC2` 恢复后的消息数组以日志投影为准：未压缩时为历史过程 + 尾部新 user；已压缩时为 Compact User + 还没压进摘要的原文（可空，可含多条 User）+ 尾部新 user。新语句不会改写历史任务或历史配置。
  - `WB-SESSION-007-AC3` 同一伙伴连续多次中断和恢复后仍保留完整任务主线，原始任务始终保留在记录首条 user，不把历史任务递归嵌套为新的原始任务。
  - `WB-SESSION-007-AC4` 切换伙伴或重启应用后，原伙伴日志仍可投影；其他伙伴不能读取该日志。
  - `WB-SESSION-007-AC5` 编辑并重新发送最后一条用户消息时，只删除该消息、关联 assistant、run 与该 run 的全部日志记录，其他历史不变；不回滚已写文件。
  - `WB-SESSION-007-AC6` 正常完成清空计划展示但不删除历史日志；删除伙伴级联删除其日志。
  - `WB-SESSION-007-AC7` 达到运行上限时显示“已达到运行上限，可继续对话推进”，并允许在同一伙伴继续恢复。
  - `WB-SESSION-007-AC8` run 失败时气泡展示短标题（如「模型请求失败」）；「查看详情」可展开原文（及可选 HTTP / provider code）；toast 只用短标题，不刷长文。

#### WB-SESSION-008 伙伴界面状态独立持久化

- 验收：
  - `WB-SESSION-008-AC1` A/B 伙伴可分别保存并恢复模式无关的 Composer 状态：AI 推进偏好、执行权限、主模型、普通文字、@ 引用、附件和附件桶，反复切换互不串联。旧快照缺少执行权限时按“审核”恢复。

#### WB-SESSION-010 消息时间轴

- 系统行为：
  - 当前伙伴存在消息时，消息区左侧展示固定竖线时间轴（自身不滚动）。
  - 当前可见节点以固定间距自底部向上堆叠（最新节点靠近输入框上方），不随可用高度拉开等距。
  - 轴线叠在主区上，水平位于侧栏右缘与 Composer 左缘之间的居中位置。
  - 轴线始终是一条实线：**底端停在最新节点圆心（不向下突出），顶端与主区顶栏横线留出空隙**；节点整体底边按白色输入框顶部量齐；近端（底部）对比清晰，越往上（更早）越透明。不使用虚线。
  - **仅有消息的日期才出现节点**。默认：近 7 个本地日（含今天）有消息则显示日节点（今/昨/前或 `M/D`）；更早同年按月聚合；往年按年聚合。日/月/年圆点造型区分。
  - 点日节点跳到当天最早一条消息。点月/年节点跳到该范围最早有消息日的第一条。
  - 月节点与年节点文案下方提供搜索图标，点击后打开 Ant Design `DatePicker`；仅可选择该月/该年内真正有消息的本地日，选天后左侧轴节点不变，右侧瞬时跳到该天最早一条消息；同一天可再次选中并再次跳转；关闭弹层时不得把点击穿透到月/年节点、从而再跳到该范围最早日。不再提供月/年展开收起、淡段标或「收起」入口。
  - 点击节点只滚动消息列表容器（`.nc-document-scroll`），并将该天最早一条消息**瞬时贴顶**（不使用平滑滚动）；仅当已贴顶（偏差小于 2px）时不重复滚动，避免带动侧栏或 Composer。
  - 列表底部常驻刚够让**最新有消息日**最早一条贴顶的阅读留白（该日已撑满一屏则为 0），因此任意更早的日/月/年都能直接贴顶。
  - 滚到底部时视口顶是最新日、轴高亮该日；今天消息少时输入框上方允许留白。点轴只滚动，高亮仍跟视口顶部走。当前高亮节点的圆点与文案大于未选中节点。
  - 消息列表使用 `scrollbar-gutter: stable`，避免过程态显隐导致宽度抖动。右侧滚动时以视口顶部附近第一条消息的日期高亮左侧对应节点（日优先，否则高亮包含该日的月/年）。
  - **紧凑态按「完整态轴宽（含左偏移）是否会与 Composer / 审批卡左缘碰撞」判断，与是否展开右侧面板无关：会碰撞则只保留圆点与轴线，悬浮 Tooltip 显示节点时间文案；不会碰撞则保持完整文案与月/年搜索。宽栏下节点无 Tooltip。审批卡替换 Composer 时仍以审批卡为布局锚点，轴线底边对齐与紧凑态判定持续生效。**
  - 向上滚动到顶部仍懒加载更早消息；目标天未加载时先加载再跳。
- 验收：

### 8.3 Composer 输入与发送

正文按输入顺序保留普通文字、`@` 引用和文档选区片段；发送、复制和重新编辑保持该顺序与引用关联。选区交互见 `WB-DOCUMENT-REFERENCE-001`。底部工具栏左侧放附件、AI 推进偏好和执行权限，右侧放上下文用量、模型和发送。

  - `WB-COMPOSER-003-AC8` brain 在最终交付 markdown 中使用标准 Markdown 链接引用资料（名称 + 绝对路径或 https URL）；最终交付生成后、回传界面前，后台**仅对本地文件**链接地址并行去重检查并写入交付 `linkAccess` sidecar（不改写正文）。可访问的本地文件链接保留文件预览交互；不可访问或无法识别的本地文件链接不得删除，必须使用强调色降低透明度的灰色弱化文本，悬浮提示「链接无法访问」，且不可点击。`http(s)` 网页链接不做可达性检查、不写入可达性 sidecar，交付前后均默认可点并打开内置浏览器。界面不把裸 URL / `www.…` 自动识别为链接，也不对其套用 `linkAccess` 弱化态；流式阶段尚无 sidecar 时本地文件链接可先保持可点，交付落库后按 sidecar 更新。界面渲染和用户点击时均不再次检查可访问性。渲染侧匹配 sidecar 前须对 href 做 percent-decoding / 路径规范化，避免中文等非 ASCII 路径因编码差异误判不可达。

#### WB-COMPOSER-015 LLM 自动重试过程层

- 系统行为：Brain / LLM 调用层可重试错误由 `classifyLlmRetry` 驱动 `runLlmCallWithActivity`，只认结构化信号：HTTP status、providerCode/type、以及连接类类型（`APIConnectionError` / `APIConnectionTimeoutError` / `TimeoutError`）。可重试含 408/429/5xx、限流/容量、断网连接错误、供应商连接超时、以及调用层 `TIMEOUT`。上限 `AI_LLM_CALL_MAX_RETRY_ATTEMPTS` 表示**首次失败后再试最多 5 次**。过程区以独立重试行展示，不并入 Activity。同一 run 只使用一个过程组 id（`${runId}:llm-retry`），次数在同一行就地更新（`正在重试 1/5` → `2/5`），不按 attempt 或后续 LLM 调用再叠多行。该行 running 时必须隐藏“让俺想想”。**该次调用重试成功后该行消失**，过程流继续（Thought / 工具 / 最终回答），不展示“已重试”。耗尽则收口为“重试失败 n/5”，失败码为 `llm_request_failed`。429 / rate_limit_exceeded / ResourceExhausted 使用 2s 起、上限 15s 的指数退避；连接错误与超时使用短退避。自动重试前清空上一尝试草稿仍见 `WB-COMPOSER-014-AC3`。

#### WB-COMPOSER-006 AI 运行取消

- 系统行为：智能模式在普通任务运行时，Composer 右侧只有一个主按钮：草稿没有可发送内容时显示停止；有可发送内容时显示发送，提交后按 `WB-COMPOSER-017` 追加到当前 run 的消息队列，草稿清空后按钮恢复为停止。点击停止后 UI 保持占用当前 run，直到 Main 发出 `run_cancelled` / 失败 / 完成；清理期间该按钮为转圈态并禁用，提示「正在停止本次运行」。若当前 run 正在等待提问或审批，停止也必须释放对应等待、移除交互卡并结束本次 run；Activity 不得继续显示「等待用户处理」。取消是独立终态，不生成失败气泡，也不在 assistant turn 中追加或保留「已取消」正文；取消前已经产生的回答片段、过程记录和文件修改入口继续保留。正在执行 `browser_use`（含页面加载与 Stagehand observe/act/extract）时，停止须立刻中断并结束 run，不得等页面或 Stagehand 自然完成后再结束。当前 run 仍在等待模型首个 token（流式尚未返回）时，停止也须立刻按 `user_cancelled` 结束，不得等待服务商拆掉连接或 stream 自然结束。
- 验收：
  - `WB-COMPOSER-006-AC1` 普通运行中右侧只显示一个主按钮：草稿无可发送内容时显示停止，有可发送内容时显示发送并排队；排队发送后草稿清空，按钮恢复为停止。点击停止会停止当前 run，页面不显示额外的文字“取消”按钮。

#### WB-COMPOSER-017 运行中追加消息

- 系统行为：普通 `running` 状态下 Composer 保持可用，排队消息能力不变。右侧只显示一个主按钮：没有可发送草稿时按钮为停止；输入文字、附件或引用等可发送内容后，该按钮切换为发送，提交后消息按提交顺序暂存在当前 run 上，输入清空后按钮恢复为停止。消息气泡只以浅灰视觉表示尚未交接，不显示等待说明，不提供编辑或撤回入口。Main 在追加消息校验开始前登记待处理提交；`context_budget` 与 Brain 入口等待校验结束并复查队列，避免提交正在校验时启动下一轮 Brain。校验失败则当前任务继续。主模型继续当前任务；当前 Brain 已开始最终回答时先完成交付，再处理追加消息。当前 run 的工具调用、结果日志和统一投递队列全部完成后，human graph 在下一次 `context_budget` 结束处安全交接，追加消息按 FIFO 顺序进入伙伴 transcript，组成一次续接请求。交接后的旧 run 显示固定用时；助手过程气泡按其用户气泡的投影时间加 1 毫秒排序。审批和提问状态由交互卡替代 Composer，不显示输入框或普通主按钮，不能排队。用户停止 run、任务失败或应用中断时，已追加消息作为普通用户历史记录保存，不自动启动 AI；未完成的工具调用继续按中断恢复规则在下一轮模型上下文投影中补齐“未执行”结果。

### 8.4 资料引用与文档选区

#### WB-SCOPE-001 `@` 候选来源规则

- 系统行为：输入 `@` 后，根据当前关键字返回目录、文件和网页资料候选。本地候选相对每个工作地址根**最多收录两级路径**（根为第 0 级，可引用工作地址本身；其下第一层、第二层的目录与文件进入列表；第三层及更深不出现）。列表为「文件 / 网页」两组**平铺**，无展开、无点进目录；点击任一项即插入对应 token。工作地址根、目录、文件、网页均可选中。候选按页懒加载，单次最多 50 条，滚到底加载下一批；有关键字时在上述扁平集合内子串过滤后再分页。本地索引只补充索引状态，不决定候选是否出现。键盘上下移动高亮项时列表滚动跟随使当前项可见；Enter 插入当前高亮项。未创建或未选中伙伴时 Composer 为空态，不开放 `@` 发送路径。
- 验收：
  - `WB-SCOPE-001-AC1` 未选中伙伴时不把资料选择当作正常发送路径暴露给用户。
  - `WB-SCOPE-001-AC2` 已选中伙伴后，候选可同时出现工作地址根、根下两级内的目录/文件与全局网页；只展示“文件”和“网页”两组；点击目录与点击文件一样直接插入，不进入子层。
  - `WB-SCOPE-001-AC3` 在上一次索引或候选打开后新增、修改或删除本地文件时，再次打开 `@`（或搜索）必须反映真实目录；深度超过两级的路径不出现；新增或变更但未索引的文件仍可选择，并显示“未索引”。

  - 输入支持自适应多行。提问与审批卡内按 Enter 等同点击右下角当前主动作（下一步、发送回复、允许执行、确认拒绝或发送指导），选项行和输入框获得焦点时均可使用，不切换或清空已有选择；Shift+Enter 换行，Ctrl/Cmd+Enter 也可执行当前主动作。顶部翻页和停止按钮保留各自键盘操作。输入法组合输入与长按重复键不触发主动作，禁用、提交或取消期间不得触发。提交期间禁止重复提交并冻结选择、输入和翻页，停止入口保留；取消期间禁用全部操作。提交失败显示错误并保留草稿，成功由运行事件移除卡片。
  - 审批指导输入显示「告诉{对应伙伴名}该怎么做」：子任务优先使用来源子伙伴名，否则使用当前伙伴名；均缺失时使用「伙伴」，不硬编码产品名。保留子任务来源展示。提问输入依次使用「或直接输入回复…」「补充说明（可选）…」或纯输入题的「回复…」。
  - 审核权限下，`terminal_run` 先做副作用规则判断：已知文件增删改、写入重定向、明确的脚本/程序运行、系统/进程操作及网络写入进入 AI 审核；未命中规则的命令默认执行。错误输出丢弃（如 `2>/dev/null`、`2>$null`）不算写文件；空命令与语法错误由工具报错。AI 审核使用本次运行主模型，输入本次任务要求、用户默认工作区目录、命令及 commandId、平台和终端默认启动目录；命令说明仅用于人工审批卡与日志。任务授权包括完成目标所必要、合理的配套操作；只有实际操作属于授权范围、目标及重要影响明确、用户约束和前置条件已满足，且风险未超出授权范围时才自动通过，表示可立即执行。任一条件不满足、存在影响授权或安全判断的重要不确定，或审核失败时进入人工审批。每条审核结果以 JSON 返回 commandId、decision 和简短 reason，commandId 对应待审命令，reason 说明放行依据与实际影响或缺失条件并写入运行日志；JSON 修复后仍无效时最多重发 3 次，最终失败转人工。进入 AI 审核前，同一 `terminal_run` 工具项立即出现在 Activity，展示审核中状态；审核重试更新该项，不新增过程项。
  - AI 审核自动通过时直接执行且不展示审批卡；存在需人工确认的命令时，在底部用审批卡片替换普通 Composer。卡片一次只展示当前一条审批项，用户可通过左右切换浏览整批，整批在人工决定前都不执行；任一项拒绝或指导时整批零执行。AI 审核结论写入运行日志，供排查和恢复读取。
  - 审批卡不展示内部策略原因；完整命令放在独立浅灰代码块，支持换行和滚动。下方「允许本次操作 / 拒绝本次操作」为整行单选，不默认选择、不标推荐。非空指导文字清除当前选择并禁用选择行，清空指导后恢复未选状态；指导不是允许执行的附言。末项按钮按整批决定显示「允许执行 / 允许执行 N 项」「确认拒绝」或优先显示「发送指导」，此前仅为「下一步」。任何一项拒绝或指导均整批不执行；全部允许且最终提交后才执行。审批不自动超时，等待明确提交或取消。
  - 等待 AI 审核期间，Activity header 显示「正在审核终端命令」，多条命令时显示数量；展开行显示正在审核的命令。AI 自动通过后，同一工具项转为准备执行和执行状态。需要人工决定时 header 显示「等待用户处理」，展开行显示待确认命令；审批后同一工具项继续显示实际执行结果，拒绝或指导且整批未执行时显示「命令未执行」。刷新后从消息日志恢复审核与人工决定状态；取消后清除运行中等待状态。
  - Activity header 按当前工具汇总文案显示，但无论工具执行成功、失败或部分失败均保持中性灰色层级；失败句式保留，具体失败工具行仍以红色提示。被人工拒绝或指导、实际未执行的终端命令不算工具执行失败；独立错误提示气泡规则不变。
  - Activity 展开后，在对应工具行下按时间顺序显示问题、选项文字、自定义答案和审核结果；AI 审核结果与人工审批决定均使用与问答一致的内嵌竖线层级，只展示审核结论 / 用户决定，不展示 AI 内部 reason；不再使用审核图标前缀或 hover 替换工具文案。
  - 不在过程流展示只读 blockers 提示，也不弹出「有 n 条命令需要审核 / 审核已通过」toast。决策结果写入 `chat_session_message_log` 的 `approval_batch_resolved` annotation，刷新后可恢复。
  - 完全访问权限下跳过 AI 与人工审核，不创建等待审批状态、不发送审批事件、不展示审批卡片与审批叙事；工具自身的禁止规则、取消及其他运行时保护仍生效。

#### WB-PANEL-004 内置浏览器面板

- 系统行为：
  - 每个浏览器 Tab 对应独立 Electron `WebContentsView`，全部视图共享持久分区 `persist:ncurator-browser`。该面板只服务用户手动开标签和 `browser_use`；`web_search` 的外网抓取使用独立隐藏 crawler view，不得复用或污染本面板。

  - 浏览器 Runtime、界面 Presentation 和 AI Automation 相互独立：切换文件、折叠右侧栏或切换伙伴时，只从主窗口显示树移除 View，不关闭 `webContents`，不改变 AI 正在操作的那块 View；重新显示时挂载同一个 View 并展示后台操作后的实时最终状态。

  - `WB-PANEL-004-AC1` 收到 AI 浏览器面板事件后，右侧显示事件指定的浏览器 Tab；面板动画期间不逐帧缩放原生 View，动画结束后按最终 bounds 一次挂载并与正文视口对齐；分栏拖拽调整面板宽度期间，原生 View 暂停逐帧 bounds 发送并由静态页面快照占位，拖拽结束后在无补间延迟下瞬时对齐并无缝恢复原生视图，垫底快照延时退出以避免白屏闪烁。
  - `WB-PANEL-004-AC2` AI 通过 `browser_use` 的 `navigate` 打开 URL：不传 `tabId` 时新建标签并返回 `tabId`，传了则在指定标签导航。`list_tabs` 可列出当前伙伴标签。`observe / extract / act / act_instruction / screenshot / scroll` 必须显式传入 `tabId`；`screenshot` 截取当前标签页视口截图；`scroll` 支持按视口比例向下或向上滚动页面以加载后续内容；`act` 执行此前 `observe` 返回的单个 `actionId`（确定性回放，支持传入 `text` 为输入/填写动作注入文本，对非输入动作安全过滤参数）；`act_instruction` 支持直接按自然语言指令推导执行页面动作。需要切换页面时先 `navigate`。
  - `WB-PANEL-004-AC3` 切换到文件 Tab、收起面板或切换伙伴时，浏览器 View 从主窗口显示树移除，不使用窗口外坐标停放；`webContents`、页面 JS、网络请求、Cookie、滚动位置、表单和 SPA 状态继续存在。
  - `WB-PANEL-004-AC4` AI 浏览器任务完成后，assistant 最终输出应使用浏览器操作获得的结果完成用户诉求，右侧浏览器面板状态与最终回答形成可理解的任务闭环。
  - `WB-PANEL-004-AC5` 多个浏览器标签可以打开相同 URL；Stagehand 必须按浏览器 Tab 对应的 CDP targetId 精确选择页面，不得按 URL 猜测或串页。
  - `WB-PANEL-004-AC6` 浏览器标签共享 Cookie、登录态、LocalStorage、IndexedDB、Service Worker 和 HTTP 缓存；除非用户主动清除浏览数据，应用不得自动清空持久分区。
  - `WB-PANEL-004-AC7` 新增标签页和浏览器更多菜单使用无边框原生子窗口显示在浏览器上方；菜单打开期间浏览器保持原尺寸和可见状态，点击外部、按 Escape、主窗口移动或切换 Tab 时关闭菜单。菜单不得因内置 `WebContentsView` 抢焦点或主窗口 `resize` 事件被误关；点击外部关闭需在失焦后短延迟复核菜单仍未聚焦再关闭。菜单加载失败或超时应向用户显示错误提示。
  - `WB-PANEL-004-AC8` 浏览器更多菜单的缩小、百分比、放大必须位于同一行且都可点击；缩放操作不关闭菜单，百分比可恢复 100%；更多菜单不再提供系统浏览器打开入口。
  - `WB-PANEL-004-AC9` 地址为空时“前往”按钮禁用；地址非空时点击按钮或按 Enter 都导航到相同目标，按钮 tooltip 与无障碍名称均为“前往”。用户导航（含 Markdown 网页链接与地址栏前往）启动后立即返回，不等待页面 `did-finish-load`；AI `browser_use` 的 `navigate` 必须等到页面有真实内容，或等到系统错误页 / 空白验证超时后再返回工具结果。
  - `WB-PANEL-004-AC10` 内置浏览器自动化不得打开进程级远程调试口，也不得依赖固定 CDP 端口。旧端口 `9333` 或其他本地端口被占用时应用仍应正常启动。Stagehand 与网页抓取只在操作时按当前 Tab 或隐藏 crawler view 挂到本机回环 CDP 桥；用户打开网页时该页不得作为调试目标出现在 `/json/list`。
  - `WB-PANEL-004-AC11` AI 在浏览器未显示时仍可按原 targetId 连续执行 observe、act、extract 和导航；恢复后必须直接显示 AI 操作后的最新网址、页面内容、滚动位置和表单状态，恢复前后 `webContents.id` 不变。
  - `WB-PANEL-004-AC12` 后台浏览器在应用运行期间不得自动销毁；仅应用退出、用户主动关闭浏览器 Tab 或删除所属伙伴时销毁。应用重启后按伙伴恢复标签顺序、URL、导航历史和缩放并按需重新创建；不承诺恢复页面 JS、内存滚动状态或未提交表单。
  - `WB-PANEL-004-AC13` AI 通过 `browser_use` 的 `act` 触发网页操作时，通过 DOM 虚拟光标提供移动和点击视觉反馈；单次动作执行完毕时光标保持常驻在最后操作位置（不提前隐藏），后续动作平滑连续移动；仅当整轮 AI Run 结束（正常完成、用户取消或异常中断）时，通过运行资源管理器统一平滑淡出隐藏。
  - `WB-PANEL-004-AC14` 地址栏右侧提供“将打开外部浏览器”按钮（右上角外链图标）；有可打开 URL 时可点击，tooltip 与无障碍名称为“将打开外部浏览器”，点击后通过系统默认浏览器打开当前页或地址栏中的 URL。
  - `WB-PANEL-004-AC15` 用户地址栏与 AI `navigate` 对网址协议的处理一致：输入什么协议就打开什么。只填主机（如 `epub.cnipa.gov.cn`）时补成 `https://`，失败停在 https，不自动改 http；写明 `http://` 只走 http；写明 `https://` 只走 https。地址栏始终展示本次实际尝试的地址。
  - `WB-PANEL-004-AC16` 网络打不开时由馆长在同一内置页写入 Chrome 式错误文档：标题「无法访问此站点」、副文「无法加载 {主机}」、建议列表、底部 Chromium `did-fail-load` 给出的 `ERR_` 错误码、灰色圆角「重新加载」按钮。只认主框架 `did-fail-load` 且非 `ERR_ABORTED`；不另设馆长加载超时。连接或 TLS 何时失败由 Chromium 自己报。不因 https 失败改走 http。不另画 React 遮罩，不等 `chrome-error://`。地址栏显示尝试的站点，不显示 `chrome-error://`。`navigate` 一开始就打开右侧浏览器面板，失败也打开。重新加载走当前地址栏同一套导航。
  - `WB-PANEL-004-AC17` AI `navigate` 不得把反爬/安全验证空白第一屏当成成功。等到有真实标题或正文/表单，或超时仍空白则失败（说明可能卡在站点安全验证）。Chromium 把网址当成标题（主机、主机:端口、路径）时不算真实标题。等待期间不挂 Stagehand。`observe` / `extract` / `screenshot` / `act` / `scroll` 若当前已是系统错误页或仍空白，同样失败，不得空结果报完成。
  - `WB-PANEL-004-AC18` `navigate` 成功给模型：`Tab`（tabId）、有标题时 `Title`、`URL`（最终地址）。失败给模型：`Error`（含中文说明与错误码，需要时写入尝试过的地址）和 `Tab`（tabId），便于模型决定是否在同一标签重试，而不是盲目新开标签。JSON 仍用 `page: { title, url }`，文案不再把标题和地址挤在一行 `Page:` 里。
  - `WB-PANEL-004-AC19` 主框架加载期间，地址栏行底边出现约 2px 浅蓝色进度线（约 12% 起向 85% 推进）；`isLoadingMainFrame()` 变为 false，或已写入馆长错误页后，走到 100% 并淡出。错误页展示期间不得继续显示进度线。不在原生网页上叠转圈遮罩。

### 8.7 直接写回与回退

#### WB-APPLY-001 打开 AI 修改记录后的默认选中逻辑

- 系统行为：从 assistant turn 打开修改记录时，自动展开右侧面板并打开或激活对应文件 Tab，但工作区文件列表默认保持关闭；用户手动打开文件列表后默认进入“本次运行改动”，并选中当前文件。同一路径只保留一个文件 Tab。Docx 工具修改使用 Review Docx，普通文本记录使用结构化文本 diff。
- 验收：
  - `WB-APPLY-001-AC1` 成功打开修改记录后，界面立即可见当前文件面包屑；若记录存在审核内容则默认进入审核模式并展示回退入口，切到预览模式后隐藏回退入口和差异信息。
  - `WB-APPLY-001-AC2` 在同一轮多文件场景下，点击哪个修改文件入口，右侧就加载该文件记录，而不是空白态或自动跳到其他文件。
  - `WB-APPLY-001-AC3` 用户点击 assistant turn 中的本轮“修改的文件”入口后，右侧应进入修改的文件工作区，并默认加载该入口对应的本轮修改记录。

#### WB-APPLY-002 AI 修改完成后直接写回

- 系统行为：受支持 `docx`、`pptx`、`xlsx`、图片生成和普通文本写任务完成后直接写回源文件或创建目标文件，并生成修改记录。普通文本支持创建、完整改写、唯一文本编辑和全部精确匹配替换；保存前校验失败时不写入，保存后校验或后续处理失败时不自动恢复，错误须说明实际文件状态并提示重新读取（见 `WB-APPLY-003-AC14`）。各格式写入细节由 AI tool / live 回归覆盖（见 `doc/ai-harness/tool-design.md`）。
- 验收：
  - `WB-APPLY-002-AC1` 修改现有 `docx` 后，源文件立即变为 AI 最终净稿，assistant turn 展示本轮「修改的文件」入口。
  - `WB-APPLY-002-AC2` 新建 `docx` 后，目标文件立即存在，assistant turn 展示本轮「修改的文件」入口。
  - `WB-APPLY-002-AC3` 创建或修改普通文本文件后，目标文件立即更新并生成修改记录；运行期间不展示修改入口，收到 `run_completed / run_failed / run_cancelled` 后 assistant turn 才展示本轮「修改的文件」，右侧可查看由真实写入前后内容计算的文本 diff。`answer_completed` 不视为 run 已结束。
  - `WB-APPLY-002-AC4` 普通文本 `edit` 的每个 `oldText` 必须唯一且互不重叠；`replaceAll` 替换一个 `oldText` 的全部非重叠精确匹配；匹配、范围等保存前校验失败时文件保持原样，保存后失败遵循 `WB-APPLY-003-AC14`。
  - `WB-APPLY-002-AC5` 同一次 AI Run 对同一个 pptx 的多次编辑只生成一条修改记录；PPT Diff 固定比较本 Run 第一次接触文件时的状态和 Run 完成后的最终状态。
  - `WB-APPLY-002-AC6` 创建或修改 `xlsx` 后，正式路径立即包含最终净工作簿并生成一条修改记录；同一次 AI Run 对同一路径连续编辑时保持首次写入前基线，不重复生成记录。
  - `WB-APPLY-002-AC7` 生成 PNG、JPEG 或 WebP 图片后，正式路径立即包含可读取图片并生成一条修改记录；同一次 AI Run 对同一路径再次生成时自动更新并保持首次写入前基线。
  - `WB-APPLY-002-AC8` 写回 `.docx` / `.pptx` / `.xlsx` 后的 WPS 自动刷新见 `WB-WPS-001`。

#### WB-TERMINAL-001 终端执行

- 系统行为：智能模式可通过终端执行命令；默认 cwd 为用户主目录。单次 `terminal_run` 可指定最长盯着命令结束的时间；到点后命令继续执行，本次调用不再盯。未指定时按原有默认盯时。长命令可在运行中让出控制权并由后续读取续接；命令遵守审批与安全策略。绝对路径可访问工作地址外文件。终端改文件不进入修改记录，也不能从馆长回退。涉及数据计算、对账、统计等数值处理时，须通过终端真实执行计算，不得仅靠模型推算后直接写出结论文件。终端工具协议与并发/游标细节由 AI tool 回归覆盖。
- 验收：
  - `WB-TERMINAL-001-AC3` 删除伙伴、取消所属 run 或退出应用不会遗留进程。
  - `WB-TERMINAL-001-AC4` terminal 命令继续遵守审批与其他安全策略；不能访问其他伙伴的终端。
  - `WB-TERMINAL-001-AC7` AI 涉及数据计算、对账、统计、求和、对比等数值处理时，必须通过 terminal 执行真实计算；计算结果由终端命令产出，结果文件不自动进入修改记录与回退。
  - `WB-TERMINAL-001-AC8` `terminal_run` 的 `maxWaitSeconds` 只限制本次调用盯着命令结束的时间；到点后命令继续执行，不中断命令。

#### WB-APPLY-003 回退本次 AI 修改

- 系统行为：受控文件工具写回工作地址内文件时立即保存本次 run 的修改记录、有效变更校验和所需快照。AI 或用户在没有受控工具写回时产生的外部变化（含终端改文件）不归入任何 AI Run。基线内容按 SHA-256 保存；内容 Diff 由主 run 收尾根据首次原始内容与最后确认版本生成，历史审核仅消费自包含产物。回退使用修改前对象，不反向计算 Diff。
- 验收：
  - `WB-APPLY-003-AC1` 未发生后续修改时，回退恢复写回前 checkpoint，记录状态变为 `reverted`。
  - `WB-APPLY-003-AC2` 新建文件回退时删除 AI 新建目标文件。
  - `WB-APPLY-003-AC3` 回退成功后，右侧修改的文件工作区应刷新记录状态；普通文本历史 diff 继续保留并标记“已回退”或“已删除”，避免丢失本次修改记录。
  - `WB-APPLY-003-AC5` Docx 工具修改保存 before 和 Review Docx；Review Docx 继续由现有 Docx Renderer 渲染并保留段落、表格、图片、字体和页面结构。
  - `WB-APPLY-003-AC6` PPT 修改记录使用 Diff Manifest v4，在审核模式提供固定的修改前后页面快照；不支持的审核格式明确报错。Excel 专用工具修改 `xlsx` 时在审核模式提供单元格边框标记，并可切换到预览模式。
  - `WB-APPLY-003-AC7` 图片生成记录直接预览最终图片并提供回退，不显示不存在的图片 Diff；更新图片回退后恢复首次生成前的文件，新建图片回退后删除目标文件。
  - `WB-APPLY-003-AC8` Docx Review 固定比较本次任务首次原始文档和最终文件，不依赖编辑操作历史；删除保留原位置，新增保留最终位置，移动使用原位置红删和新位置绿增。相同首尾状态生成相同净审阅；恢复原状、新增后删除不留下本轮修改记录或过期统计。
  - `WB-APPLY-003-AC11` 同位置段落及单元格文字使用用户感知字符级 Diff：未变字符只出现一次，删除字符红色加删除线，新增字符绿色，替换旧字符在前新字符在后；跨 run、超链接、空白、emoji 和组合字符保留正确格式及结构。字段、公式、图片等结构按对象处理。
  - `WB-APPLY-003-AC12` 纯格式变化在最终内容上局部标绿，不复制正文，不插入说明文字。文字样式仅标记变化字符，段落、单元格、表格及节设置标记对应范围；默认浅绿背景，已有背景或背景变化使用绿边框，保持真实字体颜色。格式恢复取消标记；不可定位的文档级变化只保留有效记录，不误标无关正文。
  - `WB-APPLY-003-AC13` Docx 预览、统计及有效记录使用同一净差异结果；文字新增、删除按内容块或单元格计数，替换和移动计 +1/-1 且有效修改计一项，逐字展示不逐字计数；纯格式及独立文档级变化计有效修改但不伪造文字增删，组合变化不重复计数。
  - `WB-APPLY-003-AC9` 专用写工具成功前正式文件已保存并校验；历史审核固定首次原始 A→最后确认 B，后来正式文件变为 C 时预览显示 C、审核仍显示 A→B。只在主 run 真正完成、失败或取消时生成审核，子任务、yield 和追加消息续接不提前生成。
  - `WB-APPLY-003-AC14` 保存失败不自动恢复。提示与实际文件状态一致，已成功保存的修改继续有效；运行中断后启动补生成审核，不继续 AI 或改变正式文件。审核失败显示错误并保留重试输入。
  - `WB-APPLY-003-AC15` 清理临时 B 后历史审核仍完整可用，文本可展开未变行。审核产物缺失、损坏或格式不支持时明确报错，不回退到当前文件。PPT 备注变化只保留修改标记；Excel 保留空白样式、行高、列宽及合并，删除 Sheet 以唯一合法“原名（已删除）”展示，新 Sheet 保留正式名。
  - `WB-APPLY-003-AC16` 不同 run 的审核独立；两轮依次撤销可分别恢复 B、A 的原始字节。清空消息保留回退记录与资源，删除伙伴清理对应目录。
  - `WB-APPLY-003-AC10` 回退 `.docx` / `.pptx` / `.xlsx` 后的 WPS 自动刷新见 `WB-WPS-001`。

#### WB-WPS-001 已打开的 WPS 文档随写回自动刷新

- 系统行为：
  - 这是默认功能，设置页没有开关。馆长启动后在 `127.0.0.1` 开启回环服务（优先端口 `18723`，避开 Windows Hyper-V/WinNAT 会动态排除的 ephemeral 端口；若该端口已是本馆长 `/status` 通道则不再另开端口；仅当该端口被占用或系统拒绝绑定（`EACCES`）时才改用空闲端口监听）。
  - `publish.xml` 与已授权 `ncurator-sync` 的 path 始终写成 `http://127.0.0.1:18723/addon/`，不随临时监听端口改写，避免 WPS 把加载项当成新身份反复弹授权；实际监听端口只写入 port.json，加载项用它连接 SSE。从旧端口 `58123` 迁到 `18723` 只改写这一次授权地址。授权条目的 mode/path 已经正确时不再重写 `authaddin.json`，也不改 namelist。
  - 文字、表格、演示是独立组件，需各自载入加载项（每个组件授权一次）；只有对应组件连上后，该格式窗口才会先 close 放锁再写盘再 open。加载项只按当前组件识别，不得探测其他组件的 `ActiveWorkbook` / `ActivePresentation` / `ActiveDocument`。本机 WPS 7.3 上 `file://` / `jsplugin` 离线目录只会弹出授权、不会载入功能区和 JS；加载项代码必须由回环 HTTP 提供。加载项带「馆长」功能区页签（文字组件功能区上的中文页签名）。
  - 同一组件可能同时活着多个加载项实例（用户开了第二个窗口、或上一个实例还没退干净），每个加载项页面自报一个 `clientId`，馆长按 `clientId` 而不是按组件维护已打开文档表，close / open 只投给确实持有该文档的那个实例，实例断开后它登记的文档随即失效。
  - 加载项连上且文档已打开时，AI 写回或回退 `.docx` / `.pptx` / `.xlsx` 前先推送 close；写盘成功后再让该文档窗口显示新稿。写盘前轮询直到该路径可写，避免 Windows 独占锁尚未放下。加载项必须先真正关掉文档、复查已不在文档列表，才上报 close-result；`Close` 被组件静默忽略时上报失败，馆长据此放弃写盘，不让磁盘换了新稿而窗口还留着旧稿。close-result 带上本组件关闭后的剩余文档数 `remaining`。
  - Windows 版 WPS 用单一宿主进程承载文字 / 表格 / 演示，关掉某组件最后一篇文档后该组件就无法再 `Open`，因此不得用「SSE 是否断开」判断加载项能否干活：`remaining` 为 0 时加载项先建一个空占位文档撑住组件进程，写盘后 open 回目标文档再关掉占位，并在 close-result 里说明占位是否建起。`remaining > 0` 或占位已建起时推送 open，由加载项打开磁盘文件并尽量恢复滚动/选区；占位没建起来、或该组件客户端已断开时，才用该组件可执行文件拉起文档（Windows 上为 `wps.exe` / `et.exe` / `wpp.exe`，不用 `cmd start`，以免塞进其它组件已打开的窗口），Mac 用系统打开。
  - 表格与演示组件不注册 ApiEvent，系统打开后不会主动上报文档列表，馆长按固定间隔向该组件推送 list，直到该路径重新登记后再要摘录，不再二次 Open，避免 WPS 弹出不能重复打开。被指派的加载项回报 open 失败、或推送 open 后超时仍无成功结果时，降级为一次系统打开；其它实例的失败回报不作数，不得把正在干活的实例挤去走系统打开。同一路径全程只允许一次系统打开，避免双开抢锁。
  - 加载项收到 open 时若发现目标文档还开着，说明上一步 close 没落地、内存里仍是写盘前的旧稿，必须真关掉再从磁盘打开，不得只因「已经开着」就回报成功。本实例刚 close 过才允许 Open；既没 close 过、当前也没开着，上报 `not open here`，不得抢开别的实例或从未持有的文档。滚动/选区只用于尽量恢复。加载项只处理与自身组件扩展名相符的路径。
  - Windows 上 WPS 对已打开文档持独占锁，不先 close 则无法覆盖。
  - 本机回环 `GET /status` 提供诊断：已连接客户端、最近一次 dispatch、最近一次 close-result、加载项最近一次 reload-result、WPS 对 `/addon` 的请求。验收以 `/status` 为准，不靠人眼看功能区。
  - 未安装 WPS、加载项未授权、未连接或文件未在 WPS 打开时不发 close，直接尝试写盘，写成功后再发 open（无客户端则为空操作）；不得因刷新失败而回滚已成功的写盘。Windows 上文件仍被 WPS 独占时写盘会失败，这是系统锁而不是馆长回滚。加载项路径未命中时仍上报 reload-result。WPS 里有未保存编辑时同样照刷，会丢这些未保存内容。
  - `.doc` / `.ppt` / `.xls` 以及 Microsoft Office 不在范围内。知识库不因这次刷新而重索引。
- 验收：
  - `WB-WPS-001-AC1` 馆长启动即启动回环服务，把 `publish.xml` 写成回环 `/addon` 地址 `http://127.0.0.1:18723/addon/`，并把已有 `ncurator-sync` 授权条目从离线目录改写为同一 HTTP 地址；不把加载项再拷成 WPS 离线目录。未发现 WPS 加载项目录时不写系统配置。Workbench e2e 跳过覆盖拷文件，仍启动回环服务；`publish.xml` / 授权 path 保持优先端口，端口文件记录实际监听端口。

### 8.11 应用内文本编辑

#### WB-EDIT-001 Markdown 与普通文本应用内即时渲染编辑

- 系统行为：
  - 右侧面板打开真实本地 `.md`/`.markdown` 文件时，使用即时渲染（IR）编辑方式——文件内容渲染为排版预览，点击任意位置直接编辑文字；光标进入加粗、行内代码等 markdown 语法元素时，该元素局部露出 markdown 源可编辑。
  - **点击链接时打开目标**：`http(s)` 经系统默认浏览器打开；相对路径 / `file://` / 本地绝对路径相对当前 `.md` 所在目录解析后经系统默认应用打开；目标不存在或无法打开时 toast 提示。
  - 标题元素前不展示 H1/H2 等标题级别标签（Vditor 默认 `::before` 标签）与 `#`/`##` 等标题源标记，标题不加额外装饰（无下划线），保持沉浸式排版；编辑区始终撑满右侧面板，不出现右侧灰色残留。编辑器不展示任何操作按钮、工具栏或交互栏，用户打开即可直接编辑。
  - 内嵌图片：相对路径、`file://` 与本地绝对路径按当前 `.md` 所在目录解析后在编辑器内展示（不改写磁盘源）；`http(s)` 可直接显示。双击已加载成功的图片打开应用内 `ImageLightbox` 预览；加载失败的图片双击不打开预览并 toast「图片无法加载」。
  - 打开 `.txt` 及其他严格 UTF-8 普通文本（如 `.log`、`.json`、代码、配置文件、无扩展名文本）时，使用与纯文本预览一致的纯文本编辑框直接编辑；纯文本内容（编辑态与只读预览态）每行前显示行号，行号随内容同步滚动。

- 范围边界：应用内编辑不生成 AI 修改记录、不进入回退体系；不限定只能编辑已添加工作地址内的文件，任意本地真实文件均可编辑。
