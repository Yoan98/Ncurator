# Workbench PRD

## 1. 文档定位

- 本文档是 workbench 用户可见功能的产品规格来源，描述目标、范围、术语、交互、状态、边界和验收标准。
- workbench 的用户可见行为、流程、反馈或阻塞逻辑发生变化时，必须同步更新本文。
- 后续实现、测试、评审和 AI 最终汇报都应引用本文中的需求编号与验收编号。

## 2. 产品目标

- 用户通过对话让 AI 完成搜索、分析、回答、整理和文档处理等任务。
- 用户可以把本地资料作为上下文，让 AI 优先据此完成检索、分析、回答和受支持文件处理。
- 让 workbench 成为“发起任务、查看过程、处理中断、查看修改的文件并按需回退、继续执行”的主工作台。
- workbench 应把任务推进到完成；无法完成时明确说明原因、限制或所需条件。

## 3. 产品原则

- 本地资料是重要上下文，但不是唯一能力边界；未显式选择资料时，AI 仍可完成通用任务。
- workbench 的发送前提是先绑定可用工作区；可用工作区指当前已选择工作区且该工作区已设置工作文件地址。是否再显式插入 `@` 本地目录、文件或网页资料，是在此基础上的可选上下文控制。
- 当用户显式绑定工作区或插入 `@` 参考资料时，AI 应优先基于这些范围完成任务，而不是忽略用户给出的约束；工作区既包含本地资料，也包含该工作区下的网页资料。
- workbench 不只展示问答过程，还要交付可消费结果，或给出明确失败信息。
- 用户可见能力边界必须明确可见，尤其是哪些资料可检索、哪些格式可直接写回并回退、哪些情况只能查看或分析。

## 4. 范围

- 包含会话管理。
- 包含 composer 输入、发送、取消与模式切换。
- 包含智能模式下 AI 推进偏好的选择与本机恢复。
- 包含附件拖放和智能模式下执行权限的选择与会话恢复。
- 包含 `@` 参考资料 token 的插入与维护。
- 包含 AI 运行中的审批、搜索模式提示与上下文压缩过程提示。
- 包含右侧内容面板中的搜索结果、文档查看与修改的文件回退入口。
- 包含基于本地资料和网页资料的上下文使用。
- 包含定时任务的入口、配置、启用开关与到点自动创建会话并发送任务。
- 不包含设置页中的资料配置逻辑。
- 不包含视觉风格与基础控件样式定义。

## 5. 当前能力边界

- workbench 可使用当前工作区内已导入的本地资料和网页资料作为任务上下文。
- 当前本地知识库可索引文件类型为 `.pdf`、`.doc`、`.docx`、`.md`、`.markdown`、`.txt`、`.xlsx`、`.xlsm`、`.xltx`、`.xltm`。每个文件索引时都会前置一个「文件名锚点」内容块，保证按文件名可被知识库搜索命中；空文本文件不产生正文内容，但保留文件名锚点。Excel 只索引文件名、文档标题与工作表名等元数据，不索引任何单元格内容，单元格数据仍由 Excel 专用工具按工作区路径处理。`.doc` 只读，不支持直接编辑。
- 未显式选择参考资料时，智能模式仍可处理通用任务。
- 显式选择目录、文件或网页资料后，任务应优先使用这些资料。只绑定工作区时，默认使用工作区内全部已导入资料；资料不足时，智能模式可用模型通用知识补充通用部分。
- 当前可由 workbench 直接写回并支持回退的受支持文件类型包括 `docx`、`pptx`、`xlsx`、生成的 `png`、`jpg`、`jpeg`、`webp` 图片，以及 Markdown、TXT、配置文件和代码等 UTF-8 普通文本文件；普通文本支持创建、完整改写、唯一文本编辑和全部精确匹配替换。Excel 工具可读取 `xlsx`、`xlsm`、`xltx`、`xltm`，但只允许创建和编辑 `xlsx`，避免写回时丢失宏或模板信息。
- 用户可在右侧面板对真实本地 Markdown（所见即所得）与普通 UTF-8 文本（纯文本）做应用内手动编辑并保存，见 `WB-EDIT-001`；应用内手动编辑不生成修改记录、不进入回退体系。
- 当前通过 composer 附件进入对话上下文的文件不限扩展名，只要是可以选中的文件即可作为附件；`+` 选择和拖放文件保留源文件绝对路径，粘贴文件保存副本到当前工作区。附件不自动预解析，只把名称与路径交给 AI 后续自行处理。AI 工具侧仍有各自格式边界（如 `doc` 只读、`pptx` 可交给 PPT 工具读取和编辑、Excel 工具只写 `xlsx`），无法处理的文件会在 AI 工具层报错。
- 其他格式不保证直接写回和回退。AI 可以在工作区和审批边界内尝试处理，但不属于受支持文件能力范围。
- 终端执行只允许当前平台安全指令集直接运行；一条 terminal 命令被拆分后的每段都命中安全指令集时可直接执行，任一段未命中则必须先经用户手动批准。安全指令集只决定是否可直接执行，不决定执行模式。
- 搜索模式只检索当前工作区下可检索的已导入资料；`@` 候选仍可展示当前工作区下的全部本地目录和文件，但未索引的本地目录或文件不能产生纯搜索结果，部分可检索目录只覆盖其已索引子文件。
- 涉及本地执行、命令、脚本或文件修改的请求，必须先具备工作区绑定；`@` 参考资料不能替代工作区绑定。
- 搜索、文件读取和执行结果必须服务后续回答、结论或文件产物，不能只停留在过程展示中。

## 6. 术语

- 会话：一条独立的聊天上下文。
- 参考资料：通过 `@` 插入的目录、文件或网页资料 token。
- 工作区绑定：当前独立选中的工作区，用于提供本地运行根目录与默认知识库范围（包括本地资料与该工作区下的网页资料）。
- 搜索模式：只执行本地检索，不启动 AI 运行。
- 智能模式：启动 AI 运行，允许产生阻塞、审批、文件直接写回与回退入口。
- 受支持文件：当前已具备直接写回与回退能力的文件类型；当前包括 `docx`、`pptx`、`xlsx`、生成的 PNG、JPEG、WebP 图片和 UTF-8 普通文本文件。
- 目标文件：用户要求新建受支持文件时，AI 写工具直接创建的工作区文件路径。
- 直接写回：AI 写工具将最终 docx、pptx、xlsx、生成图片或普通文本结果原子写入源文件或创建目标文件的流程；工具成功即代表正式路径已可读取，run 收尾不再提交文件。
- 修改记录：一次 AI run 中由受控文件工具直接写回，或由某条 terminal 命令前后差异识别出的创建、更新、删除或重命名记录；提供打开文件、适用格式的审核模式与回退本次修改入口。
- 回退本次修改：基于写回前 checkpoint 恢复文件；新建文件回退时删除目标文件，若文件在 AI 写回后又被修改，需提示用户确认会丢失后续修改。
- 内部引用链接：assistant markdown 中的 `ncurator://ref` 链接。`kind=reference` 表示证据引用，`kind=normal` 表示普通资源链接，`resourceType=file/web` 表示资源类型。证据引用在最终交付生成后由 Main 检查一次可访问性，并携带 `accessStatus=accessible/unavailable`；历史证据缺少该字段时按不可用处理。可用证据可点击，不可用证据显示为弱化文本；普通资源链接不包含 `accessStatus`。
- AI 推进偏好：智能模式下用户对资料使用边界的附加约束，界面选项包括“默认”“本地资料·宽松”“本地资料·严谨”。当前“本地资料”范围包含当前工作区知识库资料、工作区文件和显式参考资料。宽松模式优先使用这些资料，资料不足时允许补充模型知识或外部网页；严谨模式只能把这些资料作为事实依据，资料不足时必须明确说明，不得把模型知识、外部搜索或浏览器结果伪装成资料内事实。
- 执行权限：智能模式下对本次运行是否等待工具审批的选择，独立于 AI 推进偏好。选项为“审核”和“完全访问”。

## 7. 需求规则

- 需求编号使用 `WB-<模块>-<三位序号>`。
- 验收编号使用 `WB-<模块>-<三位序号>-AC<序号>`。
- 需求编号稳定后不因措辞微调而重排；只有功能被废弃时才标记为废弃。
- 定时任务需求编号使用 `ST-<模块>-<三位序号>`，验收编号使用 `ST-<模块>-<三位序号>-AC<序号>`，详见 `8.13 定时任务`。

## 8. 需求明细

### 8.1 核心能力与约束

#### WB-CORE-001 本地资料是可选上下文，不是唯一前提

- 系统行为：workbench 发送前要求先绑定工作区；在此基础上，即使用户未显式选择任何本地参考资料，AI 仍可执行不依赖本地文档的通用任务；当存在本地参考资料时，可将其作为任务上下文使用。
- 验收：
  - `WB-CORE-001-AC1` 用户已绑定工作区但未选择任何本地参考资料时，智能模式仍可正常发起不依赖本地文档的任务。
  - `WB-CORE-001-AC2` 系统不会把“没有显式本地参考资料”误表现为“workbench 不可用”。

#### WB-CORE-002 用户显式选择的参考资料或工作区默认范围必须影响执行

- 系统行为：当用户插入 `@` 参考资料后，后续搜索、分析和执行应优先基于这些显式范围收敛；当用户只绑定工作区而未显式选择参考资料时，搜索与 AI 默认收口到当前工作区全部已导入资料。
- 验收：
  - `WB-CORE-002-AC1` 搜索模式下，显式参考资料或工作区默认范围会直接影响检索结果。
  - `WB-CORE-002-AC2` 智能模式下，系统不会忽略用户已经绑定的工作区或 `@` 参考资料；已选资料作为优先缩圈候选，但不自动变成唯一可搜索范围。

#### WB-CORE-003 当前受支持文件的直接写回能力边界必须明确

- 系统行为：workbench 明确区分“可直接写回并支持回退的受支持文件”和“可由 AI 自行尝试处理但不提供同等保证能力的其他任务”；当前受支持文件类型包括 `docx`、`pptx`、`xlsx`、生成的 `png`、`jpg`、`jpeg`、`webp` 图片和 UTF-8 普通文本文件。`xlsm`、`xltx`、`xltm` 只读，不属于可直接写回范围。
- 验收：
  - `WB-CORE-003-AC1` 当前支持直接写回与回退的受支持文件类型列表明确可见，包括 `docx`、`pptx`、`xlsx`、PNG、JPEG、WebP 图片的修改和新建，以及 Markdown、TXT、配置文件和代码等 UTF-8 普通文本文件。
  - `WB-CORE-003-AC2` 不在当前受支持文件类型列表中的资料不会被伪装成可进入同一直接写回与回退流程的编辑或创建目标。

#### WB-CORE-004 资料优先级受 AI 推进偏好约束

- 系统行为：默认或宽松偏好下，当用户已绑定工作区或插入参考资料时，系统优先基于这些资料完成任务；仅绑定工作区时，默认使用该工作区全部已导入资料作为知识范围。资料不足时，默认或宽松偏好允许补充模型通用知识或外部网页信息，但不能忽略或违背用户已给定的资料。严谨偏好下，只允许把当前工作区与显式参考资料作为事实依据；资料不足时应明确说明缺口，不得使用模型知识、`web_search` 或 `browser_use` 的外部内容补足事实。
- 验收：
  - `WB-CORE-004-AC1` 用户已绑定工作区默认范围或显式参考资料时，问答或受支持文件结果不会脱离这些资料另起一套无关内容。
  - `WB-CORE-004-AC2` 默认或宽松偏好下，资料不足以覆盖通用部分时，系统仍可补充模型通用知识或外部网页信息，并明确区分资料内事实与补充信息。
  - `WB-CORE-004-AC3` 严谨偏好下，资料不足时系统明确说明资料缺口，不使用工作区和显式参考资料之外的信息补足事实。

#### WB-CORE-005 任务过程中的中间结果必须服务于后续结果

- 系统行为：当任务执行过程中产生搜索结果、文件读取结果、执行结果或其他中间信息后，后续 assistant 回答、分析结论和文件产物应实际使用这些信息继续推进用户诉求；若当前中间结果不足以支撑继续完成，系统应明确说明限制，而不是伪造后续内容。
- 验收：
  - `WB-CORE-005-AC1` 任务过程中产生的中间结果，会体现在后续用户可见回答、结论或文件产物中，而不是只表现为“执行过某些步骤”。
  - `WB-CORE-005-AC2` 当前中间结果不足或执行失败时，assistant 会明确说明为什么无法继续完成、缺少什么条件或当前能确认到什么范围，而不是编造结论或文档内容。
  - `WB-CORE-005-AC3` 用户可见输出优先围绕用户原始诉求组织；若引用中间结果，应使用用户能理解的表达，而不是暴露内部工具或过程标签。

#### WB-CORE-006 用户诉求应被推进到完成或明确失败

- 系统行为：当用户已提供足够上下文且当前能力允许时，workbench 应以“最小可靠返回 × 最少连续决策轮次”持续推进用户诉求直到完成：只读取当前决策所需范围，避免全量或重复读取，独立调用尽量同轮发起，同类批量能力不拆轮。若当前无法完成，也应明确返回失败原因、限制信息或下一步所需条件，而不是停留在搜索结果、工具调用或过程提示等中间过程。
- 验收：
  - `WB-CORE-006-AC1` 用户诉求可完成时，系统会把任务推进到可消费结果、明确产物或可确认的下一步动作，而不是停留在中间态。
  - `WB-CORE-006-AC2` 用户诉求当前无法完成时，系统会明确说明失败原因、限制信息或下一步所需条件，而不是无声中断或只留下过程信息。
  - `WB-CORE-006-AC3` 最终收口默认直接围绕用户显式提出的问题组织；若同时需要说明产物、依据或限制，也应使用用户可理解的语言表达，而不是依赖内部标识、tool 名或固定章节标题。
  - `WB-CORE-006-AC4` 简单任务不强制创建 plan；复杂或多依赖任务才维护 plan，不为汇报进度单独更新。目标满足且必要检查通过后可直接交付。

#### WB-CORE-007 网页信息可用于任务推进

- 系统行为：默认或宽松偏好允许 AI 通过后台 `web_search` 搜索网页、读取指定网页正文，并在需要登录或人工操作时使用 `browser_use` 打开右侧内置浏览器继续任务；严谨偏好不得把外部网页作为资料内事实依据。`web_search` 是 Human 图后台工具，结果只回模型与过程层，不得自动展开右侧 `search_list` 面板，也不得替代 `browser_use` 的可见浏览器交互。
- 验收：
  - `WB-CORE-007-AC1` 用户要求查找公开网页信息时，AI 可搜索并读取搜索结果或用户给出的 URL，再用所得内容完成回答或产物。
  - `WB-CORE-007-AC2` 网页搜索、读取或浏览失败时，系统明确说明失败边界，不伪造网页内容。
  - `WB-CORE-007-AC3` 严谨偏好下，外部网页能力不会绕过资料范围限制。
  - `WB-CORE-007-AC4` AI 调用 `web_search` 时，Workbench 不得因工具结果自动打开右侧「搜索结果」列表；过程层可展示“搜索网页 / 抓取网页”等状态，但右侧面板保持原状，除非用户处于 Composer 搜索模式或 AI 触发 `browser_use`。
  - `WB-CORE-007-AC5` `web_search` 的外网抓取在后台 headless CDP host 中完成，用户不得看到带窗框的独立浏览器窗口或主界面被网页内容遮挡。
  - `WB-CORE-007-AC6` `web_search` fetch 默认走 Crawl4AI；抓取超时或失败时可降级为 HTTP 正文提取，以保证任务能返回可读正文或明确失败，而不是无限挂起。

#### WB-CORE-008 Workbench 窗口层与业务内容分层

- 系统行为：Windows Workbench 的原生窗口控制层独立位于业务内容上方；空会话拖动区、侧栏入口和业务内容不互相遮挡。非 Windows 平台保留页面顶部拖动区。
- 验收：
  - `WB-CORE-008-AC1` 空会话仍提供可命中的 44px 拖动区。
  - `WB-CORE-008-AC2` Windows 原生控制层为独立 36px 区域，业务内容从其下方开始。
  - `WB-CORE-008-AC3` Windows 侧栏切换按钮保持 `no-drag` 且与原生控制按钮对齐。

### 8.2 会话管理

#### WB-SESSION-001 无历史会话时先展示可输入草稿态

- 系统行为：页面初始化时拉取会话列表。列表为空时展示可输入的新对话草稿态；进入页面、点击新对话、选择工作区或添加附件都不创建会话，第一条消息发送时才创建。
- 验收：
  - `WB-SESSION-001-AC1` 首次进入且没有历史会话时，界面提供可输入、可选工作区的新对话草稿态，而不是不可操作空白页。
  - `WB-SESSION-001-AC2` 第一条消息发送前，不因进入页面、点击新对话、选择工作区或添加附件而创建真实会话记录。
  - `WB-SESSION-001-AC3` 第一条消息发送成功后，系统创建真实会话，并以该消息前 20 个字符作为标题。

#### WB-SESSION-002 切换会话时恢复目标会话状态并隔离上一会话运行态

- 系统行为：切换会话后，主区原子加载目标会话的消息、运行 snapshot 和 UI 状态。加载完成前保留原画面并展示切换态，不先闪成空白。完成后恢复目标会话自己的输入草稿、`@` 范围、附件、模式、AI 推进偏好、执行权限、模型、工作区、右侧标签和面板展开状态。上一会话的运行态和 UI 状态不得泄漏到目标会话，但目标会话自身的 active run 与 pending approval 必须可继续操作。
- 验收：
  - `WB-SESSION-002-AC1` 点击其他会话后，消息区展示目标会话的历史消息。
  - `WB-SESSION-002-AC2` 切换加载完成后恢复目标会话自己的输入和右侧面板，不保留上一会话的搜索结果、修改面板或运行中阻塞提示；加载过程中主消息区不先闪成空白态。
  - `WB-SESSION-002-AC3` 目标会话存在正在运行或最近完成的 AI run 时，切换回来后能看到已持久化的过程流、当前 partial answer 或最终回答；正在运行的 run 可继续停止。
  - `WB-SESSION-002-AC4` 目标会话存在等待审批的 AI run 时，切换回来后审批卡片仍可继续提交。
  - `WB-SESSION-002-AC5` 会话列表中存在 `running` 或 `waiting_approval` run 的会话显示“任务运行中”标记；运行完成、失败或取消后标记消失，且不会错误显示到其他会话。

#### WB-SESSION-003 首条用户消息驱动标题更新

- 系统行为：新会话创建时，以第一条用户消息的前 20 个字符生成标题；之后发送消息不再自动改名。
- 验收：
  - `WB-SESSION-003-AC1` 第一条用户消息发送后，新创建会话的标题为该消息前 20 个字符。
  - `WB-SESSION-003-AC2` 之后继续发送消息时，不会再次自动改写已有标题。

#### WB-SESSION-004 删除会话后保持可继续操作

#### WB-SESSION-005 同一会话里的续做保持任务主线

- 系统行为：用户在同一会话内基于上一轮结果继续提出局部修改、补写或 refinement 请求时，系统继续沿用当前会话上下文、上一轮产物和有效文件/回退入口，不把续做误当成全新无关任务；若用户明显切换到新的目标对象或新的交付物，系统可在保留历史上下文的前提下按新任务主线处理。
- 验收：

  - `WB-SESSION-005-AC2` 续做完成后的结果体现的是对上一轮结果的继续修改或补充，而不是简单重复旧输出或重新开题。

#### WB-SESSION-006 用户消息复制与编辑

- 系统行为：用户消息支持复制纯文本；没有任务运行时，最新一条用户消息支持编辑。编辑会撤回该消息及其后的 assistant 结果，并把原文字、参考资料和附件恢复到输入区，等待用户修改后重新发送。
- 验收：

  - `WB-SESSION-006-AC2` 只有最新用户消息且当前没有运行中任务时显示编辑入口。
  - `WB-SESSION-006-AC3` 编辑成功后，目标消息及后续回复从会话中撤回，原输入、参考资料和附件恢复为草稿。

#### WB-SESSION-007 同一会话内恢复被中断任务

- 系统行为：智能模式任务因用户主动停止、网络错误、请求超时、应用进程中断、输出截断、达到运行上限或未知异常而没有正常完成时，历史消息日志保持不变。用户之后在同一会话发送消息时，系统从日志投影“最新压缩摘要 + checkpoint 后历史”，补齐悬空工具结果，再把新 user 消息追加一次继续推进。每条历史 user 保留当轮工作区、参考资料和附件配置；新 user 只使用 Composer 当前配置。计划从 `plan_updated` 日志恢复，技能从会话技能状态恢复，不存在独立恢复快照。重启只标记中断，不自动重新调用模型。
- 验收：
  - `WB-SESSION-007-AC1` 用户停止、网络错误、请求超时、进程中断、输出截断、达到运行上限和未知异常后，下一条消息可只靠消息日志与会话技能状态继续。
  - `WB-SESSION-007-AC2` 恢复后的消息数组只包含一次压缩摘要与 checkpoint 后历史，并把用户新语句作为尾部 user 消息追加一次；新语句不会改写历史任务或历史配置。
  - `WB-SESSION-007-AC3` 同一会话连续多次中断和恢复后仍保留完整任务主线，原始任务始终保留在记录首条 user，不把历史任务递归嵌套为新的原始任务。
  - `WB-SESSION-007-AC4` 切换会话或重启应用后，原会话日志仍可投影；其他会话不能读取该日志。
  - `WB-SESSION-007-AC5` 编辑并重新发送最后一条用户消息时，只删除该消息、关联 assistant、run 与该 run 的日志记录，其他历史不变。
  - `WB-SESSION-007-AC6` 正常完成清空计划展示但不删除历史日志；删除会话级联删除其日志。
  - `WB-SESSION-007-AC7` 达到 Graph 运行上限时显示“已达到运行上限，可继续对话推进”，并允许在同一会话继续恢复。

#### WB-SESSION-008 会话界面状态独立持久化

- 系统行为：每个真实会话都在 SQLite 保存独立的 Composer 和右侧资源工作台快照；未发送的新对话使用独立 `__draft__` 快照，首次发送创建真实会话时与浏览器标签一起事务提升。正常切换、离开页面和退出应用前强制保存，重启后恢复最后活动会话。异步 AI、搜索和浏览器事件必须按 `sessionId / ownerId` 更新所属会话，不能覆盖当前其他会话。
- 验收：
  - `WB-SESSION-008-AC1` A/B 会话可分别保存并恢复工作区、模式、AI 推进偏好、执行权限、主模型、输入文本、内容节点、引用、附件和附件桶，反复切换互不串联。旧快照缺少执行权限时按“审核”恢复。
  - `WB-SESSION-008-AC2` A/B 会话可分别保存并恢复搜索结果、资源标签、活动标签和面板展开状态；后台返回只更新事件所属会话。
  - `WB-SESSION-008-AC3` 正常退出并使用同一用户目录重启后，恢复最后活动会话及其完整 UI 状态；异常崩溃最多丢失最后一个输入防抖窗口。
  - `WB-SESSION-008-AC4` 未发送草稿不会创建真实会话；首次发送时草稿 UI 状态和 `__draft__` 浏览器标签在同一事务中转移到新会话。
  - `WB-SESSION-008-AC5` 删除会话时同步删除其 UI 快照和浏览器标签；删除当前会话后按现有规则回落并更新最后活动会话。
  - `WB-SESSION-008-AC6` 模型、引用或附件失效时清理或回退到可用状态并保存修复后的快照；文件预览路径失效时保留标签并展示不可用状态。

### 8.3 Composer 输入与发送

#### WB-COMPOSER-001 发送前置条件

- 系统行为：只有当前存在会话、已绑定可用工作区、输入裁剪后非空且未处于发送中时，发送按钮才可执行；发送按钮因前置条件不满足而不可执行时，用户可通过 hover 查看具体原因提示。
- 验收：
  - `WB-COMPOSER-001-AC1` 纯空白输入不会触发发送。
  - `WB-COMPOSER-001-AC2` 未完成工作区绑定或发送中时，不会重复触发发送。
  - `WB-COMPOSER-001-AC3` 发送按钮不可执行时，hover 可见禁用原因。

#### WB-COMPOSER-002 键盘行为

- 系统行为：`Enter` 发送，`Shift + Enter` 插入换行；中文等输入法组词期间不应被输入区同步、光标恢复或候选刷新打断。
- 验收：
  - `WB-COMPOSER-002-AC1` 按 `Enter` 后触发当前模式对应的发送逻辑。
  - `WB-COMPOSER-002-AC2` 按 `Shift + Enter` 后，输入区保留内容并新增换行，不触发发送。
  - `WB-COMPOSER-002-AC3` 使用中文输入法快速输入时，输入区不会中断组词并遗留未确认的英文拼音字符。

#### WB-COMPOSER-003 智能模式发送路径

- 系统行为：智能模式发送时，renderer 只调用提交接口；Main 侧统一校验会话、输入、模型、工作区与 `@` 范围，并在启动 AI 前创建用户消息、assistant 占位消息和 AI run 记录。AI 运行中的事件先写入会话消息记录（`chat_session_message_log`）作为唯一真相源，再更新 run / assistant message 投影并广播给 renderer；renderer 通过 session snapshot 中的 `runs` 恢复已完成 / 进行中的展示投影（从消息记录按 `seq` 投影重建过程流），通过 `activeRuns` 继续运行中或等待审批的交互状态，并结合实时事件展示思考层、决策层、执行层、学习层、压缩层、总结层与最终 markdown 输出。输入区模式选项中该模式展示为“大聪明”，但内部模式语义仍是智能模式。
- 验收：
  - `WB-COMPOSER-003-AC1` 智能模式发送后，主区先可见用户消息与 assistant 占位消息。
  - `WB-COMPOSER-003-AC2` AI 运行成功启动后，assistant 过程流通过事件逐步追加更新，而不是一次性静态替换。
  - `WB-COMPOSER-003-AC3` assistant 占位回复在最终输出前展示“让俺想想”并带有流动视觉反馈；当后端 thinking 过程事件到达时，本地占位被替换为该 run 的 thinking 过程组，不重复展示；当出现“正在重试”过程组时，必须隐藏“让俺想想”占位，避免两个等待状态同时出现。
  - `WB-COMPOSER-003-AC4` assistant turn 中 brain 最终输出始终位于过程流下方，并按 markdown 渲染；等待 AI 返回最终输出时先展示总结层“基本完成了，让俺收尾下吧”，首个 markdown token 或完成事件到达后隐藏该等待层；证据引用链接与普通链接视觉区分，内部文件链接打开右侧文件预览，内部网页链接使用系统浏览器打开。
  - `WB-COMPOSER-003-AC5` 决策层文本来自 `assistant_process_thought` 中经过 schema 约束的 `thought.next`，不得展示模型原始 chain-of-thought；决策层出现时，当前思考层必须立即隐藏，即使下一步执行正等待审批。
  - `WB-COMPOSER-003-AC6` 过程流使用用户可理解的分层文案，不直接暴露内部 tool 名或底层事件名；同一轮执行中的多个工具调用合并为一个执行层 header，展开后每个工具按其入参生成一句自然语言说明。
  - `WB-COMPOSER-003-AC7` AI 输出中切到 Settings 或触发 renderer 重新挂载后，回到 Workbench 能通过会话消息记录投影恢复过程流、partial answer、最终回答或等待审批状态。
  - `WB-COMPOSER-003-AC8` brain 负责在最终交付 markdown 中生成证据引用（名称、地址、资源类型）；最终交付生成后、回传 renderer 前，Main 对引用地址并行去重检查并写入证据专用的 `accessStatus`。可访问引用保留文件或网页链接交互；不可访问引用不得删除，必须使用与可访问引用相同的强调色降低透明度，并显示为无资源图标、无悬浮反馈、普通鼠标且不可点击的文本。缺少 `accessStatus` 的证据按不可访问处理，普通资源链接不使用该字段；renderer 渲染和用户点击时均不再次检查可访问性。
  - `WB-COMPOSER-003-AC9` terminal 审批要求表示命令正在等待用户决定，不属于执行失败；用户未允许时命令状态为未执行且不得产生 terminal step。命令启动后自然退出时，无论退出码是否为零，都属于执行完成并保留真实退出码供 brain 判断；只有终端执行器、Shell 或会话在执行期间异常时才显示“执行终端指令失败”。用户主动停止单独记录为已取消；正常中断后终端回到 idle，强制终止进程树后终端进入 closed。

#### WB-COMPOSER-004 搜索模式发送路径

- 系统行为：搜索模式发送时，不启动 AI 运行；renderer 只调用提交接口，Main 侧创建用户消息、执行现有搜索，并创建一条已完成的 assistant 结果摘要消息，右侧进入搜索结果态；输入区模式选项中该模式展示为“没头脑”，但内部模式语义仍是搜索模式。
- 验收：
  - `WB-COMPOSER-004-AC1` 搜索模式发送后，不启动 AI 运行流程。
  - `WB-COMPOSER-004-AC2` 搜索提交期间发送按钮保持发送中状态，避免重复提交。
  - `WB-COMPOSER-004-AC3` 搜索成功后，主区展示用户消息和 completed assistant 结果摘要，右侧内容面板展示命中列表和命中详情。

#### WB-COMPOSER-005 发送前必须先绑定工作区

- 系统行为：workbench 的发送前必须已有可用工作区绑定；可用工作区绑定指当前已选择工作区且该工作区已设置工作文件地址。当工作区列表为空、绑定失效、当前尚未完成工作区选择或所选工作区未设置工作文件地址时，发送按钮保持不可执行，并在 composer 附近提示用户先完成工作区设置。
- 验收：
  - `WB-COMPOSER-005-AC1` 无可用工作区绑定时不会直接启动 AI 运行或纯搜索，发送按钮保持不可执行。
  - `WB-COMPOSER-005-AC2` 未选择工作区时，提示会明确要求先选择工作区；已选择工作区但未设置工作文件地址时，提示会明确要求前往设置页完成目录绑定；未显式插入 `@` 参考资料时，后续默认使用当前工作区全部已导入资料作为默认检索范围。

#### WB-COMPOSER-006 AI 运行取消

- 系统行为：智能模式在当前任务仍在运行时，composer 不展示独立取消按钮；底部发送按钮切换为停止图标，点击后直接中止当前 run。若当前 run 正在等待审批，停止也必须释放审批等待并结束本次 run。
- 验收：
  - `WB-COMPOSER-006-AC1` 运行中发送按钮切换为停止图标，页面不再显示独立“取消”按钮。
  - `WB-COMPOSER-006-AC2` 点击停止图标后，当前运行结束并给出已取消反馈。
  - `WB-COMPOSER-006-AC3` 当前运行卡在审批等待时，点击停止图标也会结束本次 run，而不是继续等待审批提交。

#### WB-COMPOSER-007 模型、工作区、AI 推进偏好与执行权限选择

- 系统行为：输入区底部展示当前模式和主模型。模型列表行只保留服务商图标、模型名和选中勾，不使用 Tooltip、眼睛或价格图标；鼠标悬浮或键盘聚焦模型时，在列表右侧展示说明、能力和“较低 / 适中 / 较高”价格档位，空间不足时翻到左侧。视觉能力属于预设模型元数据；自定义模型只展示配置名、模型 ID 和“能力与价格信息未提供”。其余工作区、推进偏好、执行权限、会话快照和回退规则保持现有契约。
- 验收：
  - `WB-COMPOSER-007-AC1` 模型选择展开后展示预设模型区与底部「自定义模型」入口；进入自定义模型视图后为原服务商分组面板效果，可按模型名称搜索候选。
  - `WB-COMPOSER-007-AC2` 预设模型平铺展示且不出现分组标题；列表行只含服务商图标、模型名和选中勾。
  - `WB-COMPOSER-007-AC3` 悬浮或键盘聚焦模型时显示可左右翻转的信息侧栏；预设模型展示说明、能力和“较低 / 适中 / 较高”价格档位，自定义模型不猜测信息。
  - `WB-COMPOSER-007-AC4` 选中预设模型后输入框展示服务商图标与模型名，选中自定义模型后展示模型名；会话快照存储 `configId + modelName`。
  - `WB-COMPOSER-007-AC5` 用户切换模式、AI 推进偏好、执行权限、模型或工作区后，切回该会话或重启应用时恢复该会话自己的 SQLite 快照。
  - `WB-COMPOSER-007-AC6` 当会话快照中的工作区或模型已失效时，系统自动清理或回退到当前可用候选，并保存修复后的快照。
  - `WB-COMPOSER-007-AC7` 模型选择和工作区选择入口都有可识别图标，而不是只展示纯文本。
  - `WB-COMPOSER-007-AC8` 输入区模式入口展示“大聪明 / 没头脑”，该展示文案不改变智能模式与搜索模式的内部行为。
  - `WB-COMPOSER-007-AC9` 智能模式下可选择默认、本地资料宽松和本地资料严谨三种推进偏好；本地资料入口通过二级菜单选择宽松或严谨。
  - `WB-COMPOSER-007-AC10` 切换到搜索模式后 AI 推进偏好入口隐藏；切回智能模式后保留此前选择。
  - `WB-COMPOSER-007-AC11` 发送智能任务时，当前 AI 推进偏好会进入 Main 侧 AI run 上下文并影响资料使用边界。

### 8.5 `@` 参考资料

#### WB-SCOPE-001 `@` 候选来源规则

- 系统行为：输入 `@` 后，根据当前关键字和当前工作区返回目录、文件和网页资料候选。每次进入新的 `@` 候选状态时，系统读取当前工作区的真实本地目录树和当前网页资料列表；本地索引只补充索引状态，不决定候选是否出现。打开后的本轮输入只过滤这份快照，不重复扫描目录。正常发送前用户必须先完成工作区绑定，因此候选基于当前工作区返回全部本地目录、本地文件和网页资料；候选浮层按“文件”和“网页”两组展示，本地目录归入“文件”组并通过目录图标区分，右侧只展示索引状态。若工作区尚未就绪，则不开放发送，并提示先完成工作区绑定。
- 验收：
  - `WB-SCOPE-001-AC1` 未完成工作区绑定时，不返回其他工作区的本地目录或文件，也不会把未绑定工作区时的资料选择当作正常发送路径暴露给用户。
  - `WB-SCOPE-001-AC2` 选中工作区后，候选中同时可出现本地目录、本地文件和网页资料；候选覆盖当前工作区下的全部本地目录和文件，且只展示“文件”和“网页”两组，目录位于“文件”组内并通过图标识别。
  - `WB-SCOPE-001-AC3` 在上一次索引或候选打开后新增、修改或删除本地文件时，下一次打开 `@` 必须反映真实目录；新增或变更但未索引的文件仍可选择，并显示“未索引”。

#### WB-SCOPE-002 `@` 插入与删除规则

- 系统行为：候选可通过键盘或鼠标插入为内联 token；目录、文件和网页资料都可作为合法 token 插入；输入区支持多个已插入 token 共存；token 使用无边框的紧凑图标加名称样式展示。目录、网页、PDF、DOCX、PPT/PPTX 使用各自的专属样式；Markdown、TXT 和其他文件统一使用普通文件样式。文字与图标保持同色。按 `Backspace` 可移除参考资料；发送后，用户消息中保留本轮参考资料 token 回显，样式与输入区 token 保持一致。
- 验收：
  - `WB-SCOPE-002-AC1` 目录、文件或网页资料插入成功后，参考资料以 token 形式保留在输入流中，并进入后续发送参数。
  - `WB-SCOPE-002-AC2` 输入区支持多个已插入 token 共存，而不是后插入覆盖前一个范围。
  - `WB-SCOPE-002-AC3` 删除 token 后，对应范围不再参与后续发送。
  - `WB-SCOPE-002-AC4` 发送后，用户消息仍展示本轮 `@` 参考资料 token，用户可从消息中看见当时选择的资料范围。

### 8.6 AI 运行中的阻塞与提示

#### WB-BLOCKER-001 审批阻塞

- 系统行为：审核权限下，AI 运行收到批量审批事件后，在输入框上方展示紧贴 composer 的审批卡片；卡片一次只展示当前一条审批项，用户可通过上下切换浏览整批，并且必须先完成整批审核后系统才会继续决策是否执行。审批卡片不展示内部策略原因，命令文本与同意/拒绝图标按钮左右排列，指导输入框与提交按钮同排展示；审批不自动超时，必须等待用户明确操作或运行被取消/关闭。完全访问权限下，统一审批入口直接批准该 run 的所有审批项，不创建等待审批状态、不发送审批事件、不展示审批卡片。完全访问只跳过审批，不绕过工作区绑定、命令安全限制、取消、工作区内文件变更记录或其他运行时保护。

- 验收：
  - `WB-BLOCKER-002-AC1` 智能模式下，未完全索引参考资料不额外展示耗时 warning。
  - `WB-BLOCKER-002-AC2` 搜索模式下明确说明部分可检索目录只覆盖其已索引子文件。

#### WB-BLOCKER-003 上下文压缩过程提示

- 系统行为：当 AI 运行触发上下文压缩时，后端通过 `assistant_process_group_started` 派发 compaction 过程组，assistant turn 展示“东西太多了，让俺整理下”；压缩完成后通过 `assistant_process_group_completed` 更新为“呼，终于整理好了，累死俺了”。
- 验收：

  - `WB-BLOCKER-003-AC2` 收到 compaction 类型的 `assistant_process_group_completed` 事件后，该过程组更新为完成态并展示完成文案。

### 8.7 右侧内容面板

  - `WB-PANEL-003-AC9` 同一文件存在多个 Run 修改批次时，默认展示最新批次；工具栏下拉使用用户请求摘要和时间切换历史批次，不展示内部 Run ID，也不把多个 Run 强制合成一份累计 Diff。
  - `WB-PANEL-003-AC10` 当前文件在“全部”和“本次运行改动”中都使用稳定浅灰选中态，并在切换后自动进入可见范围。
  - `WB-PANEL-003-AC11` assistant turn 的“修改的文件”列表使用 `工作区/目录/文件` 路径；右侧文件预览工具栏继续使用 `工作区 > 目录 > 文件` 面包屑。

#### WB-PANEL-004 内置浏览器面板

- 系统行为：每个浏览器 Tab 对应独立 Electron `WebContentsView`，全部视图共享持久分区 `persist:ncurator-browser`。该面板只服务用户手动开标签和 `browser_use`；`web_search` 的外网抓取使用独立隐藏 CDP host，不得复用或污染本面板。浏览器 Runtime、界面 Presentation 和 AI Automation 相互独立：切换文件、折叠右侧栏或切换会话时，只从主窗口显示树移除 View，不关闭 `webContents`，不改变 AI 的 CDP target；重新显示时挂载同一个 View 并展示后台操作后的实时最终状态。浏览器导航栏提供后退、前进、刷新/停止、URL 输入、输入框内“前往”按钮和更多操作；浏览器更多菜单及新增标签页菜单使用主窗口原生子窗口承载自绘内容，覆盖在浏览器上方且不隐藏浏览器。
- 验收：
  - `WB-PANEL-004-AC1` 收到 AI 浏览器面板事件后，右侧显示事件指定的浏览器 Tab；面板动画期间不逐帧缩放原生 View，动画结束后按最终 bounds 一次挂载并与正文视口对齐。
  - `WB-PANEL-004-AC2` AI 通过 `browser_use` 的 `navigate` 动作传入 URL 时，右侧内置浏览器先导航到该 URL；`extract / observe / act` 只作用于当前页面、不会跳转，需要切换页面时先调用 `navigate`。
  - `WB-PANEL-004-AC3` 切换到文件 Tab、收起面板或切换会话时，浏览器 View 从主窗口显示树移除，不使用窗口外坐标停放；`webContents`、页面 JS、网络请求、Cookie、滚动位置、表单和 SPA 状态继续存在。
  - `WB-PANEL-004-AC4` AI 浏览器任务完成后，assistant 最终输出应使用浏览器操作获得的结果完成用户诉求，右侧浏览器面板状态与最终回答形成可理解的任务闭环。
  - `WB-PANEL-004-AC5` 多个浏览器标签可以打开相同 URL；Stagehand 必须按浏览器 Tab 对应的 CDP targetId 精确选择页面，不得按 URL 猜测或串页。
  - `WB-PANEL-004-AC6` 浏览器标签共享 Cookie、登录态、LocalStorage、IndexedDB、Service Worker 和 HTTP 缓存；除非用户主动清除浏览数据，应用不得自动清空持久分区。
  - `WB-PANEL-004-AC7` 新增标签页和浏览器更多菜单使用无边框原生子窗口显示在浏览器上方；菜单打开期间浏览器保持原尺寸和可见状态，点击外部、按 Escape、主窗口移动或切换 Tab 时关闭菜单。
  - `WB-PANEL-004-AC8` 浏览器更多菜单的缩小、百分比、放大必须位于同一行且都可点击；缩放操作不关闭菜单，百分比可恢复 100%，系统浏览器打开入口位于分割线下一行。
  - `WB-PANEL-004-AC9` 地址为空时“前往”按钮禁用；地址非空时点击按钮或按 Enter 都导航到相同目标，按钮 tooltip 与无障碍名称均为“前往”。
  - `WB-PANEL-004-AC10` 内置浏览器自动化不得依赖固定 CDP 端口；旧端口 `9333` 或其他本地端口已被占用时，应用仍应正常启动并通过随机回环端口完成浏览器任务。
  - `WB-PANEL-004-AC11` AI 在浏览器未显示时仍可按原 targetId 连续执行 observe、act、extract 和导航；恢复后必须直接显示 AI 操作后的最新网址、页面内容、滚动位置和表单状态，恢复前后 `webContents.id` 不变。
  - `WB-PANEL-004-AC12` 后台浏览器在应用运行期间不得自动销毁；仅应用退出、用户主动关闭浏览器 Tab 或删除所属会话时销毁。应用重启后按会话恢复标签顺序、URL、导航历史和缩放并按需重新创建；不承诺恢复页面 JS、内存滚动状态或未提交表单。

### 8.8 直接写回与回退

#### WB-APPLY-001 打开 AI 修改记录后的默认选中逻辑

- 系统行为：从 assistant turn 打开修改记录时，自动展开右侧面板并打开或激活对应文件 Tab，但工作区文件列表默认保持关闭；用户手动打开文件列表后默认进入“本次运行改动”，并选中当前文件。同一路径只保留一个文件 Tab。Docx 工具修改使用 Review Docx，普通文本记录使用结构化文本 diff。
- 验收：
  - `WB-APPLY-001-AC1` 成功打开修改记录后，界面立即可见当前文件面包屑；若记录存在审核内容则默认进入审核模式并展示回退入口，切到预览模式后隐藏回退入口和差异信息。
  - `WB-APPLY-001-AC2` 在同一轮多文件场景下，点击哪个修改文件入口，右侧就加载该文件记录，而不是空白态或自动跳到其他文件。
  - `WB-APPLY-001-AC3` 用户点击 assistant turn 中的本轮“修改的文件”入口后，右侧应进入修改的文件工作区，并默认加载该入口对应的本轮修改记录。

#### WB-APPLY-002 AI 修改完成后直接写回

- 系统行为：受支持 `docx`、`pptx`、`xlsx`、图片生成和普通文本写任务完成后直接写回源文件或创建目标文件，并生成修改记录。普通文本支持 `create`、`rewrite`、唯一非重叠 `edit` 和精确 `replaceAll`；任一校验失败时不产生部分写入。
- 验收：
  - `WB-APPLY-002-AC1` 修改现有 `docx` 后，源文件立即变为 AI 最终净稿，assistant turn 展示本轮“修改的文件”入口。
  - `WB-APPLY-002-AC2` 新建 `docx` 后，目标文件立即存在，assistant turn 展示本轮“修改的文件”入口。
  - `WB-APPLY-002-AC3` 创建或修改普通文本文件后，目标文件立即更新并生成修改记录；运行期间不展示修改入口，收到 `run_completed / run_failed / run_cancelled` 后 assistant turn 才展示本轮“修改的文件”，右侧可查看由真实写入前后内容计算的文本 diff。`answer_completed` 不视为 run 已结束。
  - `WB-APPLY-002-AC4` 普通文本 `edit` 的每个 `oldText` 必须唯一且互不重叠；`replaceAll` 替换一个 `oldText` 的全部非重叠精确匹配；失败时文件保持原样。
  - `WB-APPLY-002-AC5` 同一次 AI Run 对同一个 pptx 的多次编辑只生成一条修改记录；PPT Diff 固定比较本 Run 第一次接触文件时的状态和 Run 完成后的最终状态，工具调用只用于识别页面、元素和真实移动，不直接累加操作次数。
  - `WB-APPLY-002-AC6` 创建或修改 `xlsx` 后，正式路径立即包含最终净工作簿并生成一条修改记录；同一次 AI Run 对同一路径连续编辑时保持首次写入前基线，不重复生成记录。
  - `WB-APPLY-002-AC7` DOCX 写作技能使用 `docx_content_edit` 统一处理正文和 visual 节点；支持 `replace_text`、`insert_nodes`、`replace_node`、`delete_node`、`move_node`，不再提供独立媒体工具。
  - `WB-APPLY-002-AC7-1` 所有文件工具（docx / ppt / excel / pdf / text-file / image）的 `sourcePath`、`outputPath`、`path` 必须是本机绝对路径；系统不做任何路径拼接，相对路径直接返回错误，AI 需自行改为绝对路径后再调用。
  - `WB-APPLY-002-AC8` DOCX 编辑定位统一使用会话内稳定 `nodeId`；不存在 block、blockId、cellBlockId、wrapperPath 或 lineageId 协议。outline segment 的 `nodeIndex` 范围只表示当前临时顺序，重新打开或编辑后允许重新分段。
  - `WB-APPLY-002-AC9` DOCX 详细读取使用严格递归语义树，按真实顺序保留 `paragraph / run / text / tab / break / hyperlink / content_control / revision / field / table / table_row / table_cell / visual` 的归属关系；详细树中的正文只存在于叶子 `text` 节点，不重复返回 paragraph、table 或 cell 的派生文本和行列统计。
  - `WB-APPLY-002-AC10` DOCX visual 类型固定为 `image / chart / diagram / shape / embedded_object`，与普通节点统一使用 nodeId；读取结果包含可供 `read_image` 使用的本地图片路径。
  - `WB-APPLY-002-AC11` `read_image` 一次接受 1 至 10 个图片路径，将图片按顺序加入主模型上下文，不调用独立视觉模型。
  - `WB-APPLY-002-AC12` `docx_content_edit` 使用浅层节点构造和最小 patch：支持 `replace_text / insert_nodes / replace_node / delete_node / move_node`，不提供 `replace_content` 或 `replace_children`，也不要求 AI 重建完整递归树。
  - `WB-APPLY-002-AC13` `docx_format` 分别支持 text、paragraph、table、row、cell 和 section 的直接格式，另支持重置格式、命名样式 CRUD、应用命名样式和编号。`format_text` 使用最多 20 个 `{ nodeId, text? }` target，其余局部格式 operation 使用最多 20 个 `nodeIds`；同次调用共享一个 patch、拒绝重复 ID，并在全部目标预校验后原子提交。patch 类型或任一目标不匹配时整次写入失败；`update_named_style` 修改全局样式定义。
  - `WB-APPLY-002-AC14` `replace_text` 只在指定 `nodeId` 子树内替换确定原文，可跨相邻 run，但不能跨 paragraph、tab、break 或 visual；原位保留未修改 run、段落格式和视觉节点。
  - `WB-APPLY-002-AC15` visual 作为普通节点按 nodeId 删除或替换，删除时自动清理无引用媒体。表格读写坐标统一从 1 开始。失败不得推进 WorkingPackage，也不得产生部分结果。
  - `WB-APPLY-002-AC16` `docx_read_outline` 使用 `fromPercent`/`toPercent` 按根节点比例返回 segment map，`0–100` 返回全文结构，并返回 `fromPercent/toPercent/fromNodeIndex/toNodeIndex/totalRootCount`。segment 只包含 `story/fromNodeIndex/toNodeIndex/textMap`，不返回 nodeId；`textMap` 最多 360 个 Unicode 字符，由结构锚点、TF-IDF 动态关键词和 TF-IDF 质心 + MMR 原文代表句组成。所有 DOCX 使用相同分段算法，每个 story 根节点无遗漏且不重叠。`docx_read_nodes` 返回 story 递归内容树，一次最多读取 20 个 nodeId 或连续 50 个根节点。未支持 OOXML 投影为 opaque，局部写入必须原样保留；content control 是可定位容器，空容器可用 `insert_nodes inside_start/inside_end` 写入。
  - `WB-APPLY-002-AC16-2` `docx_search` 只支持 literal/regex 并搜索完整原文，不使用 DOCX embedding、向量索引或硬编码别名。每个实际出现位置为一个 match，Worker 统计全部命中但只构造和返回前 10 个；`includeContext:true` 固定返回同一 story 前后各 2 个节点预览。无效 regex，以及任一过期、未知或不可搜索的 scope nodeId，均返回 `invalid_input`。
  - `WB-APPLY-002-AC16-1` 每条工具结果独立判断大小：不超过 32,000 字符时完整进入模型上下文，超过时完整落盘并返回最多 8,000 字符的 head；截断信封只包含 `truncated/filePath/totalChars/head`，同一 dispatch 不设置批次总量限制。
  - `WB-APPLY-002-AC17` 四个 DOCX 写工具复用 Human 统一 `status/result/error` 信封。普通修改成功时 `result` 为空；创建新节点、图片、批注或回复时只在 `result.createdIds` 返回后续定位需要的稳定 ID，不返回完整节点或 `changes`。成功前仍须完成 OOXML、relationship/media 一致性与受影响区域内部回读校验；最终内容、格式和图片效果由读取工具按受影响范围确认。
  - `WB-APPLY-002-AC17-1` 同一 Run 内四个写工具共享首次接触文件时的 Source 和连续推进的 Working。Diff 比较 Source 与最终 Working：A→B→A、新增后删除不产生 Diff；body、header、footer、footnote、endnote、textbox 均生成红绿审核结果，只有 package part 变化时显示“文档级变更”摘要；Word 原生批注和修订与 NCurator Diff 独立保留。
  - `WB-APPLY-002-AC18` 所有 Human 工具的输入结构由 Zod schema 统一渲染；公共类型使用稳定命名定义并只展开一次，同时保留长度、数量、正则、数值和跨字段语义约束，不生成匿名 schema 名称。
  - `WB-APPLY-002-AC7` 生成 PNG、JPEG 或 WebP 图片后，正式路径立即包含可读取图片并生成一条修改记录；同一次 AI Run 对同一路径再次生成时自动更新并保持首次写入前基线。

#### WB-TERMINAL-001 终端执行

- 系统行为：terminal 每次 `terminal_run` 新建终端并从当前 workspace 根目录执行一条命令，命令执行完即销毁，不保留会话。要切换目录需在同一条命令内用 `cd` 链接。长命令运行超过时限后返回 `status=running` 并让出控制权，可通过 `terminal_read` 携带返回的 `readEndPosition` 增量续读，命令结束后由框架清理。`terminal_read` 必须传入 `terminalId`，每次最多返回单次上限字符数，返回的 `readEndPosition` 是本次已返回内容之后的下一读取位置；返回 `hasMoreOutput=true` 表示还有更多输出未读完，应继续用 `readEndPosition` 读取。工具不接收 `cwd`，默认起始目录是用户的工作区目录。绝对路径可以访问工作区外文件；相对路径以工作区根目录为起点。每个会话最多同时存在 5 个运行中的终端，达到上限后 `terminal_run` 返回 `terminal_session_limit_reached`，可等待命令结束，或用新终端执行终止命令（kill/pkill/taskkill）腾出位置。
- 验收：
  - `WB-TERMINAL-001-AC1` 每次 `terminal_run` 新建从 workspace 根目录开始的终端，命令结束即销毁，不保留 `cd` 后的路径。
  - `WB-TERMINAL-001-AC2` 长命令固定让出控制权但不被误判为失败；terminal_read 只返回游标后的增量输出和客观状态，单次返回不超过字符上限，`hasMoreOutput=true` 时可用返回的 `readEndPosition` 连续读取直到 `hasMoreOutput=false`。
  - `WB-TERMINAL-001-AC3` 删除会话、取消所属 run 或退出应用不会遗留进程。
  - `WB-TERMINAL-001-AC4` terminal_run 继续遵守命令审批与其他安全策略；terminal_read 不能访问其他会话或 workspace 的终端。
  - `WB-TERMINAL-001-AC5` shell 后台符号、nohup 或 Start-Process 不能绕过终端管理。
  - `WB-TERMINAL-001-AC6` 达到每会话并发终端上限（5 个）时 terminal_run 返回 `terminal_session_limit_reached` 并给出提示；终止类命令（kill/pkill/taskkill）不受该上限限制。
  - `WB-TERMINAL-001-AC7` AI 涉及数据计算、对账、统计、求和、对比等数值处理时，必须通过 terminal 执行真实计算（如 python / python3 / node 脚本、awk、join、paste 等命令），计算结果由终端命令产出；不得仅靠模型内部推算后直接写出结论文件，终端产出的变化按 terminal 修改记录处理。

#### WB-APPLY-003 回退本次 AI 修改

- 系统行为：受控文件工具写回工作区内文件时立即保存本次 run 的修改记录、有效变更校验和所需快照；terminal 每条命令执行前保存工作区基线，命令最终结束或失败后计算该命令窗口内的新增、修改、删除和重命名。终端记录归入发起命令的 run。不同 terminal 命令并发重叠时允许同一变化在多个 run 中重复记录；系统不加锁、不推断唯一归属。AI 可以读写工作区外绝对路径，但这些变更不进入当前修改记录与回退能力。AI 或用户在没有受控工具写回和 terminal 命令窗口时产生的外部变化不归入任何 AI Run。基线内容按 SHA-256 保存；文本 Diff 根据不可变的修改前后内容生成并缓存。回退使用修改前对象，不反向计算 Diff。
- 验收：
  - `WB-APPLY-003-AC1` 未发生后续修改时，回退恢复写回前 checkpoint，记录状态变为 `reverted`。
  - `WB-APPLY-003-AC2` 新建文件回退时删除 AI 新建目标文件。
  - `WB-APPLY-003-AC3` 回退成功后，右侧修改的文件工作区应刷新记录状态；普通文本历史 diff 继续保留并标记“已回退”或“已删除”，避免丢失本次修改记录。
  - `WB-APPLY-003-AC4` 终端通过 Shell、Python、Node 或其他程序造成的文件变化均由 Run 结束扫描捕获；终端修改的文本可生成普通行级 Diff，终端直接修改的 Docx 等二进制文件只提供修改前/修改后版本，不伪造语义审阅标记。
  - `WB-APPLY-003-AC5` Docx 工具修改保存 before 和 Review Docx；Review Docx 继续由现有 Docx Renderer 渲染并保留段落、表格、图片、字体和页面结构。
  - `WB-APPLY-003-AC6` PPT 修改记录使用 Diff Manifest v4，在审核模式提供固定的修改前后页面快照；旧 v3 记录明确提示格式过期，正式 PPT 不受影响。Excel 专用工具修改 `xlsx` 时在审核模式提供单元格边框标记，并可切换到预览模式。终端产生的二进制文件变化只提供修改前/修改后版本，不显示模式切换；终端产生的 UTF-8 文本变化按普通文本规则处理。
  - `WB-APPLY-003-AC7` 图片生成记录直接预览最终图片并提供回退，不显示不存在的图片 Diff；更新图片回退后恢复首次生成前的文件，新建图片回退后删除目标文件。
  - `WB-APPLY-003-AC8` Docx Review 只展示本次 Run 初始文档到最终净稿的净变化；同一原始节点连续修改只显示一次原始红色版本和一次最终绿色版本，中间稿不得出现，改回原内容不产生修改记录；本轮新增节点只显示最终仍存在的绿色版本，新增后删除不产生净变化。
  - `WB-APPLY-003-AC9` 专用写工具的成功记录以工具原子写入结果、checkpoint 和前后 checksum 为权威依据；通用扫描匹配到同一路径时可补充快照，未匹配时不得否定已被校验的真实写入。

#### WB-APPLY-004 后续修改后的强制回退

- 系统行为：若回退时检测到当前文件与 AI 写回后的 checksum 不一致，先提示用户该文件已被后续修改，继续回退会丢失这些内容；用户确认后仍允许强制回退。
- 验收：
  - `WB-APPLY-004-AC1` 点击任何可回退记录时先展示统一确认框“回退这次修改？”，说明文件将恢复到这次修改发生前的状态；用户确认后才发起回退。
  - `WB-APPLY-004-AC2` 检测到后续修改时，在统一确认之后继续展示“仍然回退这次修改？”风险确认；用户确认强制回退后，系统恢复 checkpoint 或删除新建文件。
  - `WB-APPLY-004-AC3` 强制回退完成后，右侧修改的文件工作区应刷新为最新记录状态，并让用户能确认回退已经生效。

#### WB-APPLY-005 同一轮多个修改记录入口保留

- 系统行为：同一轮任务若实际修改多个文件，assistant turn 保留本轮全部修改入口；点击入口后打开或切换到对应文件 Tab。每个入口直接展示该文件本次真实修改与删除数量，无需点击即可见，切换会话后依然保持。文件入口超过 3 个时列表默认折叠，只展示前 3 个，底部提供“显示剩余 N 个文件”展开入口，展开后该入口变为“收起文件”；头部总数始终展示完整数量。Assistant 最终回答只在修改文件区域展示文件入口。
- 验收：
  - `WB-APPLY-005-AC1` 同一轮任务生成的多个修改记录都会出现在同一 assistant turn 的修改的文件列表中。
  - `WB-APPLY-005-AC2` 点击不同修改记录入口时，右侧会加载对应修改记录；有 diff 预览的记录展示对应预览稿，而不是按源文件跳到最新轮次。
  - `WB-APPLY-005-AC3` 同一轮多文件修改的全部入口保留在 assistant turn 列表中，不因切换当前文件而丢失其他文件的检查或回退入口。
  - `WB-APPLY-005-AC4` 修改记录入口未点击时即展示真实非零的修改/删除数量；切换会话再切回后不点击仍保持真实数量，不重置为 0。
  - `WB-APPLY-005-AC5` 文件入口超过 3 个时默认只展示前 3 个，列表底部展示“显示剩余 N 个文件”（N 为剩余数量）；点击后展示全部入口，底部入口变为“收起文件”，再次点击恢复折叠；头部文件总数不受折叠影响。

### 8.9 PPT 创建、编辑与审核模式

#### WB-PPT-001 AI 创建和编辑 PPT

- 系统行为：AI 通过 `ppt-read` 和 `ppt-write` 读取、创建和编辑 pptx。`ppt_edit` 一次调用只执行一个 operation（顶层 `type` 判别联合）；路径不存在时创建，存在时编辑。`insert_slide` / `replace_slide` 使用同一套页面元素规格（`background?`、`notes?`、`defaults?`、`elements[]`）。`replace_slide` 保留原 `slideId`，清空后按规格重写。成功后原子写入真实文件，只返回 `sourcePath`、`slideCount` 和继续写所需的 `slideId`、`createdElementIds`。任务结束时只生成 run 级差异记录，不再次提交文件。
- 验收：
  - `WB-PPT-001-AC1` AI 可自行新建 pptx，不依赖用户点击新建入口。
  - `WB-PPT-001-AC2` 新建演示文稿或插入页面时，单次调用只允许一张页面的元素规格，不接受页面数组或 HTML。
  - `WB-PPT-001-AC3` 文本、形状、线条、图片、表格、图表和公式按支持类型转换，不把整页默认导出为截图。
  - `WB-PPT-001-AC4` AI 可使用真实 slideId 和 elementId 继续编辑已有页面和元素。
  - `WB-PPT-001-AC5` 公式由 LaTeX 渲染为 SVG；公式整体可移动和缩放，内部字符为只读内容。
  - `WB-PPT-001-AC6` `ppt_read_outline` 支持 percent 和 slide_index；`ppt_read_slides` 支持 slide_index 和 slide_ids，默认 `detail=full` 返回元素与可交给 `read_image` 的 `slideImagePath`，`detail=images` 仅返回 `slideId` / 页码 / `slideImagePath`；`ppt_search` 使用可选 `scope.slideIds`。
  - `WB-PPT-001-AC7` `ppt_edit` 成功后只返回继续写所需锚点：`sourcePath`、`slideCount`、相关 `slideId`、`createdElementIds`（insert / replace / add_element / duplicate）；不返回变更清单或整页 readback。
  - `WB-PPT-001-AC8` 元素编辑支持文字、位置、样式、图层、复制、删除、新增、图片、表格、图表和公式更新。
  - `WB-PPT-001-AC9` 一次 `ppt_edit` 失败时，文件和活动 session 都保持调用前状态。
  - `WB-PPT-001-AC10` `ppt_edit` 返回成功时，其他程序已经可以读取最终 pptx。
  - `WB-PPT-001-AC11` 不提供 `create_presentation`；`insert_slide` 使用可选 `location:{slideId,position}`，不传时追加到末尾。
  - `WB-PPT-001-AC12` `move_slide` 必须提供 `slideId` 和 `location`；`duplicate_slide` 必须提供 `slideId`，可选 `location`，不传时追加到末尾。移动不能锚定自身，复制可以锚定源页自身；旧 `position + anchorSlideId`、`html`、`actions[]` 参数无效，最终至少保留一页。
  - `WB-PPT-001-AC13` `replace_slide` 必须提供已有 `slideId` 与元素规格；保留该页部件身份，Diff 将该页记为 modified，元素按旧全部 deleted、新全部 added 计数。

#### WB-PPT-002 PPT 单页左右审核模式

- 验收：
  - `WB-PPT-002-AC1` 主区域按左侧修改前、右侧修改后一次各显示一页。
  - `WB-PPT-002-AC2` 缩略图支持只看变化页和查看全部页两种图标模式，默认只看变化页。
  - `WB-PPT-002-AC3` 新增、修改、移动页使用绿色标记，整页删除使用红色标记，不显示“修改几页”等文字差异说明；已有页面只删除内部元素时，该页仍按修改显示绿色。

### 8.10 Excel 读取、编辑与审核模式

#### WB-EXCEL-001 AI 读取和编辑 Excel

- 系统行为：AI 通过 `excel-read` 的 `excel_read` 读取工作簿地图、A1 范围的值与公式、样式，或按格子值/公式搜索；通过 `excel-write` 的 `excel_edit` 一次一个 type 创建或编辑工作表、范围、样式和结构。路径只出现在入参。路径不存在时第一次 `add_sheet` 创建工作簿（不自动生成 Sheet1），存在时编辑。读取支持 `xlsx`、`xlsm`、`xltx`、`xltm`，写入只支持 `xlsx`。Excel 文件不进入本地知识库内容索引，只索引文件名、文档标题与工作表名等元数据（不含单元格内容），具体单元格数据仍由 Excel 专用工具按工作区路径处理。产品侧 Diff / 修改记录 / 回退仍由系统维护，不投影给模型。
- 验收：
  - `WB-EXCEL-001-AC1` `excel_read` 按 type 工作：`workbook` 返回各表 `name/range/rowCount/columnCount`（空表 `range` 为 null）；`range` 返回网格，公式格为 `{ formula, value? }`，字面量为原值；`style` 只返回有格式的 `bold/fontColor/fillColor/numberFormat`，否则为 `null`；`search` 只搜单元格值和公式，返回 `{ totalMatchCount, returnedMatchCount, matches: [{ sheetName, address, value? 或 formula }] }`。
  - `WB-EXCEL-001-AC2` `excel_edit` 一次一个 type：`add_sheet` / `delete_sheet` / `rename_sheet` / `set_range` / `clear_range` / `merge_cells` / `unmerge_cells` / 插删行列 / `set_style` / `set_column_width` / `set_row_height` / `auto_fit`。`set_range` 的 `range` 必须与 `values` 行列一致的 A1 矩形（如 `A1:C3`）；单格写入可用 `A1` 或 `A1:A1`；不传 style 则保留原样式。成功返回 `{}`。
  - `WB-EXCEL-001-AC3` 单次 `excel_edit` 失败时不产生部分写入；文件在连续编辑之间被外部修改时拒绝覆盖并提示冲突；无实际变化时不生成修改记录。
  - `WB-EXCEL-001-AC4` `xlsm`、`xltx`、`xltm` 可以读取但不能写回；拒绝写入时源文件保持不变，并明确说明是为了避免丢失宏或模板信息。
  - `WB-EXCEL-001-AC5` Excel 创建或编辑成功后，正式文件中的值与公式可被其他程序立即读取，正式文件不包含审核模式使用的红绿边框。
  - `WB-EXCEL-001-AC6` 新建工作簿只包含 `add_sheet` 显式创建的 Sheet，不自动生成 `Sheet1`；最终至少保留一个 Sheet，删除最后一个 Sheet 必须失败。
  - `WB-EXCEL-001-AC7` 新增已存在的 Sheet、删除不存在的 Sheet、重命名到已存在名称都必须失败，且不写入部分结果。

#### WB-EXCEL-002 Excel 单网格审核模式

- 系统行为：用户打开普通 Excel 文件或 `xlsx` 修改记录后，前端使用成熟的 Univer 工作簿组件分别预览正式 XLSX 和 Diff XLSX，不自行解析 OOXML 生成 HTML 表格。Excel 预览是只读预览：不允许编辑单元格内容，但允许切换工作表、滚动、缩放和拖动列宽查看内容。Diff 只展示本次 Run 首个 baseline 到最终工作簿的净变化；操作记录只用于识别 Sheet 和行的结构身份，不直接累加为最终差异。新增和修改单元格使用绿色中等粗细边框，删除或清空的单元格在 Diff XLSX 中保留修改前值并使用红色中等粗细边框。用户不使用 PPT 的修改前/修改后左右画面对比。
- 验收：
  - `WB-EXCEL-002-AC1` 预览模式展示正式净工作簿，审核模式展示基于首次写入前基线生成的差异工作簿；两者均为只读预览，且均可切换工作表、滚动、缩放和拖动列宽。
  - `WB-EXCEL-002-AC2` 新增和修改单元格显示绿色中等粗细边框，删除或清空的单元格显示红色中等粗细边框并保留修改前值；未变化单元格不增加差异边框，正式工作簿也不带差异边框。
  - `WB-EXCEL-002-AC3` 同一 AI Run 对同一路径连续编辑后只保留一条有效修改记录，差异始终相对该 Run 首次写入前基线计算。
  - `WB-EXCEL-002-AC4` 回退已有 `xlsx` 时恢复写入前原始 bytes；回退新建 `xlsx` 时删除目标文件，修改记录状态同步更新。
  - `WB-EXCEL-002-AC5` Diff XLSX 中新增 Sheet 的标签为绿色，删除 Sheet 以修改前完整内容恢复到 Diff XLSX 的原位置并将标签标为红色；恢复内容包括单元格值、样式、行高、列宽和合并单元格；正式 XLSX 不带这些差异标记。
  - `WB-EXCEL-002-AC6` 暂不定义移动 Sheet 位置的 Excel diff action；如果未来新增 `move_sheet`，需要单独定义差异语义。
  - `WB-EXCEL-002-AC7` 插入或删除行时按逻辑行对齐生成联合预览：新增行只标绿最终新增内容，删除行在原逻辑位置保留旧内容并标红；其他仅因插入或删除而改变地址的原有行不得产生红绿边框，预览末尾不得生成重复行。
  - `WB-EXCEL-002-AC8` 同一 Run 中单元格、行或 Sheet 被多次修改时只保留最终净变化；改回 baseline、插入后删除、新增 Sheet 后删除均不产生红绿标记或变更计数；原始 Sheet 多次重命名只保留最终名称和一次重命名状态，不复制整张 Sheet 作为删除加新增。

### 8.12 应用内文本编辑

#### WB-EDIT-001 Markdown 与普通文本应用内即时渲染编辑

- 系统行为：右侧面板打开真实本地 `.md`/`.markdown` 文件时，使用即时渲染（IR）编辑方式——文件内容渲染为排版预览，点击任意位置直接编辑文字；光标进入链接、加粗、行内代码等 markdown 语法元素时，该元素局部露出 markdown 源可编辑。标题元素前不展示 H1/H2 等标题级别标签（Vditor 默认 `::before` 标签）与 `#`/`##` 等标题源标记，标题不加额外装饰（无下划线），保持沉浸式排版；编辑区始终撑满右侧面板，不出现右侧灰色残留。编辑器不展示任何操作按钮、工具栏或交互栏，用户打开即可直接编辑。打开 `.txt` 及其他严格 UTF-8 普通文本（如 `.log`、`.json`、代码、配置文件、无扩展名文本）时，使用与纯文本预览一致的纯文本编辑框直接编辑；纯文本内容（编辑态与只读预览态）每行前显示行号，行号随内容同步滚动。AI 修改记录的审核/预览态、预览弹窗以及 PDF/DOCX/PPTX/XLSX/图片等其他格式保持只读。
- 保存：不做显式保存按钮与"未保存"提示；每次内容变更后防抖（约 400ms）自动原子写入磁盘（`write-text-file`，临时文件 + rename），并对内容做 UTF-8 合法性校验；纯文本保存时保留原文件的换行符风格（CRLF/LF）与 UTF-8 BOM。自动保存为纯覆盖，不做冲突提示。
- 外部修改：磁盘内容与编辑器最后成功写入的内容一致时不响应；空闲（无未保存改动）时检测到外部修改自动重载最新磁盘内容；编辑中存在未保存改动时不打断编辑，下一次自动保存覆盖外部内容。
- 范围边界：应用内编辑不生成 AI 修改记录、不进入回退体系；不限定只能编辑已绑定工作区内的文件，任意本地真实文件均可编辑。
- 验收：
  - `WB-EDIT-001-AC1` 打开真实 `.md` 文件后直接进入即时渲染编辑态，无工具栏/操作按钮；点击任意位置光标落下，输入内容实时渲染并反映在编辑区。
  - `WB-EDIT-001-AC2` 光标进入链接等 markdown 语法元素时，该元素局部露出 markdown 源可编辑；离开后恢复渲染态。
  - `WB-EDIT-001-AC3` 打开 `.txt`、`.json`、代码等严格 UTF-8 文本后直接进入纯文本编辑框，输入与保存内容一致，不出现 markdown 化改写。
  - `WB-EDIT-001-AC4` 编辑后无需点击保存，约 400ms 内自动落盘，磁盘内容更新为编辑结果；界面不展示保存按钮或"未保存"标记。
  - `WB-EDIT-001-AC5` 空闲时外部保存文件自动重载最新内容；编辑中存在未保存改动时外部保存被下次自动保存覆盖，不弹出冲突提示。
  - `WB-EDIT-001-AC6` 纯文本文件保存后保留原换行符风格（CRLF/LF）与 UTF-8 BOM。
  - `WB-EDIT-001-AC7` AI 修改记录审核/预览态与预览弹窗中的 Markdown 仍为只读渲染，不进入编辑态。
  - `WB-EDIT-001-AC8` 应用内编辑保存不产生 AI 修改记录。
  - `WB-EDIT-001-AC9` 打开 `.md` 后编辑区撑满右侧面板（无右侧灰色残留）；标题前不显示 H1/H2 等标题级别标签与 `#`/`##` 等标题源标记，标题无下划线等额外装饰；拉宽窗口后页面不白屏、编辑态保持。
  - `WB-EDIT-001-AC10` 纯文本内容（编辑态与只读预览态）每行前显示从 1 开始递增的行号，行号随内容滚动同步对齐。
