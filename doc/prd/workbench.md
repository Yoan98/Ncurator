# Workbench PRD

## 1. 产品目标

- 用户通过对话让 AI 完成搜索、分析、回答、整理和文档处理等任务。
- 用户可以把本地资料作为上下文，让 AI 优先据此完成检索、分析、回答和受支持文件处理。
- 让 workbench 成为“发起任务、查看过程、处理中断、查看修改的文件并按需回退、继续执行”的主工作台。
- workbench 应把任务推进到完成；无法完成时明确说明原因、限制或所需条件。

## 2. 产品原则

- 本地资料是重要上下文，但不是唯一能力边界；未显式选择资料时，AI 仍可完成通用任务。
- workbench 的发送前提是已有伙伴且输入非空。
- 未显式插入 `@` 时，知识库默认覆盖设置页全部已索引文件地址与全局网页资料；`@` 只用于在此基础上再收窄。工作地址列表按设置页现表进入本轮对话上下文，不作为 Composer 选择器。
- 当用户插入 `@` 参考资料时，AI 应优先基于这些范围完成任务，而不是忽略用户给出的约束。
- workbench 不只展示问答过程，还要交付可消费结果，或给出明确失败信息。
- 用户可见能力边界必须明确可见，尤其是哪些资料可检索、哪些格式可直接写回并回退、哪些情况只能查看或分析。

## 3. 范围

- 包含伙伴管理（创建、编辑、切换、删除、置顶、空态）。
- 包含 composer 输入、发送与取消；Composer 只有智能模式。
- 包含智能模式下 AI 推进偏好的选择与本机恢复。
- 包含附件拖放和智能模式下执行权限的选择与伙伴级恢复。
- 包含 `@` 参考资料 token 的插入与维护。
- 包含按天时间轴跳转，以及清空消息记录。
- 包含 AI 运行中的审批与上下文压缩过程提示。
- 包含右侧内容面板中的文档查看与修改的文件回退入口。
- 包含基于本地资料和网页资料的上下文使用。
- 包含定时任务的入口、独立主区视图、任务配置、启用开关与到点触发。
- 包含 AI 写回或回退已打开的 WPS `.docx` / `.pptx` / `.xlsx` 时自动刷新（默认功能，无设置项）。

## 4. 当前能力边界

- 本地知识库支持 PDF、DOC／DOCX、Markdown、TXT 及 Excel 元数据索引；不索引 Excel 单元格内容。空文本仍可按文件名找到，DOC 只读。
- 受控写回与回退支持 DOCX、PPTX、XLSX、PNG／JPEG／WebP 图片及 UTF-8 普通文本；其他格式可由 AI 尝试处理，不提供同等保证。完整边界见 `WB-CORE-003`、`WB-EXCEL-001`。
- 知识库功能要求本地向量模型可用；模型缺失或出错时返回明确错误，不隐式下载、不终止普通聊天、不扩大所选范围。更新索引期间暂停知识库查询，检查更新不拦截；空库、空范围与无命中返回空结果。
- 附件按真实路径供 AI 使用；粘贴附件保存副本。具体交互与格式限制见 `WB-COMPOSER-010`。
- 应用内手动文本编辑不生成 AI 修改记录，见 `WB-EDIT-001`；WPS 自动刷新见 `WB-WPS-001`；终端修改不提供馆长回退，见 `WB-TERMINAL-001`。

## 5. 术语

- 伙伴：一条一直聊下去的对话记录。侧栏只有伙伴列表。
- 参考资料：通过 `@` 插入的目录、文件或网页资料 token。
- 工作地址：设置页添加的本地目录根路径。
- 智能模式：Composer 唯一发送路径；启动 AI 运行，允许产生阻塞、审批、文件直接写回与回退入口。
- 受支持文件：当前已具备直接写回与回退能力的文件类型；当前包括 `docx`、`pptx`、`xlsx`、生成的 PNG、JPEG、WebP 图片（`.png` / `.jpg` / `.jpeg` / `.webp`）和 UTF-8 普通文本文件。
- 目标文件：用户要求新建受支持文件时，AI 写工具直接创建的文件路径。
- 直接写回：AI 写工具将最终 docx、pptx、xlsx、生成图片或普通文本结果原子写入源文件或创建目标文件的流程；工具成功即代表正式路径已可读取，run 收尾不再提交文件。
- 修改记录：一次 AI run 中由受控文件工具直接写回产生的创建、更新、删除或重命名记录；提供打开文件、适用格式的审核模式与回退本次修改入口。终端造成的磁盘变化不记修改记录。
- 回退本次修改：恢复本次修改前的原始文件；新建文件回退时删除目标文件，若文件在 AI 写回后又被修改，需提示用户确认会丢失后续修改。
- 清空消息记录：删除该伙伴全部对话消息记录及对应任务过程及旧运行缓存，界面回到空对话；伙伴保留。确认框默认不勾选删除文件修改历史，保留回退记录、备份和审核材料；主动勾选后同步删除。
- 内部引用链接：assistant 回答中使用标准 Markdown 语法 `[显示名](绝对本地路径或 https URL)` 引用的本地文件或网页链接；点击可在右侧工作台预览文件或打开内置浏览器。本地文件做可达性检查，不可访问时展示弱化状态并禁止点击；`http(s)` 网页链接不做可达性检查，默认可点。详细校验与交互见 `WB-COMPOSER-003-AC8`。
- AI 推进偏好：智能模式下用户对资料使用边界的附加约束，界面选项包括“默认”“本地资料·宽松”“本地资料·严谨”。当前“本地资料”范围包含全部已索引文件地址、全局网页资料、工作地址内文件和显式参考资料。宽松模式优先使用这些资料，资料不足时允许补充模型知识或外部网页；严谨模式只能把这些资料作为事实依据，资料不足时必须明确说明，不得把模型知识、外部搜索或浏览器结果伪装成资料内事实。
- 执行权限：智能模式下对本次运行是否等待工具审批的选择，独立于 AI 推进偏好。选项为“审核”和“完全访问”。

## 6. 需求明细

### 6.1 核心能力与约束

#### WB-CORE-001 本地资料是可选上下文，不是唯一前提

- 系统行为：workbench 发送前要求已有伙伴；在此基础上，即使用户未显式选择任何本地参考资料，AI 仍可执行不依赖本地文档的通用任务；当存在本地参考资料时，可将其作为任务上下文使用。未创建伙伴时 Composer 为空态，不能发送。
- 验收：
  - `WB-CORE-001-AC1` 用户已创建并选中伙伴但未选择任何本地参考资料时，智能模式仍可正常发起不依赖本地文档的任务。
  - `WB-CORE-001-AC2` 系统不会把“没有显式本地参考资料”误表现为“workbench 不可用”；未创建伙伴时才表现为 Composer 空态。

#### WB-CORE-002 用户显式选择的参考资料或默认知识范围必须影响执行

- 系统行为：当用户插入 `@` 参考资料后，后续检索、分析和执行应优先基于这些显式范围收敛；当用户未显式选择参考资料时，知识库默认覆盖设置页全部已索引文件地址与全局网页资料。
- 验收：
  - `WB-CORE-002-AC2` 智能模式下，系统不会忽略用户已经给出的 `@` 参考资料或默认知识范围；已选资料作为优先缩圈候选，但不自动变成唯一可搜索范围。

#### WB-CORE-003 当前受支持文件的直接写回能力边界必须明确

- 系统行为：workbench 明确区分“可直接写回并支持回退的受支持文件”和“可由 AI 自行尝试处理但不提供同等保证能力的其他任务”；当前受支持文件类型包括 `docx`、`pptx`、`xlsx`、生成的 `png`、`jpg`、`jpeg`、`webp` 图片和 UTF-8 普通文本文件。`xlsm`、`xltx`、`xltm` 只读，不属于可直接写回范围。
- 验收：
  - `WB-CORE-003-AC1` 当前支持直接写回与回退的受支持文件类型列表明确可见，包括 `docx`、`pptx`、`xlsx`、PNG/JPEG/WebP 图片（`.png` / `.jpg` / `.jpeg` / `.webp`）的修改和新建，以及 Markdown、TXT、配置文件和代码等 UTF-8 普通文本文件。
  - `WB-CORE-003-AC2` 不在当前受支持文件类型列表中的资料不会被伪装成可进入同一直接写回与回退流程的编辑或创建目标。

#### WB-CORE-004 资料优先级受 AI 推进偏好约束

- 系统行为：默认或宽松偏好下，当用户已插入参考资料或存在已索引文件地址 / 全局网页时，系统优先基于这些资料完成任务；未显式 `@` 时，默认使用全部已索引文件地址与全局网页作为知识范围。资料不足时，默认或宽松偏好允许补充模型通用知识或外部网页信息，但不能忽略或违背用户已给定的资料。严谨偏好下，只允许把已索引文件地址、全局网页与显式参考资料作为事实依据；资料不足时应明确说明缺口，不得使用模型知识、后台网页搜索与抓取 或 内置浏览器操作 的外部内容补足事实。
- 验收：
  - `WB-CORE-004-AC1` 用户已有默认知识范围或显式参考资料时，问答或受支持文件结果不会脱离这些资料另起一套无关内容。
  - `WB-CORE-004-AC2` 默认或宽松偏好下，资料不足以覆盖通用部分时，系统仍可补充模型通用知识或外部网页信息，并明确区分资料内事实与补充信息。
  - `WB-CORE-004-AC3` 严谨偏好下，资料不足时系统明确说明资料缺口，不使用默认知识范围和显式参考资料之外的信息补足事实。

#### WB-CORE-005 任务过程中的中间结果必须服务于后续结果

- 系统行为：当任务执行过程中产生搜索结果、文件读取结果、执行结果或其他中间信息后，后续 assistant 回答、分析结论和文件产物应实际使用这些信息继续推进用户诉求；若当前中间结果不足以支撑继续完成，系统应明确说明限制，而不是伪造后续内容。
- 验收：
  - `WB-CORE-005-AC1` 任务过程中产生的中间结果，会体现在后续用户可见回答、结论或文件产物中，而不是只表现为“执行过某些步骤”。
  - `WB-CORE-005-AC2` 当前中间结果不足或执行失败时，assistant 会明确说明为什么无法继续完成、缺少什么条件或当前能确认到什么范围，而不是编造结论或文档内容。
  - `WB-CORE-005-AC3` 用户可见输出优先围绕用户原始诉求组织；若引用中间结果，应使用用户能理解的表达，而不是暴露内部工具或过程标签。

#### WB-CORE-006 用户诉求应被推进到完成或明确失败

- 系统行为：用户已提供足够上下文且当前能力允许时，持续推进任务直到交付可消费结果，避免无必要的重复操作。无法完成时明确说明失败原因、限制或所需条件，不能停在搜索结果、工具调用或过程提示等中间态。
- 验收：
  - `WB-CORE-006-AC1` 用户诉求可完成时，系统会把任务推进到可消费结果、明确产物或可确认的下一步动作，而不是停留在中间态。
  - `WB-CORE-006-AC2` 用户诉求当前无法完成时，系统会明确说明失败原因、限制信息或下一步所需条件，而不是无声中断或只留下过程信息。
  - `WB-CORE-006-AC3` 最终收口默认直接围绕用户显式提出的问题组织；若同时需要说明产物、依据或限制，也应使用用户可理解的语言表达，而不是依赖内部标识、tool 名或固定章节标题。
  - `WB-CORE-006-AC4` 简单任务不强制创建 plan；复杂或多依赖任务才维护 plan，不为汇报进度单独更新。目标满足且必要检查通过后可直接交付。

#### WB-CORE-007 网页信息可用于任务推进

- 系统行为：默认或宽松偏好允许 AI 通过后台 后台网页搜索与抓取 搜索网页、读取指定网页正文，并在需要登录或人工操作时使用 内置浏览器操作 打开右侧内置浏览器继续任务；严谨偏好不得把外部网页作为资料内事实依据。后台网页搜索与抓取 是 Human 图后台工具，结果只回模型与过程层，不得自动展开右侧列表，也不得替代 内置浏览器操作 的可见浏览器交互。
- 验收：
  - `WB-CORE-007-AC1` 用户要求查找公开网页信息时，AI 可搜索并读取搜索结果或用户给出的 URL，再用所得内容完成回答或产物。
  - `WB-CORE-007-AC2` 网页搜索、读取或浏览失败时，系统明确说明失败边界，不伪造网页内容。
  - `WB-CORE-007-AC3` 严谨偏好下，外部网页能力不会绕过资料范围限制。
  - `WB-CORE-007-AC4` AI 调用 后台网页搜索与抓取 时，Workbench 不得因工具结果自动打开右侧搜索列表；过程层可展示“搜索网页 / 抓取网页”等状态，但右侧面板保持原状，除非用户手动打开资源或 AI 触发 内置浏览器操作。
  - `WB-CORE-007-AC5` 后台网页搜索与抓取 抓取时用户不得看到带窗框的独立浏览器窗口，也不得让网页内容遮挡主界面。
  - `WB-CORE-007-AC6` 后台网页搜索与抓取 读取网页应返回可读正文或明确失败，不得无限挂起。

#### WB-CORE-008 Workbench 窗口层与业务内容分层

- 系统行为：Windows Workbench 的原生窗口控制层独立位于业务内容上方；无伙伴空态拖动区、侧栏入口和业务内容不互相遮挡。非 Windows 平台保留页面顶部拖动区。
- 验收：
  - `WB-CORE-008-AC1` 无伙伴空态仍提供可命中的 44px 拖动区。
  - `WB-CORE-008-AC2` Windows 原生控制层为独立 36px 区域，业务内容从其下方开始。
  - `WB-CORE-008-AC3` Windows 侧栏切换按钮保持 `no-drag` 且与原生控制按钮对齐。

### 6.2 伙伴管理

侧栏只有伙伴列表与「创建伙伴」；伙伴创建弹窗提交即落库。

#### WB-SESSION-001 无伙伴时展示空态，创建即落库

- 系统行为：页面初始化时拉取伙伴列表。列表为空或当前未选中伙伴时，主区展示空态文案，Composer 不出现可输入草稿；侧栏提供「创建伙伴」，列表区为空时不展示空态文案。创建弹窗填写名称，并选择 6 种外形 × 12 种颜色的头像（圆、圆角方、横向胶囊、圆角六边形、云、水滴；2D 圆润色块，眼睛可正视或上下左右张望，转身时眼睛绕到背面再从另一侧进入）。创建/编辑弹窗中的形象保持自然动画。提交成功后立即保存并选中该伙伴。侧栏伙伴项展示头像、名称和相对时间（刚刚 / N小时 / N天）；无任务运行时头像保持静止初始姿态，仅当该伙伴存在 running / waiting_human / waiting_approval 任务时才播放跳跃、转眼与张望。有用户消息时副文案为最新用户语句预览，没有则展示「做点啥呢？」。
- 验收：
  - `WB-SESSION-001-AC1` 首次进入且没有伙伴时，侧栏列表区不展示空态文案，主区为空态并保留 44px 拖动区，而不是不可操作空白页；Composer 不出现可发送输入框。
  - `WB-SESSION-001-AC4` 创建弹窗提交成功后，新伙伴立即出现在侧栏并成为当前选中项；名称与头像外形 / 颜色按提交值保存。
  - `WB-SESSION-001-AC5` 伙伴列表项展示头像、名称与相对时间；无任务运行时头像静止，任务运行中才播放动画；发送用户消息后副文案更新为该语句预览，尚无用户消息时展示「做点啥呢？」。
  - `WB-SESSION-001-AC6` 创建伙伴时名称不能为空，且不得与其他伙伴重名；去除首尾空白后按名称完全相同判断重名。重名时保留弹窗并提示用户改名，任何写入入口均不得创建同名伙伴。

#### WB-SESSION-002 切换伙伴时恢复目标伙伴状态并隔离上一伙伴运行态

- 系统行为：切换伙伴后，主区原子加载目标伙伴的消息、运行状态和界面快照。加载完成前保留原画面并展示切换态，不先闪成空白。完成后恢复目标伙伴自己的输入草稿、`@` 范围、附件、AI 推进偏好、执行权限、模型、右侧标签和面板展开状态。上一伙伴的运行态和 UI 状态不得泄漏到目标伙伴，但目标伙伴自身的 active run 与 pending approval 必须可继续操作。
- 验收：
  - `WB-SESSION-002-AC1` 点击其他伙伴后，消息区展示目标伙伴的历史消息。
  - `WB-SESSION-002-AC2` 切换加载完成后恢复目标伙伴自己的输入和右侧面板，不保留上一伙伴的修改面板或运行中阻塞提示；加载过程中主消息区不先闪成空白态。
  - `WB-SESSION-002-AC3` 目标伙伴存在正在运行或最近完成的 AI run 时，切换回来后能看到已持久化的过程流、当前 partial answer 或最终回答；若切走时仍处于 AI 思考等待（「让俺想想」），切回后该提示仍在，不得因整表重建而消失。正在运行的 run 可继续停止。
  - `WB-SESSION-002-AC4` 目标伙伴存在等待审批的 AI run 时，切换回来后审批卡片仍可继续提交。
  - `WB-SESSION-002-AC5` 伙伴列表中存在 `running` 或 `waiting_approval` run 的伙伴显示“任务运行中”标记，且该伙伴头像播放跳跃、转眼与张望；运行完成、失败或取消后标记与头像动画一起消失，且不会错误显示到其他伙伴。

#### WB-SESSION-003 标题就是伙伴名称，不因消息改名

### 6.3 Composer 输入与发送

Composer 使用 18px 圆角、15px 正文和 24px 行高；工具栏采用 12px 字号、28px 控件高度及紧凑间距。发送/停止按钮为 28px 圆形、12px 图标，主动作深灰底白色图形，禁用浅灰底弱化图形。

正文按输入顺序保留普通文字、`@` 引用和文档选区片段；发送、复制和重新编辑保持该顺序与引用关联。选区交互见 `WB-DOCUMENT-REFERENCE-001`。底部工具栏左侧放附件、AI 推进偏好和执行权限，右侧放上下文用量、模型和发送。

#### WB-COMPOSER-009 消息流布局

#### WB-COMPOSER-006 AI 运行取消

- 系统行为：智能模式在普通任务运行时，Composer 右侧只有一个主按钮：草稿没有可发送内容时显示停止；有可发送内容时显示发送，提交后按 `WB-COMPOSER-017` 追加到当前 run 的消息队列，草稿清空后按钮恢复为停止。点击停止后 UI 保持占用当前 run，直到系统确认取消、失败或完成；清理期间该按钮为转圈态并禁用，提示「正在停止本次运行」。若当前 run 正在等待提问或审批，停止也必须释放对应等待、移除交互卡并结束本次 run；Activity 不得继续显示「等待用户处理」。取消是独立终态，不生成失败气泡，也不在 assistant turn 中追加或保留「已取消」正文；取消前已经产生的回答片段、过程记录和文件修改入口继续保留。正在执行 内置浏览器操作（含页面加载、查看、操作和提取）时，停止须立刻中断并结束 run，不得等页面或浏览器操作自然完成后再结束。当前 run 仍在等待模型首个 token（流式尚未返回）时，停止也须立刻进入取消状态，不得等待服务商拆掉连接或 stream 自然结束。

  - `WB-COMPOSER-006-AC1` 普通运行中右侧只显示一个主按钮：草稿无可发送内容时显示停止，有可发送内容时显示发送并排队；排队发送后草稿清空，按钮恢复为停止。点击停止会停止当前 run，页面不显示额外的文字“取消”按钮。

#### WB-COMPOSER-017 运行中追加消息

#### WB-SCOPE-001 `@` 候选来源规则

#### WB-DOCUMENT-REFERENCE-001 DOCX 选区引用

- 普通文本：MD/TXT 和现有可编辑 UTF-8 文本支持跨行、段落、列表及代码块；保留源文位置及上下文，Markdown 维护源文与可见文字映射，排除隐藏语法标记与重复渲染节点，支持跨标题、列表、粗体、行内代码和 GFM 表格；重复正文结合选中块位置与上下文定位。高亮不修改文件或撤销历史。普通文本回跳恢复编辑器的原生选区与焦点，可继续复制和编辑；高亮绘制在正文下方，临时、已保存及悬停选区均保留文字可读性；MD、普通文本及 Excel 已保存选区悬停显示手形光标，单击可编辑引用，拖选仍保持原生行为。

- 确认时的文字与单元格内部快照不随源文件变化改写；PPT 视觉对象与 Excel 区域的模型内容以 AI 读取时的源文件为准。回跳核对内部快照与位置，无法可靠匹配时保留引用并提示；Excel 不把变化后的旧坐标当作原内容。提交等待被引用文本的待保存内容落盘；失败保留草稿，接受或排队成功后清除。引用不自动收窄知识库或授权修改。

#### WB-BLOCKER-001 人机交互阻塞

- 系统行为：
  - AI 提问使用 `waiting_human`，待审批使用 `waiting_approval`，共用底部交互位置，已有问题优先于后续审批。两类卡片共用外框、顶部「问题 / 操作确认」、右上分页与停止、整行选择及多行输入提交区；问题或操作说明独占标题区。仅一项时隐藏分页；停止结束整个 run，拒绝操作则交回伙伴继续处理。等待期间普通 Composer 隐藏，不接受排队消息，内置网页仍可由用户操作。

  - 提问与审批输入共用 全局多行输入主题与自动高度：有选项时从标准单行高度开始，纯输入题从三行开始，最多展示六行后滚动。选项下的补充输入与审批指导默认及悬停时无边框、无阴影，获得焦点后显示全局 Input 主题的边框与阴影，失焦后隐藏；纯输入题保留完整细描边。提问与审批卡内按 Enter 等同点击右下角当前主动作（下一步、发送回复、允许执行、确认拒绝或发送指导），选项行和输入框获得焦点时均可使用，不切换或清空已有选择；Shift+Enter 换行，Ctrl/Cmd+Enter 也可执行当前主动作。顶部翻页和停止按钮保留各自键盘操作。输入法组合输入与长按重复键不触发主动作，禁用、提交或取消期间不得触发。提交期间禁止重复提交并冻结选择、输入和翻页，停止入口保留；取消期间禁用全部操作。提交失败显示错误并保留草稿，成功由运行事件移除卡片。
  - 审批指导输入显示「告诉{对应伙伴名}该怎么做」：子任务优先使用来源子伙伴名，否则使用当前伙伴名；均缺失时使用「伙伴」，不硬编码产品名。保留子任务来源展示。提问输入依次使用「或直接输入回复…」「补充说明（可选）…」或纯输入题的「回复…」。

  - 审批卡不展示内部策略原因；完整命令放在独立浅灰代码块，支持换行和滚动。下方「允许本次操作 / 拒绝本次操作」为整行单选，不默认选择、不标推荐。非空指导文字清除当前选择并禁用选择行，清空指导后恢复未选状态；指导不是允许执行的附言。末项按钮按整批决定显示「允许执行 / 允许执行 N 项」「确认拒绝」或优先显示「发送指导」，此前仅为「下一步」。任何一项拒绝或指导均整批不执行；全部允许且最终提交后才执行。审批不自动超时，等待明确提交或取消。

#### WB-PANEL-004 内置浏览器面板

- 系统行为：
  - 各浏览器标签使用独立页面，共享持久化登录和浏览数据。本面板服务用户及 AI 浏览器操作，后台网页抓取独立运行，不污染本面板。
  - 普通打开网页不启用远程调试；自动化只在操作当前页面时连接本机控制通道，结束后释放。
  - 切换文件、折叠右侧栏或切换伙伴时，网页在后台继续运行，AI 操作不被打断；重新显示时保留同一页面，并展示后台操作后的实时状态。
  - 浏览器导航栏提供后退、前进、刷新/停止、URL 输入、输入框内“前往”按钮、地址栏右侧“将打开外部浏览器”按钮和更多操作；从 Markdown 网页链接打开内置浏览器时，先按当前伙伴已有 Tab 的当前 URL 匹配，命中则激活已有 Tab，未命中再新建并导航；地址栏导航仍作用于当前 Tab。
  - 用户地址栏与 AI `navigate` 共用同一套网址补全：输入什么协议就打开什么；未写协议时只补成 `https://`，失败不改成 `http://`。
  - 页面开始加载即展示面板与地址栏进度线，不等待加载完成。网络失败显示统一错误页和浏览器错误码，地址栏保留尝试打开的地址；用户停止不显示网络错误。AI 打开页面要等待真实标题、正文或表单才报告成功，网址本身与空白首屏不算就绪；失败仍返回目标标签信息，允许在原标签重试。
  - 浏览器更多菜单及新增标签页菜单使用主窗口原生子窗口承载自绘内容，覆盖在浏览器上方且不隐藏浏览器。

  - `WB-PANEL-004-AC14` 地址栏右侧提供“将打开外部浏览器”按钮（右上角外链图标）；有可打开 URL 时可点击，tooltip 与无障碍名称为“将打开外部浏览器”，点击后通过系统默认浏览器打开当前页或地址栏中的 URL。
  - `WB-PANEL-004-AC15` 用户地址栏与 AI `navigate` 对网址协议的处理一致：输入什么协议就打开什么。只填主机（如 `epub.cnipa.gov.cn`）时补成 `https://`，失败停在 https，不自动改 http；写明 `http://` 只走 http；写明 `https://` 只走 https。地址栏始终展示本次实际尝试的地址。
  - `WB-PANEL-004-AC16` 网络打不开时由馆长在同一内置页写入 Chrome 式错误文档：标题「无法访问此站点」、副文「无法加载 {主机}」、建议列表、底部 浏览器给出的网络错误码、灰色圆角「重新加载」按钮。只处理主页面的网络失败，用户主动停止不算失败；不另设馆长加载超时。连接或 TLS 何时失败由 Chromium 自己报。不因 https 失败改走 http。错误反馈直接展示在该页，不用额外遮罩。地址栏显示尝试的站点，不显示 `chrome-error://`。`navigate` 一开始就打开右侧浏览器面板，失败也打开。重新加载走当前地址栏同一套导航。
  - `WB-PANEL-004-AC17` AI `navigate` 不得把反爬/安全验证空白第一屏当成成功。等到有真实标题或正文/表单，或超时仍空白则失败（说明可能卡在站点安全验证）。Chromium 把网址当成标题（主机、主机:端口、路径）时不算真实标题。`observe` / `extract` / `screenshot` / `act` / `scroll` 若当前已是系统错误页或仍空白，同样失败，不得空结果报完成。
  - `WB-PANEL-004-AC18` 打开成功时向 AI 提供目标标签、可用标题及最终 URL；失败提供目标标签、错误说明与错误码，必要时包含尝试地址，便于在原标签重试。标题和地址清楚区分，不混成一行难以辨认的内容。
  - `WB-PANEL-004-AC19` 主框架加载期间，地址栏行底边出现约 2px 浅蓝色进度线（约 12% 起向 85% 推进）；主页面加载结束，或已写入馆长错误页后，走到 100% 并淡出。错误页展示期间不得继续显示进度线。不在原生网页上叠转圈遮罩。

### 6.7 直接写回与回退

#### WB-APPLY-001 打开 AI 修改记录后的默认选中逻辑

- 验收：

#### WB-APPLY-002 AI 修改完成后直接写回

- 验收：
  - `WB-APPLY-002-AC1` 修改现有 `docx` 后，源文件立即变为 AI 最终净稿，assistant turn 展示本轮「修改的文件」入口。
  - `WB-APPLY-002-AC2` 新建 `docx` 后，目标文件立即存在，assistant turn 展示本轮「修改的文件」入口。
  - `WB-APPLY-002-AC3` 创建或修改普通文本文件后，目标文件立即更新并生成修改记录；运行期间不展示修改入口，任务完成、失败或取消后 assistant turn 才展示本轮「修改的文件」，右侧可查看由真实写入前后内容计算的文本 diff。回答文本完成不等于任务收尾结束。
  - `WB-APPLY-002-AC4` 普通文本局部编辑只能匹配唯一且互不重叠的目标；全部替换处理所有非重叠精确匹配。匹配或范围等保存前校验失败时文件保持原样，保存后失败遵循 `WB-APPLY-003-AC14`。
  - `WB-APPLY-002-AC5` 同一次 AI Run 对同一个 pptx 的多次编辑只生成一条修改记录；PPT Diff 固定比较本 Run 第一次接触文件时的状态和 Run 完成后的最终状态。
  - `WB-APPLY-002-AC6` 创建或修改 `xlsx` 后，正式路径立即包含最终净工作簿并生成一条修改记录；同一次 AI Run 对同一路径连续编辑时保持首次写入前基线，不重复生成记录。
  - `WB-APPLY-002-AC7` 生成 PNG、JPEG 或 WebP 图片后，正式路径立即包含可读取图片并生成一条修改记录；同一次 AI Run 对同一路径再次生成时自动更新并保持首次写入前基线。
  - `WB-APPLY-002-AC8` 写回 `.docx` / `.pptx` / `.xlsx` 后的 WPS 自动刷新见 `WB-WPS-001`。

#### WB-TERMINAL-001 终端执行

- 系统行为：智能模式可通过终端执行命令；默认 cwd 为用户主目录。单次 终端执行 可指定最长盯着命令结束的时间；到点后命令继续执行，本次调用不再盯。未指定时按原有默认盯时。长命令可在运行中让出控制权并由后续读取续接；命令遵守审批与安全策略。绝对路径可访问工作地址外文件。终端改文件不进入修改记录，也不能从馆长回退。涉及数据计算、对账、统计等数值处理时，须通过终端真实执行计算，不得仅靠模型推算后直接写出结论文件。终端工具协议与并发/游标细节由 AI tool 回归覆盖。
- 验收：
  - `WB-TERMINAL-001-AC3` 删除伙伴、取消所属 run 或退出应用不会遗留进程。
  - `WB-TERMINAL-001-AC4` terminal 命令继续遵守审批与其他安全策略；不能访问其他伙伴的终端。
  - `WB-TERMINAL-001-AC7` AI 涉及数据计算、对账、统计、求和、对比等数值处理时，必须通过 terminal 执行真实计算；计算结果由终端命令产出，结果文件不自动进入修改记录与回退。
  - `WB-TERMINAL-001-AC8` 终端执行 的 指定等待时间 只限制本次调用盯着命令结束的时间；到点后命令继续执行，不中断命令。

#### WB-APPLY-003 回退本次 AI 修改

- 系统行为：受控文件写回保存本次任务的修改记录与修改前原始文件；外部编辑和终端修改不归入 AI 修改记录。历史审核固定比较本次原始内容与最后确认内容，不受以后文件变化影响。回退恢复原始字节，不反向计算差异。
- 验收：
  - `WB-APPLY-003-AC1` 未发生后续修改时，回退恢复写回前 checkpoint，记录状态变为 `reverted`。
  - `WB-APPLY-003-AC2` 新建文件回退时删除 AI 新建目标文件。
  - `WB-APPLY-003-AC3` 回退成功后，右侧修改的文件工作区应刷新记录状态；普通文本历史 diff 继续保留并标记“已回退”或“已删除”，避免丢失本次修改记录。
  - `WB-APPLY-003-AC5` Word 审核保留修改前原始文件和固定审阅稿，审阅展示段落、表格、图片、字体及页面结构。
  - `WB-APPLY-003-AC6` PPT 修改记录在审核模式提供固定的修改前后页面快照；不支持的审核格式明确报错。Excel 专用工具修改 `xlsx` 时在审核模式提供单元格边框标记，并可切换到预览模式。
  - `WB-APPLY-003-AC7` 图片生成记录直接预览最终图片并提供回退，不显示不存在的图片 Diff；更新图片回退后恢复首次生成前的文件，新建图片回退后删除目标文件。
  - `WB-APPLY-003-AC8` Docx Review 固定比较本次任务首次原始文档和最终文件，不依赖编辑操作历史；删除保留原位置，新增保留最终位置，移动使用原位置红删和新位置绿增。相同首尾状态生成相同净审阅；恢复原状、新增后删除不留下本轮修改记录或过期统计。
  - `WB-APPLY-003-AC11` 同位置段落及单元格文字使用用户感知字符级 Diff：未变字符只出现一次，删除字符红色加删除线，新增字符绿色，替换旧字符在前新字符在后；跨 run、超链接、空白、emoji 和组合字符保留正确格式及结构。字段、公式、图片等结构按对象处理。
  - `WB-APPLY-003-AC12` 纯格式变化在最终内容上局部标绿，不复制正文，不插入说明文字。文字样式仅标记变化字符，段落、单元格、表格及节设置标记对应范围；默认浅绿背景，已有背景或背景变化使用绿边框，保持真实字体颜色。格式恢复取消标记；不可定位的文档级变化只保留有效记录，不误标无关正文。
  - `WB-APPLY-003-AC13` Docx 预览、统计及有效记录使用同一净差异结果；文字新增、删除按内容块或单元格计数，替换和移动计 +1/-1 且有效修改计一项，逐字展示不逐字计数；纯格式及独立文档级变化计有效修改但不伪造文字增删，组合变化不重复计数。
  - `WB-APPLY-003-AC9` 专用写工具成功前正式文件已保存并校验；Office 历史审核固定首次原始 A→最后确认 B，后来正式文件变为 C 时预览显示 C、Office 审核仍显示 A→B；文本审核使用所选 run 的 A 对比当前 C，原始 AI 修改记录及其计数仍固定 A→B。只在主 run 真正完成、失败或取消时生成审核，子任务、yield 和追加消息续接不提前生成。
  - `WB-APPLY-003-AC14` 保存失败不自动恢复。提示与实际文件状态一致，已成功保存的修改继续有效；运行中断后启动补生成审核，不继续 AI 或改变正式文件。审核失败显示错误并保留重试输入。
  - `WB-APPLY-003-AC15` 清理临时 B 后历史审核仍完整可用，文本审核产物保留完整 A、B 文本，界面可展开未变行。审核产物缺失、损坏或格式不支持时明确报错，不回退到当前文件。PPT 备注变化只保留修改标记；Excel 保留空白样式、行高、列宽及合并，删除 Sheet 以唯一合法“原名（已删除）”展示，新 Sheet 保留正式名。
  - `WB-APPLY-003-AC16` 不同 run 的审核独立；两轮依次撤销可分别恢复 B、A 的原始字节。清空消息的勾选项决定是否保留回退记录与资源，删除伙伴清理对应目录。
  - `WB-APPLY-003-AC10` 回退 `.docx` / `.pptx` / `.xlsx` 后的 WPS 自动刷新见 `WB-WPS-001`。

#### WB-WPS-001 已打开的 WPS 文档随写回自动刷新

- 系统行为：默认支持 WPS 中已经打开的 Word 文档、Excel 表格、PPT 演示文稿 `.docx`、`.xlsx`、`.pptx` 随 AI 写回或回退刷新，设置页无需开关。馆长自动准备加载项，首次是否需要授权或手动启用由 WPS 决定，三类文件可能分别要求启用；刚启用或更新后仍未连接时，先保存并正常重启 WPS。尊重用户禁用加载项的选择。Workbench 在打开方式旁提供手册入口。
- 系统行为：写回前先关闭持有目标文件的 WPS 文档并释放文件锁，写回成功后重新打开新稿，尽量恢复滚动和选区。多个 WPS 实例之间不得误关或误开文件；关闭最后一篇文档后也应能重新打开目标文件，降级重开不得重复打开。同一组件完成授权后，不能因馆长重新启动或更新而无故重复要求授权。
- 异常边界：未安装、未授权或未连接时不强制关闭 WPS，仍尝试写盘；如果文件被独占且无法释放锁，写盘可以失败。刷新失败不撤销已成功的写盘。刷新会丢失 WPS 中尚未保存的编辑。旧格式 `.doc`／`.ppt`／`.xls` 与 Microsoft Office 不在范围内，刷新不触发知识库重索引。
- 验收：
  - `WB-WPS-001-AC1` 启动时自动准备 WPS 集成，无需用户配置开关；未发现 WPS 安装环境时不写系统配置。加载项可以载入馆长功能区及其代码，注册身份保持稳定。
  - `WB-WPS-001-AC2` AI 写回三种支持格式后，原持有目标文件的窗口展示重新打开后的内容；不能以仍打开的旧内容冒充刷新成功。
  - `WB-WPS-001-AC3` 回退后同样刷新；目标是组件最后一篇文档时仍能重开。组件无法自行重开时可使用系统打开，每次刷新同一路径最多执行一次，且需要确认最终内容已更新。
  - `WB-WPS-001-AC4` 未连接或拒绝授权时不强制关文档；未独占的文件仍能写盘与回退，独占且无法释放时允许失败。同组件多实例不会错误关闭或重新打开其他实例的文档。
  - `WB-WPS-001-AC5` 三组件各自首次授权；同一集成身份授权成功后不因重复注册或临时通信地址变化而重复提示。WPS 已运行或加载项更新时按要求重启后可载入「馆长」页签。首次授权弹窗由 WPS 负责，不作为馆长自有 UI 验收；Workbench 授权问号遵循 `WB-PANEL-003-AC22`。

- 审核定位：仅当前生效默认应用为 WPS 时，Office 修改区域提供点击反馈。DOCX 定位文字、段落或表格内容，PPT 定位页及可确认的元素，Excel 激活表并选中有效区域；拖选和拖动不触发定位。打开目标始终为正式文件，已打开则激活实际持有文件的实例。导航不关闭、重载或强制保存文档，保留未保存编辑；删除区域只定位可确认的邻近位置，不能确认时仅打开并说明。区分精确位置、容器、仅打开及失败反馈。WPS 编辑不实时重算审核。定位读取 WPS 当前内存中的内容，兼容已保存或未保存的后续编辑。Word 通过保留原文及文字上下文寻找段落，追加文字或相邻段变化不直接否定位置；PPT 优先使用实际幻灯片和元素身份，文字变化不直接否定元素；Excel 使用单元格原值、同行与同列上下文确认当前位置，无关单元格保存不阻止定位，可唯一确认的行列位移使用当前位置。查找有耗时和次数上限，重复、歧义、删除或超限时只打开并说明，不盲跳旧位置。
- `WB-WPS-001-AC6` 三种 Office 修改区域在默认 WPS 下打开当前文件并定位；非 WPS 默认不触发。多实例、重复点击不误开，不丢失未保存编辑，后续结构变化不得盲用旧坐标。
- `WB-WPS-001-AC7` 目标删除、文字重复、定位超时和文件缺失均有具体 toast；只定位到段落、单元格或幻灯片时说明范围及后续变化，精确成功无需额外提示。加载项问题与位置问题分别反馈，应用启动成功不能代替定位成功。
- `WB-WPS-001-AC8` 审核点击、用户在馆长内用 WPS 打开，以及已确认曾打开的文件写回刷新，共用按文件类型区分的加载项判断。明确禁用记录提示“未启用”；启用但无连接提示“未连接”；缺少或无法读取配置提示“无法确认状态”；不能由无连接推断“未授权”。已连接但目标未登记或响应超时按文档问题反馈。
- `WB-WPS-001-AC9` 加载项问题用统一说明框提供“稍后”和“查看使用手册”；当前会话相同类型、相同问题去重，连续问题合并在同一弹框，不因未在 WPS 打开的普通文件写入弹框。官网单篇手册说明启用、授权、必要时正常重启、定位与刷新作用及异常处理；两平台共用。刷新失败不改变磁盘写入结果，提示不得将打开成功说成刷新或定位成功。

#### WB-APPLY-004 后续修改后的强制回退

- 系统行为：若回退时检测到当前文件与 AI 写回后的内容不一致，先提示用户该文件已被后续修改，继续回退会丢失这些内容；用户确认后仍允许强制回退。
- 验收：
  - `WB-APPLY-004-AC1` 点击任何可回退记录时先展示统一确认框“回退这次修改？”，说明文件将恢复到这次修改发生前的状态；用户确认后才发起回退。
  - `WB-APPLY-004-AC2` 检测到后续修改时，在统一确认之后继续展示“仍然回退这次修改？”风险确认；用户确认强制回退后，系统恢复 checkpoint 或删除新建文件。

#### WB-APPLY-005 同一轮多个修改记录入口保留

### 6.11 应用内文本编辑

- 系统行为：

  - `WB-EDIT-001-AC14` `http(s)` 图片可直接显示；加载失败时按 AC13 处理。

- 文本审核顶部为单行紧凑栏，左侧“本次运行前”、右侧“当前文件（可编辑）”，暂不可编辑时右侧标明“当前文件（只读）”；右端使用 28px 无常驻边框的上一处／下一处差异和展开／折叠图标按钮，悬停说明操作、键盘焦点清晰可见。未变内容提示为“已折叠 N 行”，可单击或通过键盘展开，单块恢复提示为“恢复这处修改”。文本审核提供同步滚动、自动换行、未变内容折叠及单块恢复。右侧编辑实时更新审核区差异计数，不覆盖原始 AI 计数，不生成修改记录，单块恢复可撤销且不改变整条记录状态。切换模式、记录、关闭和回退前等待保存，失败保留内容。当前文件不存在时禁止写入，不自动重建。
- `WB-EDIT-001-AC15` 双栏修改、撤销、单块恢复、换行和联动滚动正确；不同 run 的左侧基线独立，右侧始终是当前文件。
- `WB-EDIT-001-AC16` 自动保存保留完整内容、BOM 和换行风格；切换与回退前等待保存，失败保留可重试内容。
- `WB-EDIT-001-AC17` 差异计算超时提示并暂停自动比较，保留完整文本编辑保存及重试；文件缺失不重建。
- `WB-EDIT-001-AC18` 当前审核计数随手动修改更新，原始 AI 记录及计数不变；旧审核产物格式不支持时明确报错。

### 6.12 定时任务

定时任务绑定伙伴，支持手动配置或由 AI 协助创建；到点使用伙伴当前模型、偏好和执行权限。表单、绑定失效及触发规则由下列 ST 需求分别定义。

#### ST-ENTRY-001 左侧栏入口

- 系统行为：Workbench 左侧栏「创建伙伴」下方展示同级、同样式的「定时任务」入口；点击后整个主区域（除左侧伙伴列表外）切换为定时任务视图，不展示聊天对话和资源面板。当存在已启用定时任务时，入口右侧展示蓝色数量 chip（显示已启用个数），时钟图标同步使用蓝色；已启用数为 0 时不展示 chip，入口恢复安静态。
- 验收：
  - `ST-ENTRY-001-AC1` 「定时任务」入口位于「创建伙伴」下方，使用与「创建伙伴」一致的侧栏选项样式。
  - `ST-ENTRY-001-AC2` 点击入口后，主区域整块切换为定时任务视图，聊天对话与资源面板不再显示。
  - `ST-ENTRY-001-AC3` 存在已启用定时任务时，入口右侧可见蓝色数量 chip，数值等于已启用任务数；全部关闭或无任务时 chip 不显示。

#### ST-VIEW-001 视图独立与返回

- 系统行为：定时任务视图是独立自包含组件，占据除左侧伙伴列表外的整个主区域；该视图没有聊天对话。视图顶部提供标题栏（标题旁复用与侧栏同款的已启用数量 chip），点击「创建伙伴」或点击左侧任意伙伴即返回聊天视图并切换 / 停留在该伙伴。侧栏伙伴的编辑 / 删除确认弹窗在定时任务视图下仍可正常展示。
- 验收：
  - `ST-VIEW-001-AC1` 定时任务视图中不展示聊天对话或资源面板。
  - `ST-VIEW-001-AC2` 点击左侧任意伙伴后返回聊天视图并切换到该伙伴。
  - `ST-VIEW-001-AC3` 点击「创建伙伴」后返回聊天视图并打开创建弹窗。
  - `ST-VIEW-001-AC4` 存在已启用定时任务时，标题栏「定时任务」旁可见与侧栏同款的蓝色数量 chip。
  - `ST-VIEW-001-AC5` 定时任务视图下点击侧栏伙伴删除，删除确认弹窗可见且可操作。

#### ST-LIST-001 列表展示

- 系统行为：视图打开后拉取全部定时任务并展示；每个任务项展示名称、绑定伙伴、调度时间摘要、启用开关、「立即执行」按钮、编辑图标与删除图标。无任务时展示空态与创建入口。
- 验收：
  - `ST-LIST-001-AC1` 视图打开后可见已配置任务列表，而不是未初始化状态。
  - `ST-LIST-001-AC2` 任务项展示名称、绑定伙伴和调度时间摘要。
  - `ST-LIST-001-AC3` 无任务时展示空态和创建入口。
  - `ST-LIST-001-AC4` 任务项提供「立即执行」入口。

#### ST-FORM-001 新增与编辑配置

- 系统行为：手动新增和编辑从右侧打开约半屏宽的 Drawer，窄窗口时占满可用主区；字段从上到下为任务名称、任务描述、伙伴、执行周期和执行时间。内容区独立纵向滚动，取消和保存固定在底部，点击遮罩不关闭；标题栏保留可用的关闭按钮，通过关闭按钮、取消或按 Esc 尝试关闭时，有未保存修改先确认。伙伴必选；手动创建、编辑和 AI 创建均使用动态头像伙伴列表，每行显示头像、截断名称和清晰选中态，最多显示四项（208px），超出后内部滚动。没有伙伴时保存被拦截，AI 创建不能继续。任务描述复用 Composer 输入框，默认高度为 120px，超出后内部滚动；支持 `@` 资料候选，所选资料以行内 token 展示在正文中，候选面板按可用空间自动显示在输入框上方或下方；不渲染 Markdown。保存任务描述中的文字、引用与输入顺序。手动创建保存后默认开启；编辑保存保留原启用状态，并支持重新绑定伙伴。任务执行时读取绑定伙伴当前 Composer 的模型、偏好和执行权限。创建入口分为手动创建和 AI 创建。
- 验收：
  - `ST-FORM-001-AC1` 新增时可填写全部字段并保存，编辑时带出当前配置值。
  - `ST-FORM-001-AC2` 伙伴、名称、任务描述、执行时间或周期字段缺失时，保存被拦截并给出明确提示。
  - `ST-FORM-001-AC3` 选择「每周」时必须选择星期几。
  - `ST-FORM-001-AC4` 新增和编辑 Drawer 点击遮罩不关闭；标题栏关闭按钮可用；有未保存修改时，通过关闭按钮、底部取消或 Esc 关闭必须先确认，确认后关闭、取消后保留表单。
  - `ST-FORM-001-AC6` 新增保存成功后绑定所选真实伙伴。
  - `ST-FORM-001-AC7` 编辑保存后启用状态与保存前一致；已启用任务不会因保存被关闭。
  - `ST-FORM-001-AC8` 任务描述复用 Composer 输入框，默认高度为 120px，超出后内部滚动；`@` 候选被选中后以行内 token 展示，候选面板根据可用空间自动显示在输入框上方或下方；Markdown 符号保持普通文本不渲染，编辑时正文和 token 回填。
  - `ST-FORM-001-AC9` 手动创建、编辑和 AI 创建均使用伙伴列表选择，每行显示动态头像、截断名称和清晰选中态；最多显示四项（208px），更多伙伴时列表内部滚动；没有伙伴时保存被拦截且 AI 创建不能继续。
  - `ST-FORM-001-AC10` 新增和编辑使用右侧半屏 Drawer，字段按名称、描述、伙伴、周期、时间纵向排列；窄窗口占满可用主区，内容独立滚动，底部取消和保存固定；标题栏关闭按钮可用，未保存时先确认。
  - `ST-FORM-001-AC11` 保存任务描述后，文字和资料引用保持原来的输入顺序；定时触发时引用随消息交给 AI。
  - `ST-FORM-001-AC12` AI 创建选择伙伴后切换到该伙伴并预填任务设置引导语，只准备草稿，不创建任务、不发送消息或启动运行；切换伙伴后草稿仍保留。

#### ST-PARTNER-001 伙伴绑定生命周期

- 系统行为：每个新任务必须绑定现有伙伴。删除伙伴后关联任务保留、清空绑定并停用；未绑定任务不能启用。
- 验收：
  - `ST-PARTNER-001-AC1` 删除伙伴后，定时任务仍存在但显示未绑定且停用。

#### ST-SWITCH-001 启用开关

- 系统行为：每个任务项提供启用开关；新建任务默认开启，编辑保存不改变原启用状态。切换后立即生效。未绑定伙伴的任务不能启用。
- 验收：
  - `ST-SWITCH-001-AC1` 新建任务默认开启，保存后即可按调度执行。
  - `ST-SWITCH-001-AC2` 关闭后该任务到点不再触发。
  - `ST-SWITCH-001-AC3` 编辑并保存配置不会打开或关闭任务。

#### ST-DELETE-001 删除

- 系统行为：删除前二次确认，确认后从列表移除。
- 验收：
  - `ST-DELETE-001-AC1` 删除前有确认弹窗，取消不删除。
  - `ST-DELETE-001-AC2` 确认后任务从列表移除。

#### ST-RUN-001 到点触发

- 系统行为：程序运行期间，已启用任务到达调度时间时，向绑定伙伴追加任务描述，读取该伙伴当前 Composer 的主模型、偏好和执行权限；不新建额外会话，也不操作用户当前页面。绑定伙伴不存在时自动解绑并停用。伙伴已有 `running` / `waiting_human` / `waiting_approval` 时，**取消本次调度**并推进到下一调度时间。
- 验收：
  - `ST-RUN-001-AC1` 到点后往绑定伙伴追加任务消息。
  - `ST-RUN-001-AC2` 触发过程不改变用户当前正在查看的伙伴或输入草稿。
  - `ST-RUN-001-AC3` 绑定伙伴已有 running / waiting_human / waiting_approval 时取消本次执行并推进下一周期，不自动补跑。

#### ST-RUN-002 伙伴列表刷新

- 系统行为：定时任务触发并往伙伴追加消息后，广播伙伴列表刷新，Workbench 伙伴列表展示该伙伴及其运行状态。
- 验收：
  - `ST-RUN-002-AC1` 定时任务触发后，目标伙伴显示运行状态。
  - `ST-RUN-002-AC2` 用户无需手动刷新即可看到该伙伴运行标记。

#### ST-RUN-003 程序关闭错过不补跑

- 系统行为：程序关闭期间错过的调度时间不补跑，重新打开后只等待下一次到点。
- 系统行为：程序运行期间因系统休眠跨过触发点（超过 60 秒宽限）同样视为错过，不补跑并顺延到下一周期；到点后 60 秒内的正常延迟仍触发。
- 验收：
  - `ST-RUN-003-AC1` 程序关闭期间错过的调度时间，重新打开后不会立即触发补跑。
  - `ST-RUN-003-AC2` 系统休眠跨过触发点后唤醒，不补跑并顺延到下一周期。

#### ST-RUN-004 立即执行

- 系统行为：定时任务列表与忙碌取消胶囊均提供「立即执行」。点击后先弹出确认框；确认后按该任务当前配置在绑定伙伴执行。若伙伴仍占用，不提交并提示「请等待当前任务结束，或先停止后再执行」。
- 验收：
  - `ST-RUN-004-AC1` 列表「立即执行」点击后出现确认框；取消确认不执行。
  - `ST-RUN-004-AC2` 确认后在绑定伙伴启动执行（空闲时）。
  - `ST-RUN-004-AC3` 绑定伙伴仍占用时提示等待结束或先停止，不启动新 run。

#### ST-RUN-005 忙碌取消消息操作胶囊

- 系统行为：到点因绑定伙伴占用取消后，在该伙伴 Composer 显示时，于其上方展示可关闭的消息操作胶囊（与清空消息记录同壳）。问答或审批卡片替换 Composer 时暂不展示，卡片收起、Composer 恢复后继续展示未处理提示。主文案为 `立即执行「{任务名}」`（过长省略）；提供 `×` 关闭提示。点击主操作走 `ST-RUN-004` 确认后立即执行。
- 验收：
  - `ST-RUN-005-AC1` 忙碌取消后进入绑定伙伴，Composer 显示时可见该胶囊，文案含任务名；问答或审批卡片收起后提示仍可见。
  - `ST-RUN-005-AC2` 点击 `×` 后胶囊消失且不执行任务。
  - `ST-RUN-005-AC3` 点击主操作先确认，确认后按立即执行逻辑处理。
