# Workbench PRD

## 1. 文档定位

- 本文档是 workbench 用户可见功能的产品规格来源，描述目标、范围、术语、交互、状态、边界和验收标准。
- workbench 的用户可见行为、流程、反馈或阻塞逻辑发生变化时，必须同步更新本文。
- 后续实现、测试、评审和 AI 最终汇报都应引用本文中的需求编号与验收编号。

## 2. 产品目标

- 用户通过对话让 AI 完成搜索、分析、回答、整理和文档处理等任务。
- 用户可以把本地资料作为上下文，让 AI 优先据此完成检索、分析、回答和受支持文件处理。
- 让 workbench 成为“发起任务、查看过程、处理中断、查看修改的文件并按需回退、继续执行”的主工作台。
- workbench 应把任务推进到完成；无法完成时明确说明原因、限制或所需条件。

## 3. 产品原则

- 本地资料是重要上下文，但不是唯一能力边界；未显式选择资料时，AI 仍可完成通用任务。
- workbench 的发送前提是已有伙伴且输入非空。对话不再绑定工作空间，也不再要求先设置工作文件地址才能发送。
- 未显式插入 `@` 时，知识库默认覆盖设置页全部已索引文件地址与全局网页资料；`@` 只用于在此基础上再收窄。工作地址列表由当前 build user 的 `<workspace_roots>` 按设置页现表渲染（位于 `<reference_scope>` 之上），不作为 Composer 选择器，也不进 System。
- 当用户插入 `@` 参考资料时，AI 应优先基于这些范围完成任务，而不是忽略用户给出的约束。
- workbench 不只展示问答过程，还要交付可消费结果，或给出明确失败信息。
- 用户可见能力边界必须明确可见，尤其是哪些资料可检索、哪些格式可直接写回并回退、哪些情况只能查看或分析。

## 4. 范围

- 包含伙伴管理（创建、编辑、切换、删除、置顶、空态）。
- 包含 composer 输入、发送与取消；Composer 只有智能模式，不再提供 AI / 搜索切换。
- 包含智能模式下 AI 推进偏好的选择与本机恢复。
- 包含附件拖放和智能模式下执行权限的选择与伙伴级恢复。
- 包含 `@` 参考资料 token 的插入与维护。
- 包含按天时间轴跳转，以及清空消息记录。
- 包含 AI 运行中的审批与上下文压缩过程提示。
- 包含右侧内容面板中的文档查看与修改的文件回退入口。
- 包含基于本地资料和网页资料的上下文使用。
- 包含定时任务的入口、独立主区视图、任务配置、启用开关与到点触发。
- 不包含设置页中的资料配置逻辑。
- 不包含视觉风格与基础控件样式定义。
- 不包含 AI 工具协议、operation 矩阵、结果信封或 graph / prompt 细节（见 `doc/ai-harness/**` 与 `doc/test-plan/ai-test.md`）。

## 5. 当前能力边界

- workbench 可使用设置页全部已索引文件地址与全局网页资料作为默认知识库范围；`@` 再收窄本轮范围。
- 当前本地知识库可索引文件类型为 `.pdf`、`.doc`、`.docx`、`.md`、`.markdown`、`.txt`、`.xlsx`、`.xlsm`、`.xltx`、`.xltm`。每个文件索引时都会前置一个「文件名锚点」内容块，保证按文件名可被知识库搜索命中；空文本文件不产生正文内容，但保留文件名锚点。Excel 只索引文件名、文档标题与工作表名等元数据，不索引任何单元格内容，单元格数据仍由 Excel 专用工具按绝对路径处理。`.doc` 只读，不支持直接编辑。
- 未显式选择参考资料时，智能模式仍可处理通用任务。
- 显式选择目录、文件或网页资料后，任务应优先使用这些资料。未显式 `@` 时，默认使用全部已索引文件地址与全局网页；资料不足时，智能模式可用模型通用知识补充通用部分。
- 当前可由 workbench 直接写回并支持回退的受支持文件类型包括 `docx`、`pptx`、`xlsx`、生成的 `png`、`jpg`、`jpeg`、`webp` 图片，以及 Markdown、TXT、配置文件和代码等 UTF-8 普通文本文件；普通文本支持创建、完整改写、唯一文本编辑和全部精确匹配替换。Excel 工具可读取 `xlsx`、`xlsm`、`xltx`、`xltm`，但只允许创建和编辑 `xlsx`，避免写回时丢失宏或模板信息。
- 用户可在右侧面板对真实本地 Markdown（所见即所得）与普通 UTF-8 文本（纯文本）做应用内手动编辑并保存，见 `WB-EDIT-001`；应用内手动编辑不生成修改记录、不进入回退体系。
- 当前通过 composer 附件进入对话上下文的文件不限扩展名，只要是可以选中的文件即可作为附件；`+` 选择和拖放文件保留源文件绝对路径，粘贴文件保存副本到当前伙伴运行时目录。附件不自动预解析，只把名称与路径交给 AI 后续自行处理。AI 工具侧仍有各自格式边界（如 `doc` 只读、`pptx` 可交给 PPT 工具读取和编辑、Excel 工具只写 `xlsx`），无法处理的文件会在 AI 工具层报错。
- 其他格式不保证直接写回和回退。AI 可以在审批与工作地址扫描边界内尝试处理，但不属于受支持文件能力范围。
- 终端执行只允许当前平台安全指令集直接运行；一条 terminal 命令被拆分后的每段都命中安全指令集时可直接执行，任一段未命中则必须先经用户手动批准。安全指令集只决定是否可直接执行，不决定执行模式。默认工作目录是用户主目录；只有命令开始时的 cwd 落在某个工作地址内时，才扫描该 cwd 子树作为修改记录。
- Composer 不再提供搜索模式。AI 仍可通过 `web_search` / `kb_search` 检索；`web_search` 不得自动展开右侧搜索列表（该列表面板已不存在）。设置页正在「更新索引」时，`kb_search` / `kb_list_documents` 失败并提示正在更新知识库；「检查更新」不拦截。
- 发送不再要求绑定工作空间目录；`@` 参考资料不能替代「已创建并选中伙伴」这一发送前提。
- 搜索、文件读取和执行结果必须服务后续回答、结论或文件产物，不能只停留在过程展示中。

## 6. 术语

- 伙伴：一条一直聊下去的对话记录。侧栏只有伙伴列表，没有「新会话」或草稿会话。
- 参考资料：通过 `@` 插入的目录、文件或网页资料 token。
- 工作地址：设置页添加的本地目录或文件根路径（`workspace_source.root_path`）。对话里不再选择工作空间。
- 智能模式：Composer 唯一发送路径；启动 AI 运行，允许产生阻塞、审批、文件直接写回与回退入口。
- 受支持文件：当前已具备直接写回与回退能力的文件类型；当前包括 `docx`、`pptx`、`xlsx`、生成的 PNG、JPEG、WebP 图片和 UTF-8 普通文本文件。
- 目标文件：用户要求新建受支持文件时，AI 写工具直接创建的文件路径。
- 直接写回：AI 写工具将最终 docx、pptx、xlsx、生成图片或普通文本结果原子写入源文件或创建目标文件的流程；工具成功即代表正式路径已可读取，run 收尾不再提交文件。
- 修改记录：一次 AI run 中由受控文件工具直接写回，或由某条 terminal 命令前后差异识别出的创建、更新、删除或重命名记录；提供打开文件、适用格式的审核模式与回退本次修改入口。
- 回退本次修改：基于写回前 checkpoint 恢复文件；新建文件回退时删除目标文件，若文件在 AI 写回后又被修改，需提示用户确认会丢失后续修改。
- 清空消息记录：删除该伙伴全部对话消息记录（及对应 `ai_run`），界面回到空对话；不删除伙伴本身，也不删除 `ai_file_change` 文件回退记录。
- 内部引用链接：assistant 回答中使用标准 Markdown 语法 `[显示名](绝对本地路径或 https URL)` 引用的本地文件或网页链接；点击可在右侧工作台预览文件或打开内置浏览器，不可访问时展示弱化状态并禁止点击。详细校验与交互见 `WB-COMPOSER-003-AC8`。
- AI 推进偏好：智能模式下用户对资料使用边界的附加约束，界面选项包括“默认”“本地资料·宽松”“本地资料·严谨”。当前“本地资料”范围包含全部已索引文件地址、全局网页资料、工作地址内文件和显式参考资料。宽松模式优先使用这些资料，资料不足时允许补充模型知识或外部网页；严谨模式只能把这些资料作为事实依据，资料不足时必须明确说明，不得把模型知识、外部搜索或浏览器结果伪装成资料内事实。
- 执行权限：智能模式下对本次运行是否等待工具审批的选择，独立于 AI 推进偏好。选项为“审核”和“完全访问”。

## 7. 需求规则

- Workbench 基础需求编号使用 `WB-<模块>-<三位序号>`，验收编号使用 `WB-<模块>-<三位序号>-AC<序号>`。
- 定时任务子需求编号使用 `ST-<模块>-<三位序号>`，验收编号使用 `ST-<模块>-<三位序号>-AC<序号>`。
- 需求编号稳定后不因措辞微调而重排；只有功能被废弃时才标记为废弃。

## 8. 需求明细

### 8.1 核心能力与约束

#### WB-CORE-001 本地资料是可选上下文，不是唯一前提

- 系统行为：workbench 发送前要求已有伙伴；在此基础上，即使用户未显式选择任何本地参考资料，AI 仍可执行不依赖本地文档的通用任务；当存在本地参考资料时，可将其作为任务上下文使用。未创建伙伴时 Composer 为空态，不能发送。
- 验收：
  - `WB-CORE-001-AC1` 用户已创建并选中伙伴但未选择任何本地参考资料时，智能模式仍可正常发起不依赖本地文档的任务。
  - `WB-CORE-001-AC2` 系统不会把“没有显式本地参考资料”误表现为“workbench 不可用”；未创建伙伴时才表现为 Composer 空态。

#### WB-CORE-002 用户显式选择的参考资料或默认知识范围必须影响执行

- 系统行为：当用户插入 `@` 参考资料后，后续检索、分析和执行应优先基于这些显式范围收敛；当用户未显式选择参考资料时，知识库默认覆盖设置页全部已索引文件地址与全局网页资料。
- 验收：
  - `WB-CORE-002-AC1` **废弃**（原搜索模式检索范围）。Composer 已删除搜索模式。
  - `WB-CORE-002-AC2` 智能模式下，系统不会忽略用户已经给出的 `@` 参考资料或默认知识范围；已选资料作为优先缩圈候选，但不自动变成唯一可搜索范围。

#### WB-CORE-003 当前受支持文件的直接写回能力边界必须明确

- 系统行为：workbench 明确区分“可直接写回并支持回退的受支持文件”和“可由 AI 自行尝试处理但不提供同等保证能力的其他任务”；当前受支持文件类型包括 `docx`、`pptx`、`xlsx`、生成的 `png`、`jpg`、`jpeg`、`webp` 图片和 UTF-8 普通文本文件。`xlsm`、`xltx`、`xltm` 只读，不属于可直接写回范围。
- 验收：
  - `WB-CORE-003-AC1` 当前支持直接写回与回退的受支持文件类型列表明确可见，包括 `docx`、`pptx`、`xlsx`、PNG、JPEG、WebP 图片的修改和新建，以及 Markdown、TXT、配置文件和代码等 UTF-8 普通文本文件。
  - `WB-CORE-003-AC2` 不在当前受支持文件类型列表中的资料不会被伪装成可进入同一直接写回与回退流程的编辑或创建目标。

#### WB-CORE-004 资料优先级受 AI 推进偏好约束

- 系统行为：默认或宽松偏好下，当用户已插入参考资料或存在已索引文件地址 / 全局网页时，系统优先基于这些资料完成任务；未显式 `@` 时，默认使用全部已索引文件地址与全局网页作为知识范围。资料不足时，默认或宽松偏好允许补充模型通用知识或外部网页信息，但不能忽略或违背用户已给定的资料。严谨偏好下，只允许把已索引文件地址、全局网页与显式参考资料作为事实依据；资料不足时应明确说明缺口，不得使用模型知识、`web_search` 或 `browser_use` 的外部内容补足事实。
- 验收：
  - `WB-CORE-004-AC1` 用户已有默认知识范围或显式参考资料时，问答或受支持文件结果不会脱离这些资料另起一套无关内容。
  - `WB-CORE-004-AC2` 默认或宽松偏好下，资料不足以覆盖通用部分时，系统仍可补充模型通用知识或外部网页信息，并明确区分资料内事实与补充信息。
  - `WB-CORE-004-AC3` 严谨偏好下，资料不足时系统明确说明资料缺口，不使用默认知识范围和显式参考资料之外的信息补足事实。

#### WB-CORE-005 任务过程中的中间结果必须服务于后续结果

- 系统行为：当任务执行过程中产生搜索结果、文件读取结果、执行结果或其他中间信息后，后续 assistant 回答、分析结论和文件产物应实际使用这些信息继续推进用户诉求；若当前中间结果不足以支撑继续完成，系统应明确说明限制，而不是伪造后续内容。
- 验收：
  - `WB-CORE-005-AC1` 任务过程中产生的中间结果，会体现在后续用户可见回答、结论或文件产物中，而不是只表现为“执行过某些步骤”。
  - `WB-CORE-005-AC2` 当前中间结果不足或执行失败时，assistant 会明确说明为什么无法继续完成、缺少什么条件或当前能确认到什么范围，而不是编造结论或文档内容。
  - `WB-CORE-005-AC3` 用户可见输出优先围绕用户原始诉求组织；若引用中间结果，应使用用户能理解的表达，而不是暴露内部工具或过程标签。

#### WB-CORE-006 用户诉求应被推进到完成或明确失败

- 系统行为：当用户已提供足够上下文且当前能力允许时，workbench 应以“最小可靠返回 × 最少连续决策轮次”持续推进用户诉求直到完成：只读取当前决策所需范围，避免全量或重复读取，独立调用尽量同轮发起，同类批量能力不拆轮。若当前无法完成，也应明确返回失败原因、限制信息或下一步所需条件，而不是停留在搜索结果、工具调用或过程提示等中间过程。
- 验收：
  - `WB-CORE-006-AC1` 用户诉求可完成时，系统会把任务推进到可消费结果、明确产物或可确认的下一步动作，而不是停留在中间态。
  - `WB-CORE-006-AC2` 用户诉求当前无法完成时，系统会明确说明失败原因、限制信息或下一步所需条件，而不是无声中断或只留下过程信息。
  - `WB-CORE-006-AC3` 最终收口默认直接围绕用户显式提出的问题组织；若同时需要说明产物、依据或限制，也应使用用户可理解的语言表达，而不是依赖内部标识、tool 名或固定章节标题。
  - `WB-CORE-006-AC4` 简单任务不强制创建 plan；复杂或多依赖任务才维护 plan，不为汇报进度单独更新。目标满足且必要检查通过后可直接交付。

#### WB-CORE-007 网页信息可用于任务推进

- 系统行为：默认或宽松偏好允许 AI 通过后台 `web_search` 搜索网页、读取指定网页正文，并在需要登录或人工操作时使用 `browser_use` 打开右侧内置浏览器继续任务；严谨偏好不得把外部网页作为资料内事实依据。`web_search` 是 Human 图后台工具，结果只回模型与过程层，不得自动展开右侧搜索列表（该列表面板已不存在），也不得替代 `browser_use` 的可见浏览器交互。
- 验收：
  - `WB-CORE-007-AC1` 用户要求查找公开网页信息时，AI 可搜索并读取搜索结果或用户给出的 URL，再用所得内容完成回答或产物。
  - `WB-CORE-007-AC2` 网页搜索、读取或浏览失败时，系统明确说明失败边界，不伪造网页内容。
  - `WB-CORE-007-AC3` 严谨偏好下，外部网页能力不会绕过资料范围限制。
  - `WB-CORE-007-AC4` AI 调用 `web_search` 时，Workbench 不得因工具结果自动打开右侧搜索列表；过程层可展示“搜索网页 / 抓取网页”等状态，但右侧面板保持原状，除非用户手动打开资源或 AI 触发 `browser_use`。
  - `WB-CORE-007-AC5` `web_search` 的外网抓取在后台 headless CDP host 中完成，用户不得看到带窗框的独立浏览器窗口或主界面被网页内容遮挡。
  - `WB-CORE-007-AC6` `web_search` fetch 默认走 Crawl4AI；抓取超时或失败时可降级为 HTTP 正文提取，以保证任务能返回可读正文或明确失败，而不是无限挂起。

#### WB-CORE-008 Workbench 窗口层与业务内容分层

- 系统行为：Windows Workbench 的原生窗口控制层独立位于业务内容上方；无伙伴空态拖动区、侧栏入口和业务内容不互相遮挡。非 Windows 平台保留页面顶部拖动区。
- 验收：
  - `WB-CORE-008-AC1` 无伙伴空态仍提供可命中的 44px 拖动区。
  - `WB-CORE-008-AC2` Windows 原生控制层为独立 36px 区域，业务内容从其下方开始。
  - `WB-CORE-008-AC3` Windows 侧栏切换按钮保持 `no-drag` 且与原生控制按钮对齐。

### 8.2 伙伴管理

侧栏只有伙伴列表与「创建伙伴」，没有「新对话」或按工作空间分组。伙伴创建弹窗提交即落库，不是发第一条消息才创建。

#### WB-SESSION-001 无伙伴时展示空态，创建即落库

- 系统行为：智能模式任务因用户主动停止、网络错误、请求超时、应用进程中断、输出截断、达到运行上限或未知异常而没有正常完成时，历史消息日志保持不变。用户之后在同一伙伴发送消息时，系统从日志投影：先切到最后一次 `context_cleared` 之后，再按压缩书签截断。历史 User 用 log 里的 `content`（发给模型的原文）；压缩摘要在 `origin: compaction` 那条 checkpoint User 上。书签之后的原文照发（checkpoint 后可跟这段原文，可含多条 User），补齐悬空工具结果，再把新 User 追加一次继续推进。新 User 不抄 checkpoint。若压缩后又产生了尚未折进摘要的过程，这些过程前面必须先放 checkpoint User，不能直接接在 System 后面。气泡仍是人打的字（`ai_run.input`）；压缩 User 不当新气泡。每条历史 human user 保留当轮参考资料和附件配置；新 user 只使用 Composer 当前配置。计划与已学习技能均从切断点之后的消息日志恢复。重启只标记中断，不自动重新调用模型。

### 8.3 Composer 输入与发送

#### WB-COMPOSER-001 发送前置条件

- 系统行为：只有当前已选中伙伴、输入裁剪后非空且未处于发送中时，发送按钮才可执行；仍需满足已选主模型等现有条件。发送按钮因前置条件不满足而不可执行时，用户可通过 hover 查看具体原因提示。未创建伙伴时 Composer 为空态，不出现可发送按钮。

#### WB-SCOPE-001 `@` 候选来源规则

  - `WB-PANEL-004-AC13` AI 通过 `browser_use` 的 `act` 触发网页操作时，通过 DOM 虚拟光标提供移动和点击视觉反馈；单次动作执行完毕时光标保持常驻在最后操作位置（不提前隐藏），后续动作平滑连续移动；仅当整轮 AI Run 结束（正常完成、用户取消或异常中断）时，通过运行资源管理器统一平滑淡出隐藏。

### 8.8 直接写回与回退

#### WB-APPLY-001 打开 AI 修改记录后的默认选中逻辑

- 系统行为：从 assistant turn 打开修改记录时，自动展开右侧面板并打开或激活对应文件 Tab，但工作区文件列表默认保持关闭；用户手动打开文件列表后默认进入“本次运行改动”，并选中当前文件。同一路径只保留一个文件 Tab。Docx 工具修改使用 Review Docx，普通文本记录使用结构化文本 diff。
- 验收：
  - `WB-APPLY-001-AC1` 成功打开修改记录后，界面立即可见当前文件面包屑；若记录存在审核内容则默认进入审核模式并展示回退入口，切到预览模式后隐藏回退入口和差异信息。
  - `WB-APPLY-001-AC2` 在同一轮多文件场景下，点击哪个修改文件入口，右侧就加载该文件记录，而不是空白态或自动跳到其他文件。
  - `WB-APPLY-001-AC3` 用户点击 assistant turn 中的本轮“修改的文件”入口后，右侧应进入修改的文件工作区，并默认加载该入口对应的本轮修改记录。

#### WB-APPLY-002 AI 修改完成后直接写回

- 系统行为：受支持 `docx`、`pptx`、`xlsx`、图片生成和普通文本写任务完成后直接写回源文件或创建目标文件，并生成修改记录。普通文本支持创建、整篇改写、唯一片段编辑和全文精确替换；任一校验失败时不产生部分写入。各格式写入细节由 AI tool / live 回归覆盖（见 `doc/ai-harness/tool-design.md`）。
- 验收：
  - `WB-APPLY-002-AC1` 修改现有 `docx` 后，源文件立即变为 AI 最终净稿，assistant turn 展示本轮「修改的文件」入口。
  - `WB-APPLY-002-AC2` 新建 `docx` 后，目标文件立即存在，assistant turn 展示本轮「修改的文件」入口。
  - `WB-APPLY-002-AC3` 创建或修改普通文本文件后，目标文件立即更新并生成修改记录；运行期间不展示修改入口，收到 `run_completed / run_failed / run_cancelled` 后 assistant turn 才展示本轮「修改的文件」，右侧可查看由真实写入前后内容计算的文本 diff。`answer_completed` 不视为 run 已结束。
  - `WB-APPLY-002-AC4` 普通文本 `edit` 的每个 `oldText` 必须唯一且互不重叠；`replaceAll` 替换一个 `oldText` 的全部非重叠精确匹配；失败时文件保持原样。
  - `WB-APPLY-002-AC5` 同一次 AI Run 对同一个 pptx 的多次编辑只生成一条修改记录；PPT Diff 固定比较本 Run 第一次接触文件时的状态和 Run 完成后的最终状态。
  - `WB-APPLY-002-AC6` 创建或修改 `xlsx` 后，正式路径立即包含最终净工作簿并生成一条修改记录；同一次 AI Run 对同一路径连续编辑时保持首次写入前基线，不重复生成记录。
  - `WB-APPLY-002-AC7` 生成 PNG、JPEG 或 WebP 图片后，正式路径立即包含可读取图片并生成一条修改记录；同一次 AI Run 对同一路径再次生成时自动更新并保持首次写入前基线。

#### WB-TERMINAL-001 终端执行

- 系统行为：智能模式可通过终端执行命令；默认 cwd 为用户主目录。长命令可在运行中让出控制权并由后续读取续接；命令遵守审批与安全策略。绝对路径可访问工作地址外文件，但只有开始 cwd 落在某个 `workspace_source.root_path` 内时，才扫描该 cwd 子树进入修改记录与回退。涉及数据计算、对账、统计等数值处理时，须通过终端真实执行计算，不得仅靠模型推算后直接写出结论文件。终端工具协议与并发/游标细节由 AI tool 回归覆盖。
- 验收：
  - `WB-TERMINAL-001-AC3` 删除伙伴、取消所属 run 或退出应用不会遗留进程。
  - `WB-TERMINAL-001-AC4` terminal 命令继续遵守审批与其他安全策略；不能访问其他伙伴的终端。
  - `WB-TERMINAL-001-AC7` AI 涉及数据计算、对账、统计、求和、对比等数值处理时，必须通过 terminal 执行真实计算；计算结果由终端命令产出，对应变化按 terminal 修改记录处理。

#### WB-APPLY-003 回退本次 AI 修改

- 系统行为：受控文件工具写回工作地址内文件时立即保存本次 run 的修改记录、有效变更校验和所需快照；terminal 每条命令执行前，仅当开始 cwd 落在某个工作地址内时保存该 cwd 子树基线，命令最终结束或失败后计算该命令窗口内的新增、修改、删除和重命名。终端记录归入发起命令的 run。不同 terminal 命令并发重叠时允许同一变化在多个 run 中重复记录；系统不加锁、不推断唯一归属。AI 可以读写工作地址外绝对路径，但这些变更不进入当前修改记录与回退能力。AI 或用户在没有受控工具写回和 terminal 命令窗口时产生的外部变化不归入任何 AI Run。基线内容按 SHA-256 保存；文本 Diff 根据不可变的修改前后内容生成并缓存。回退使用修改前对象，不反向计算 Diff。
- 验收：
  - `WB-APPLY-003-AC1` 未发生后续修改时，回退恢复写回前 checkpoint，记录状态变为 `reverted`。
  - `WB-APPLY-003-AC2` 新建文件回退时删除 AI 新建目标文件。
  - `WB-APPLY-003-AC3` 回退成功后，右侧修改的文件工作区应刷新记录状态；普通文本历史 diff 继续保留并标记“已回退”或“已删除”，避免丢失本次修改记录。
  - `WB-APPLY-003-AC4` 终端通过 Shell、Python、Node 或其他程序造成的文件变化均由 Run 结束扫描捕获；终端修改的文本可生成普通行级 Diff，终端直接修改的 Docx 等二进制文件只提供修改前/修改后版本，不伪造语义审阅标记。
  - `WB-APPLY-003-AC5` Docx 工具修改保存 before 和 Review Docx；Review Docx 继续由现有 Docx Renderer 渲染并保留段落、表格、图片、字体和页面结构。
  - `WB-APPLY-003-AC6` PPT 修改记录使用 Diff Manifest v4，在审核模式提供固定的修改前后页面快照；旧 v3 记录明确提示格式过期，正式 PPT 不受影响。Excel 专用工具修改 `xlsx` 时在审核模式提供单元格边框标记，并可切换到预览模式。终端产生的二进制文件变化只提供修改前/修改后版本，不显示模式切换；终端产生的 UTF-8 文本变化按普通文本规则处理。
  - `WB-APPLY-003-AC7` 图片生成记录直接预览最终图片并提供回退，不显示不存在的图片 Diff；更新图片回退后恢复首次生成前的文件，新建图片回退后删除目标文件。
  - `WB-APPLY-003-AC8` Docx Review 只展示本次 Run 初始文档到最终净稿的净变化；同一原始节点连续修改只显示一次原始红色版本和一次最终绿色版本，中间稿不得出现，改回原内容不产生修改记录；本轮新增节点只显示最终仍存在的绿色版本，新增后删除不产生净变化。
  - `WB-APPLY-003-AC9` 专用写工具的成功记录以工具原子写入结果、checkpoint 和前后 checksum 为权威依据；通用扫描匹配到同一路径时可补充快照，未匹配时不得否定已被校验的真实写入。

#### WB-APPLY-004 后续修改后的强制回退

- 系统行为：若回退时检测到当前文件与 AI 写回后的 checksum 不一致，先提示用户该文件已被后续修改，继续回退会丢失这些内容；用户确认后仍允许强制回退。
- 验收：
  - `WB-APPLY-004-AC1` 点击任何可回退记录时先展示统一确认框“回退这次修改？”，说明文件将恢复到这次修改发生前的状态；用户确认后才发起回退。
  - `WB-APPLY-004-AC2` 检测到后续修改时，在统一确认之后继续展示“仍然回退这次修改？”风险确认；用户确认强制回退后，系统恢复 checkpoint 或删除新建文件。
  - `WB-APPLY-004-AC3` 强制回退完成后，右侧修改的文件工作区应刷新为最新记录状态，并让用户能确认回退已经生效。

#### WB-APPLY-005 同一轮多个修改记录入口保留

- 系统行为：同一轮任务若实际修改多个文件，assistant turn 保留本轮全部修改入口；点击入口后打开或切换到对应文件 Tab。每个入口直接展示该文件本次真实修改与删除数量，无需点击即可见，切换伙伴后依然保持。文件入口超过 3 个时列表默认折叠，只展示前 3 个，底部提供“显示剩余 N 个文件”展开入口，展开后该入口变为“收起文件”；头部总数始终展示完整数量。Assistant 最终回答只在修改文件区域展示文件入口。
- 验收：
  - `WB-APPLY-005-AC1` 同一轮任务生成的多个修改记录都会出现在同一 assistant turn 的修改的文件列表中。
  - `WB-APPLY-005-AC2` 点击不同修改记录入口时，右侧会加载对应修改记录；有 diff 预览的记录展示对应预览稿，而不是按源文件跳到最新轮次。
  - `WB-APPLY-005-AC3` 同一轮多文件修改的全部入口保留在 assistant turn 列表中，不因切换当前文件而丢失其他文件的检查或回退入口。
  - `WB-APPLY-005-AC4` 修改记录入口未点击时即展示真实非零的修改/删除数量；切换伙伴再切回后不点击仍保持真实数量，不重置为 0。
  - `WB-APPLY-005-AC5` 文件入口超过 3 个时默认只展示前 3 个，列表底部展示“显示剩余 N 个文件”（N 为剩余数量）；点击后展示全部入口，底部入口变为“收起文件”，再次点击恢复折叠；头部文件总数不受折叠影响。

### 8.9 PPT 创建、编辑与审核模式

#### WB-PPT-001 AI 创建和编辑 PPT

- 系统行为：AI 可通过 PPT 读写能力创建和编辑 pptx；写回成功后正式文件立即可读，同一次任务对同一路径聚合为一条修改记录。页面与元素级写入细节由 AI tool 回归覆盖。
- 验收：
  - `WB-PPT-001-AC1` AI 可自行新建 pptx，不依赖用户点击新建入口。
  - `WB-PPT-001-AC2` 新建演示文稿或插入页面时，单次调用只允许一张页面的元素规格，不接受页面数组或 HTML。
  - `WB-PPT-001-AC3` 文本、形状、线条、图片、表格、图表和公式按支持类型转换，不把整页默认导出为截图。
  - `WB-PPT-001-AC4` AI 可继续编辑已有页面和元素。
  - `WB-PPT-001-AC5` 公式由 LaTeX 渲染为 SVG；公式整体可移动和缩放，内部字符为只读内容。
  - `WB-PPT-001-AC9` 一次编辑失败时，正式文件保持调用前状态。
  - `WB-PPT-001-AC10` 编辑返回成功时，其他程序已经可以读取最终 pptx。

#### WB-PPT-002 PPT 单页左右审核模式

- 系统行为：用户打开 pptx 修改记录后，主区域左侧显示当前页修改前画面，右侧显示同一页修改后画面；最右侧显示缩略图。点击缩略图或滚动时左右同步切页。主区域支持滚轮缩放与拖拽平移；未操作时底部居中显示「滚轮缩放 / 拖拽平移」轻提示，用户执行任一缩放或拖拽操作后永久隐藏。审核内容严格来自同一 Run 首个 baseline 与最终 PPT 的净变化；SVG 只用于展示，不决定变化语义。
- 验收：
  - `WB-PPT-002-AC1` 主区域按左侧修改前、右侧修改后一次各显示一页。
  - `WB-PPT-002-AC2` 缩略图支持只看变化页和查看全部页两种图标模式，默认只看变化页。
  - `WB-PPT-002-AC3` 新增、修改、移动页使用绿色标记，整页删除使用红色标记，不显示“修改几页”等文字差异说明；已有页面只删除内部元素时，该页仍按修改显示绿色。
  - `WB-PPT-002-AC4` 新增页左侧为空；删除页右侧为空。
  - `WB-PPT-002-AC5` 点击缩略图或滚动后，左右主区域与当前缩略图保持同步。
  - `WB-PPT-002-AC6` `+N` 统计最终保留的新增、修改和移动单位，`-N` 统计最终保留的删除单位。新增整页为 `+1`、删除整页为 `-1`、移动整页为 `+1`，整页增删不重复统计内部元素。
  - `WB-PPT-002-AC7` 已有页面内新增元素为 `+1`、删除元素为 `-1`、修改或移动元素为 `+1`；同一元素同时修改内容、样式、位置、大小或层级只计一次。页面移动并修改两个元素时为 `+3`。
  - `WB-PPT-002-AC8` 插入或删除页面造成的自然页码变化不算移动；元素增删或置顶造成其他元素层级编号自然变化时，也不得把其他元素误算为修改。
  - `WB-PPT-002-AC9` A→B→A、移动后移回、新增后删除等零净变化不生成记录；原元素修改后删除只计 `-1`，新页面继续修改仍只计 `+1`。
  - `WB-PPT-002-AC10` 审核模式使用固定 Diff 快照，预览模式使用干净的正式 PPT；正式文件不得包含 Diff 标记，回退按修改前 bytes 恢复。
  - `WB-PPT-002-AC11` 主区域滚轮缩放与拖拽平移可用；未操作时底部居中展示「滚轮缩放 / 拖拽平移」提示，用户执行任一缩放或拖拽操作后该提示永久隐藏。

### 8.10 Excel 读取、编辑与审核模式

#### WB-EXCEL-001 AI 读取和编辑 Excel

- 系统行为：AI 可通过 Excel 读写能力读取工作簿并创建或编辑 `xlsx`；读取支持 `xlsx`、`xlsm`、`xltx`、`xltm`，写入只支持 `xlsx`。Excel 不进入本地知识库单元格内容索引，只索引文件名、文档标题与工作表名等元数据。产品侧 Diff / 修改记录 / 回退由系统维护。读写 type 与字段契约由 AI tool 回归覆盖。
- 验收：
  - `WB-EXCEL-001-AC3` 单次编辑失败时不产生部分写入；文件在连续编辑之间被外部修改时拒绝覆盖并提示冲突；无实际变化时不生成修改记录。
  - `WB-EXCEL-001-AC4` `xlsm`、`xltx`、`xltm` 可以读取但不能写回；拒绝写入时源文件保持不变，并明确说明是为了避免丢失宏或模板信息。
  - `WB-EXCEL-001-AC5` Excel 创建或编辑成功后，正式文件中的值与公式可被其他程序立即读取，正式文件不包含审核模式使用的红绿边框。
  - `WB-EXCEL-001-AC6` 新建工作簿只包含显式创建的 Sheet，不自动生成 `Sheet1`；最终至少保留一个 Sheet，删除最后一个 Sheet 必须失败。
  - `WB-EXCEL-001-AC7` 新增已存在的 Sheet、删除不存在的 Sheet、重命名到已存在名称都必须失败，且不写入部分结果。

#### WB-EXCEL-002 Excel 单网格审核模式

- 系统行为：用户打开普通 Excel 文件或 `xlsx` 修改记录后，前端使用成熟的 Univer 工作簿组件分别预览正式 XLSX 和 Diff XLSX，不自行解析 OOXML 生成 HTML 表格。Excel 预览是只读预览：不允许编辑单元格内容，但允许切换工作表、滚动、缩放和拖动列宽查看内容。Diff 只展示本次 Run 首个 baseline 到最终工作簿的净变化；操作记录只用于识别 Sheet 和行的结构身份，不直接累加为最终差异。新增和修改单元格使用绿色中等粗细边框，删除或清空的单元格在 Diff XLSX 中保留修改前值并使用红色中等粗细边框。用户不使用 PPT 的修改前/修改后左右画面对比。
- 验收：
  - `WB-EXCEL-002-AC1` 预览模式展示正式净工作簿，审核模式展示基于首次写入前基线生成的差异工作簿；两者均为只读预览，且均可切换工作表、滚动、缩放和拖动列宽。
  - `WB-EXCEL-002-AC2` 新增和修改单元格显示绿色中等粗细边框，删除或清空的单元格显示红色中等粗细边框并保留修改前值；未变化单元格不增加差异边框，正式工作簿也不带差异边框。
  - `WB-EXCEL-002-AC3` 同一 AI Run 对同一路径连续编辑后只保留一条有效修改记录，差异始终相对该 Run 首次写入前基线计算。
  - `WB-EXCEL-002-AC4` 回退已有 `xlsx` 时恢复写入前原始 bytes；回退新建 `xlsx` 时删除目标文件，修改记录状态同步更新。
  - `WB-EXCEL-002-AC5` Diff XLSX 中新增 Sheet 的标签为绿色，删除 Sheet 以修改前完整内容恢复到 Diff XLSX 的原位置并将标签标为红色；恢复内容包括单元格值、样式、行高、列宽和合并单元格；正式 XLSX 不带这些差异标记。
  - `WB-EXCEL-002-AC6` 暂不定义移动 Sheet 位置的 Excel diff action；如果未来新增 `move_sheet`，需要单独定义差异语义。
  - `WB-EXCEL-002-AC7` 插入或删除行时按逻辑行对齐生成联合预览：新增行只标绿最终新增内容，删除行在原逻辑位置保留旧内容并标红；其他仅因插入或删除而改变地址的原有行不得产生红绿边框，预览末尾不得生成重复行。
  - `WB-EXCEL-002-AC8` 同一 Run 中单元格、行或 Sheet 被多次修改时只保留最终净变化；改回 baseline、插入后删除、新增 Sheet 后删除均不产生红绿标记或变更计数；原始 Sheet 多次重命名只保留最终名称和一次重命名状态，不复制整张 Sheet 作为删除加新增。

### 8.12 应用内文本编辑

#### WB-EDIT-001 Markdown 与普通文本应用内即时渲染编辑

- 系统行为：右侧面板打开真实本地 `.md`/`.markdown` 文件时，使用即时渲染（IR）编辑方式——文件内容渲染为排版预览，点击任意位置直接编辑文字；光标进入链接、加粗、行内代码等 markdown 语法元素时，该元素局部露出 markdown 源可编辑。标题元素前不展示 H1/H2 等标题级别标签（Vditor 默认 `::before` 标签）与 `#`/`##` 等标题源标记，标题不加额外装饰（无下划线），保持沉浸式排版；编辑区始终撑满右侧面板，不出现右侧灰色残留。编辑器不展示任何操作按钮、工具栏或交互栏，用户打开即可直接编辑。打开 `.txt` 及其他严格 UTF-8 普通文本（如 `.log`、`.json`、代码、配置文件、无扩展名文本）时，使用与纯文本预览一致的纯文本编辑框直接编辑；纯文本内容（编辑态与只读预览态）每行前显示行号，行号随内容同步滚动。AI 修改记录的审核/预览态、预览弹窗以及 PDF/DOCX/PPTX/XLSX/图片等其他格式保持只读。
- 保存：不做显式保存按钮与"未保存"提示；每次内容变更后防抖（约 400ms）自动原子写入磁盘（`write-text-file`，临时文件 + rename），并对内容做 UTF-8 合法性校验；纯文本保存时保留原文件的换行符风格（CRLF/LF）与 UTF-8 BOM。自动保存为纯覆盖，不做冲突提示。
- 外部修改：磁盘内容与编辑器最后成功写入的内容一致时不响应；空闲（无未保存改动）时检测到外部修改自动重载最新磁盘内容；编辑中存在未保存改动时不打断编辑，下一次自动保存覆盖外部内容。
- 范围边界：应用内编辑不生成 AI 修改记录、不进入回退体系；不限定只能编辑已添加工作地址内的文件，任意本地真实文件均可编辑。
- 验收：
  - `WB-EDIT-001-AC1` 打开真实 `.md` 文件后直接进入即时渲染编辑态，无工具栏/操作按钮；点击任意位置光标落下，输入内容实时渲染并反映在编辑区。
  - `WB-EDIT-001-AC2` 光标进入链接等 markdown 语法元素时，该元素局部露出 markdown 源可编辑；离开后恢复渲染态。
  - `WB-EDIT-001-AC3` 打开 `.txt`、`.json`、代码等严格 UTF-8 文本后直接进入纯文本编辑框，输入与保存内容一致，不出现 markdown 化改写。
  - `WB-EDIT-001-AC4` 编辑后无需点击保存，约 400ms 内自动落盘，磁盘内容更新为编辑结果；界面不展示保存按钮或"未保存"标记。
  - `WB-EDIT-001-AC5` 空闲时外部保存文件自动重载最新内容；编辑中存在未保存改动时外部保存被下次自动保存覆盖，不弹出冲突提示。
  - `WB-EDIT-001-AC6` 纯文本文件保存后保留原换行符风格（CRLF/LF）与 UTF-8 BOM。
  - `WB-EDIT-001-AC7` AI 修改记录审核/预览态与预览弹窗中的 Markdown 仍为只读渲染，不进入编辑态。
  - `WB-EDIT-001-AC8` 应用内编辑保存不产生 AI 修改记录。
  - `WB-EDIT-001-AC9` 打开 `.md` 后编辑区撑满右侧面板（无右侧灰色残留）；标题前不显示 H1/H2 等标题级别标签与 `#`/`##` 等标题源标记，标题无下划线等额外装饰；拉宽窗口后页面不白屏、编辑态保持。
  - `WB-EDIT-001-AC10` 纯文本内容（编辑态与只读预览态）每行前显示从 1 开始递增的行号，行号随内容滚动同步对齐。

#### ST-RUN-002 伙伴列表刷新

#### ST-RUN-003 程序关闭错过不补跑
