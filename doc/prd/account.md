# Account PRD

## 1. 产品目标

用户可以选择登录、使用馆长模型并查看余额；原有免费、自定义及本地工作能力继续免登录使用。桌面提供账号概览和常用入口，官网承载充值、账单、Token 用量和费用明细。

## 2. 范围与文档分工

- 本文维护国内桌面账号菜单、设置账号页、浏览器登录授权、登录状态、退出和官网跳转。
- 模型连接由 [Settings PRD](settings.md) 维护，模型选择和任务交互由 [Workbench PRD](workbench.md) 维护，不在本页重复定义。
- 身份协议引用官网后端的 [身份规范](https://github.com/Yoan98/ncurator-official/blob/master/doc/backend/identity.md)，资金规则引用 [资金规范](https://github.com/Yoan98/ncurator-official/blob/master/doc/backend/accounting.md)，不在桌面复制记账及退款算法。

## 3. 需求明细

### ACC-ACCESS-001 可选账号与原有能力

- 系统行为：启动不强制登录或充值。未登录、退出、登录失效、未充值或余额不足，不因此禁止原有免费和自定义能力；用户自带 Key 仍调用自己配置的服务，不计入馆长余额消费。
- 系统行为：登录或退出不删除、上传或迁移已有伙伴、聊天、模型连接及本地资料，不自动将原连接或同名型号替换成馆长模型。
- 验收：`ACC-ACCESS-001-AC1` 未登录及账号、余额受限时原有路径仍可使用；`ACC-ACCESS-001-AC2` 已有配置与本地数据保留；`ACC-ACCESS-001-AC3` 自带 Key 调用不产生平台消费或被替换成馆长调用。

### ACC-ENTRY-001 左侧账号菜单

- 用户操作：点击左侧底部头像或账号入口展开菜单，点击外部或按 Escape 收起。账号使用默认头像和脱敏手机号。
- 系统行为：已登录菜单展示账号标识和余额，提供账户余额、充值、账单与用量、设置、帮助和退出入口。账户余额直达设置账号页；充值和账单与用量打开国内官网对应页面；帮助沿用官方入口。未登录时提供登录、设置和帮助，不展示账号资金。
- 验收：`ACC-ENTRY-001-AC1` 左下入口及菜单展开、收起和键盘操作可用；`ACC-ENTRY-001-AC2` 已登录菜单与跳转符合上述分工；`ACC-ENTRY-001-AC3` 未登录可登录、进入设置和帮助，不展示其他账号数据。

### ACC-PAGE-001 设置账号页

- 用户操作：从设置导航的“账号”或账号菜单进入同一账号页。
- 系统行为：已登录展示脱敏手机号、可完整复制的官网用户编号、可用余额，以及充值、账单与用量和退出当前桌面账号的操作。余额状态与刷新规则见下文。
- 系统行为：未登录展示登录入口，说明免费及自定义模型可以继续使用。官网承担详细交易和用量查询，桌面不重复建设完整账单。
- 验收：`ACC-PAGE-001-AC1` 两个入口到达同一账号页；`ACC-PAGE-001-AC2` 本人手机号、用户编号及复制行为正确；`ACC-PAGE-001-AC3` 余额来源正确，失败不伪装为零或串用他人数据；`ACC-PAGE-001-AC4` 未登录状态明确，不阻断原有能力。

### ACC-BALANCE-001 金额与资金状态展示

- 系统行为：账号菜单及账号页主数字显示可用余额，默认人民币两位小数；小于一分的非零金额使用小额提示，欠费保留方向，不显示成零。账号页提供精确金额查看及复制，格式遵循官网后端 [金额展示](https://github.com/Yoan98/ncurator-official/blob/master/doc/backend/accounting.md#金额展示)。
- 系统行为：有资金占用时补充当前余额和处理中金额，区分模型预占及退款处理中，预占不当作已消费；已接收费用待落账时显示“费用结算中”。欠费显示补足提示，免费及自定义能力不因此受限。
- 系统行为：首次未取得金额显示“—”；读取失败保留本人上次成功值并标记“待更新”，不当作零余额或退出登录。
- 验收：`ACC-BALANCE-001-AC1` 默认两位，精确值可查看复制，显示不改变实际费用；`ACC-BALANCE-001-AC2` 真零、非零小额及欠费可区分；`ACC-BALANCE-001-AC3` 当前、可用及两类占用含义清楚，预占不显示为已消费；`ACC-BALANCE-001-AC4` 失败、结算中及欠费状态正确且不阻断原有免费、自定义能力。

### ACC-BALANCE-002 按需刷新与旧响应隔离

- 系统行为：登录成功或恢复有效登录时读取余额；打开账号菜单、账号页及回到前台按需刷新，同一账号最近 30 秒取得的结果可复用，相同在途读取合并。账号页提供手动刷新，从官网充值操作回到桌面时立即读取，不受普通复用窗口限制。
- 系统行为：每次馆长请求完成费用处理后使用返回的余额更新；缺少确认时查询原请求或补读余额，不重发模型。其他设备变更在下次读取体现，不做常驻轮询。
- 系统行为：同一账号及展示上下文中，较旧钱包版本不能覆盖新金额；退出、更换账号或手动强制刷新时重建上下文，旧响应不能覆盖。资金状态按后端确认结果显示，展示缓存不代替鉴权、实时预算或资金恢复。
- 验收：`ACC-BALANCE-002-AC1` 登录及恢复时取得余额；`ACC-BALANCE-002-AC2` 普通查看遵守 30 秒复用及合并；`ACC-BALANCE-002-AC3` 手动刷新及充值返回立即读取；`ACC-BALANCE-002-AC4` 逐次结算复用快照，缺失可补读，无重复执行、常驻轮询或自动补账；`ACC-BALANCE-002-AC5` 旧版本、旧账号及旧上下文响应不覆盖新状态。

### ACC-LOGIN-001 系统浏览器登录与授权

- 用户操作：从账号菜单、账号页或馆长模型的登录引导打开系统浏览器，在国内官网完成手机号或微信登录及桌面授权。
- 系统行为：完成有效授权并可靠保存凭证后显示登录成功。取消、拒绝、过期及兑换失败显示实际结果，允许重新授权；重复及迟到回调不产生错误登录。一次性兑换结果不明时重新授权，重试与回跳校验遵循官网身份协议。
- 系统行为：访问及持久登录凭证不出现在回跳 URL、菜单、界面错误或日志中；持久凭证按系统凭据存储规则保存。
- 验收：`ACC-LOGIN-001-AC1` 使用系统浏览器及国内授权入口；`ACC-LOGIN-001-AC2` 有效授权后显示对应账号；`ACC-LOGIN-001-AC3` 异常不伪装为成功，可重新发起；`ACC-LOGIN-001-AC4` 错误或重复回跳不生成错误登录，凭证不泄漏。

### ACC-SESSION-001 独立登录与退出

- 系统行为：正常重启恢复有效登录，访问凭证按需续期。暂时断网或超时保留账号并反馈网络状态；无法恢复有效登录时引导当前桌面重新授权。
- 系统行为：服务端确认当前会话撤销时提示重新授权，不推断账号被盗或退出其他设备；旧会话的撤销不影响后来建立的新登录。
- 系统行为：退出网页只影响网页，退出当前桌面账号只撤销本桌面登录，其他设备保持各自状态。真正退出应用沿用现有运行收尾，所有类型任务都随应用退出而中断，但不因此撤销登录；仅关闭窗口是否结束应用沿用现有平台行为。
- 系统行为：登录期限以服务端为准，纯本地工作、自定义直连及后台保活不延长期限。过期、撤销或封禁后不能新开馆长调用；重新授权使用原账号与钱包，旧任务由用户手动继续。网页仍有效时只需确认桌面授权，否则先网页登录。
- 验收：`ACC-SESSION-001-AC1` 重启及按需续期符合身份协议；`ACC-SESSION-001-AC2` 网页和不同桌面的退出范围独立；`ACC-SESSION-001-AC3` 失效后不能新开馆长执行，本地数据及免费、自定义能力保留。

### ACC-SESSION-002 账号变化与在途运行

- 用户操作：有使用当前账号的馆长任务仍运行、等待审批或用户协助，或有尚未执行的馆长追加消息时，退出登录先提示“退出将停止这些任务”，确认后停止并退出；取消确认不改变账号或任务。没有这些任务时直接退出。免费和自定义任务不依赖业务登录，不因退出账号而停止；仅排队了馆长追加消息的免费或自定义 run 保持执行，该馆长接续不再自动启动。
- 系统行为：确认会话失效或账户受限时停止对应馆长任务、子任务及待执行接续，保留本地内容。正常访问凭证续期及暂时网络失败不误停止；已受理或结果不明的调用不重新执行，查询规则见 Workbench。
- 系统行为：更换账号通过退出后重新登录完成。每次馆长运行和已经提交的馆长追加消息固定提交时的业务用户及桌面登录会话；接续和子任务继承其归属，不读取后来全局登录账号来继续付费。重新登录后不自动恢复旧任务或自动重发旧消息，由用户按现有继续方式再次操作。
- 系统行为：旧调用费用仍由后端在原账号结算。退出后到达的完成确认、余额和登录回调不能恢复旧任务或覆盖新账号。
- 验收：`ACC-SESSION-002-AC1` 退出登录的确认、取消及停止范围正确，免费、自定义和其他设备不受影响；`ACC-SESSION-002-AC2` 确认失效停止相应馆长任务及待执行接续，正常换新和暂时网络失败不误退出；`ACC-SESSION-002-AC3` 更换账号不自动恢复旧任务，提交、接续和子任务不改扣新账号；`ACC-SESSION-002-AC4` 旧回调不覆盖或复活账号，已有费用留在原账号。

### ACC-WEB-001 官网账户功能跳转

- 系统行为：充值、账单及 Token 明细在系统浏览器打开国内官网对应页面，官网自行校验网页登录；桌面访问及持久登录凭证不能拼入 URL。
- 系统行为：退款说明和邮件申请方式只在官网提供，桌面不新增退款菜单、申请表或邮件发送流程。用户编号与官网本人账号一致。
- 验收：`ACC-WEB-001-AC1` 充值及明细跳转目标正确；`ACC-WEB-001-AC2` 不泄漏桌面凭证，不假定网页已登录；`ACC-WEB-001-AC3` 退款留在官网，用户编号可供客服定位；`ACC-WEB-001-AC4` 海外包不展示国内账号、钱包和充值入口。

## 4. 非目标

- 不提供手机号更换、账号注销、邮箱绑定或独立资料编辑流程。
- 不在桌面建设会员套餐、积分、完整账单或退款操作。
- 不因增加账号而建设聊天和本地工作资料的云端同步。
