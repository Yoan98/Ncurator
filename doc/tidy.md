# 文档、测试与代码 Tidy 流程

## 1. 流程

先审查并列出要处理的内容及验证方式，经确认后执行整理，最后复验并记录结果。

- 代码允许重构，但前后功能必须一致：输入输出、校验规则、状态流转、副作用和异常处理不变。死代码、兼容残留须确认无静态或动态消费方后删除。
- 禁止修改提示词及其生成源，包括 prompt 文案、ToolSpec、schema（字段、约束、description / describe）、模板与生成 / 渲染代码；“等价优化”也不能作为修改这些内容的理由。
- 发现需求、实现或测试不一致时，只报告问题，修复单独处理；不得为测试或静态检查通过修改业务行为、放宽断言。
- 修改代码后必须执行并通过相关测试，确认功能等价后才能完成本节点。
- 不得改写已发布 SQLite migration 锁清单内的历史 migration。

## 2. 审阅清单

### 2.1 文档 ↔ 实现对齐

- [ ] 核对 [AGENTS 文档索引](../AGENTS.md#1-文档引用)是否完整，路径和阅读条件是否有效。
- [ ] 对照代码和实际运行入口，核对文档描述的行为、模块职责和使用方式。

### 2.2 文档健康

- [ ] 按[文档准则](doc-guidelines.md)检查归属、结构、链接和命令。将重复规则收回所属文档，移除过期说明和一次性记录。
- [ ] 长章节难以定位内容时，按主题或职责重新组织。

- [ ] 临时句、过期备注、半截迁移残留、无消费方的重复段落。
- [ ] 同一事实多处拷贝且已漂移 → 收敛到单一真相源。
- [ ] 无价值，无意义的语句。
- [ ] 标题与内容不符的。
### 2.3 PRD ↔ 测试计划对齐

- [ ] 遍历仓库现有 PRD，按验收行为核对对应测试计划、用例断言和执行入口。
- [ ] 分别核对用例关联、实际运行状态和人工验收证据。一个编号包含多个行为时，逐项检查覆盖。

### 2.4 测试分层与清理

- [ ] 按[测试规范](test.md)核对分层及实际选中的用例，确认发布必验项有通过证据。
- [ ] 迁移测试时保留仍有价值的断言，清理重复用例和只验证退役实现的用例。

### 2.5 代码整洁

| 工具 | 用途 |
|------|------|
| `pnpm knip` | 失效文件、错误 import、未使用依赖（`knip.json`） |
| `tsc --noEmit` / eslint | 未使用局部量、未使用 import |

- [ ] 检查静态与动态引用，清理死代码、无用依赖和历史兼容分支。
- [ ] 按职责整理文件，合并重复实现，简化分支、类型和字段。
- [ ] 优化文件与代码组织。
- [ ] 类型禁止使用非必要的 `any` 与 `unknown`。
- [ ] 字段遵循最小必要原则。
