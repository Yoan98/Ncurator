# 文档与测试 Tidy 流程

本文件只定义周期性整理流程，不包含脚本或自动修改逻辑。执行 Tidy 时先审计、汇总并等待用户决策；未获得决策前，不删除、合并或改写项目文档和测试用例。

## 1. 对齐文档与实现

逐份检查项目文档（架构、PRD、测试计划、测试规范、发布文档等）与实际代码、配置、脚本和目录结构：

- 标出实现已经变化但文档未同步的内容。
- 标出文档仍描述、实现已经移除的内容。
- 标出文档之间互相矛盾或范围重复的内容。

## 2. 整理 PRD、测试计划和测试用例

分析 PRD、对应测试计划和全部实际测试用例，提出明确的处理建议：

- 多余的文档或用例：删除建议。
- 目标相同、断言重复的内容：合并建议。
- PRD 已有要求但没有计划或用例覆盖的内容：新增建议。
- 归属、名称、测试类型、How、Oracle 或 Not 不准确的内容：调整建议。

## 3. 对齐 Settings / Workbench

对 Settings 和 Workbench 分别完成一条完整链路核对：

`PRD 功能点 → 测试计划 case → 实际测试 case`

核对功能点、验收编号、case ID、测试类型、覆盖范围和关键 Oracle 是否一致。Settings 与 Workbench 的功能测试只允许 E2E；AI 架构（包括工具）只在 AI backend 测试中覆盖；Unit 只补足前述范围之外的 backend 函数、类和底层逻辑。

## 4. 文档检验

- architecture文档只需要保留总架构设计信息，禁止过细的信息进入。
- test，database,release,tidy,ui-style文档检查看是否有多余与需要合并的内容，骨架设计不能动。
- test规则检测，检测对应测试代码设计是否符合文档规范。


## 5. 汇总与决策

完成审计后输出结果现状，建议。
