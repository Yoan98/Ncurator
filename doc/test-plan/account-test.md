# NCurator-Desktop Account 测试计划

## 1. 总体目标

验证 [Account PRD](../prd/account.md) 的账号入口、授权、概览、独立退出和官网跳转，并保证原有免费、自定义及本地工作能力不被付费功能接管。通用规则遵循 [测试规范](../test.md)。

## 2. Suite 与验证边界

| Suite | 范围 |
| --- | --- |
| access | 原有免登录路径及本地数据保留 |
| authorization | 浏览器授权、续期及独立退出 |
| overview | 菜单、账号页、余额和官网跳转 |

正式 case 归入 `tests/case/account/<suite>/<caseId>.e2e.test.ts`，全部通过真实 Electron UI 及生产 Main、IPC 和服务执行，不直接写登录态、余额、模型选择或凭据存储。

使用独立测试 API 环境，外部认证、支付及模型计量在服务边界提供受控测试能力，客户端仍走完整登录、授权和请求流程。余额通过测试充值形成，异常使用过期、撤销、错误回跳或服务停机；真实短信、微信及支付另做联调。

原有模型实际调用使用 live，不能用受控模型输出证明 AI 完成真实任务。本域验证桌面账号行为及接口结果；模型选择和一般任务交互见 Workbench 计划。

## 3. 回归清单

### access

#### anonymous-existing-usage

- 测试类型：`e2e / live`
- What：原有免费及自带 Key 路径继续免登录使用，登录变化保留已有配置和资料。
- Why：新增账号可能成为全局门禁，或将旧连接替换成平台付费。
- How：在隔离本地目录通过真实 UI 配置自带 Key、创建伙伴及资料，未登录分别使用免费和自定义模型完成简单请求；经正式登录和退出后再次读取原配置。零余额下使用原连接，检查官网隔离库无馆长消费。历史配置升级的 fixture 验证随模型及存储变更补充，不直接改状态代替操作。
- Oracle：未登录及零余额仍可用原路径，覆盖 `ACC-ACCESS-001-AC1`；登录变化保留配置和本地内容，不替换原连接、不产生平台消费，覆盖 `ACC-ACCESS-001-AC2/AC3`。

### authorization

#### browser-login-outcomes

- 测试类型：`e2e`
- What：系统浏览器授权及成功、取消和无效回跳的处理。
- Why：网页成功不等于桌面已兑换登录，错误回跳可能造成串号。
- How：从桌面真实入口打开官网完成登录和授权，覆盖成功、取消、过期、错误 state 及重复回跳。用网络代理丢弃已处理的首次兑换响应，核对重新授权流程；延迟旧回调至取消、退出或新登录后交付，检查账号及会话。
- Oracle：系统浏览器及目标正确，凭证保存成功后显示对应账号，覆盖 `ACC-LOGIN-001-AC1/AC2`；重复回调合并，一次性兑换结果不明可重新授权，异常不显示成功，凭证不泄漏，覆盖 `ACC-LOGIN-001-AC3/AC4`；旧回调不覆盖当前登录，覆盖 `ACC-SESSION-002-AC4`。

#### independent-sessions-and-restart

- 测试类型：`e2e`
- What：登录恢复、按需续期、独立退出及失效后的使用边界。
- Why：共用会话或全局清理会造成设备互相退出、授权复活或本地数据丢失。
- How：通过授权建立网页和两个独立桌面会话，退出应用后重启，核对登录恢复且原任务不自动执行。访问凭证到期后触发刷新，丢弃已成功处理的刷新响应，检查协议恢复及持久化后重启；恢复失败时重新授权。暂停后端后恢复，核对网络失败不误退出。分别退出网页、当前桌面或经官网撤销设备，检查各会话范围、本地数据及重新授权后的原账号和钱包。
- Oracle：重启恢复、按需续期、响应丢失恢复及新凭证持久化正确，旧响应不复活会话，覆盖 `ACC-SESSION-001-AC1`；网页与各桌面独立退出，覆盖 `ACC-SESSION-001-AC2`；明确失效后不能新开馆长调用，重新授权保留原账号和钱包，不恢复旧任务，本地数据和免登录能力保留，覆盖 `ACC-SESSION-001-AC3`。

#### account-change-during-runs

- 测试类型：`e2e / live`
- What：主动退出、会话失效和更换账号时，馆长任务及旧回调的账号边界。
- Why：读取全局当前账号可能将旧任务或待执行接续转到新账号扣费，过宽停止会误伤免登录任务。
- How：通过真实 UI 在不同伙伴启动馆长、免费及自定义任务，馆长使用独立测试 API 环境，外部代理仅延迟或中断真实请求及响应，不伪造模型输出或桌面事件。给馆长任务提交追加消息并触发子任务，分别覆盖运行、等待审批或协助期间的退出确认取消、确认退出及后端会话撤销；另在免费 run 中提交馆长追加消息，检查退出只取消尚未执行的馆长接续，当前免费 run 继续。正常访问凭证换新和短暂断网后再次观察。正式登录另一测试账号，延迟交付先前已产生的真实完成确认，核对调用接口及账号归属；其他有效设备也保持调用用于核对停止范围。一般模型切换在 Workbench 计划验证，不以模型回答自报身份作为扣费依据。
- Oracle：确认取消不退出或停止，确认退出仅停止相应馆长任务，免费、自定义和其他设备继续，覆盖 `ACC-SESSION-002-AC1`；真正会话失效停止馆长子任务及待执行接续，正常换新或断网不误退出，覆盖 `ACC-SESSION-002-AC2`；新账号登录不自动恢复旧任务，原提交、接续、子任务及费用不换号，覆盖 `ACC-SESSION-002-AC3/AC4`；旧回调不覆盖新账号或触发执行，调用结果及余额变化仍归属原账号，不以退出免除或重扣。

### overview

#### account-menu-and-page

- 测试类型：`e2e`
- What：菜单、设置账号页、本人标识、余额及异常展示。
- Why：入口不一致、读取失败或残留数据会展示错误账号或误导余额为零。
- How：经正式授权登录后操作头像、设置导航、编号复制、外部点击及 Escape，核对登录前后菜单和页面；余额通过正式充值形成。将 UI 及剪贴板中的用户编号与官网本人账号核对。暂停后端形成读取失败，恢复后重试；
- Oracle：菜单、键盘操作及登录前后范围正确，覆盖 `ACC-ENTRY-001-AC1/AC2/AC3`；两个入口到同一页面，本人手机号、独立对外 `user_no` 和复制一致且无内部用户 ID 泄露，覆盖 `ACC-PAGE-001-AC1/AC2`；失败不伪装为零或他人数据，未登录不阻断原能力，覆盖 `ACC-PAGE-001-AC3/AC4`。

#### balance-display-and-funds-state

- 测试类型：`e2e`
- What：两位默认金额、精确详情、非零小额和资金占用及异常状态。
- Why：金额舍入或预占展示错误会造成少量余额被当成零、预占被误解为已收费，甚至前端错误拒绝可负担的调用。
- How：在独立测试 API 环境，通过充值、馆长调用、退款及异常场景形成普通余额、小于一分、零、欠费、资金占用和结算中状态。检查菜单、账号页及精确金额查看复制，暂停读取服务后重试，与账号余额及调用接口结果核对。
- Oracle：默认两位且精确值一致，显示不改费用，覆盖 `ACC-BALANCE-001-AC1`；真零、非零小额及欠费区分，覆盖 `ACC-BALANCE-001-AC2`；当前、可用及占用正确，预占不当成消费，覆盖 `ACC-BALANCE-001-AC3`；未取得、失败、结算中及欠费反馈正确，原有免费、自定义不新增门禁，覆盖 `ACC-BALANCE-001-AC4`。

#### balance-refresh-and-ordering

- 测试类型：`e2e`
- What：事件刷新、30 秒复用、逐次结算快照以及旧响应防覆盖。
- Why：多余轮询增加数据库访问，乱序或串号响应可能展示错误余额，断流重放还可能造成重复消费。
- How：通过真实 UI 登录、打开菜单及账号页、前后台切换、手动刷新和官网充值跳转，用实际网络记录及真实等待核对 30 秒窗口和相同请求合并。发起使用受控计量上游的真实馆长调用，检查每次完成确认的资金快照及查询次数，不以固定输出证明 AI 任务质量。网络交付控制仅延迟或丢弃真实响应，不改写响应内容，覆盖新版本先到、原完成确认缺失、退出后旧响应到达及重新登录；核对余额、调用状态与任务没有重复变化。
- Oracle：登录恢复获取余额，覆盖 `ACC-BALANCE-002-AC1`；普通查看复用并合并，手动刷新及充值返回立即读取，覆盖 `ACC-BALANCE-002-AC2/AC3`；逐次快照直接更新，缺失仅按原请求读取或补读，不重发模型、不轮询保活或自动补账，覆盖 `ACC-BALANCE-002-AC4`；旧版本、旧账号和重建上下文前的响应被丢弃，覆盖 `ACC-BALANCE-002-AC5`。

#### account-web-navigation

- 测试类型：`e2e`
- What：官网跳转、退款边界及海外功能隔离。
- Why：跳转可能泄漏凭证、假定网页登录或错误显示海外付费入口。
- How：从菜单和账号页打开充值、明细及帮助，核对系统浏览器目标；无网页会话时验证网页登录。检查退款留在官网、用户编号一致，并用海外发行配置确认无国内账号及资金入口。
- Oracle：目标和打开方式正确，不带桌面凭证、不假定网页登录，覆盖 `ACC-WEB-001-AC1/AC2`；退款留官网、编号可定位，海外不展示国内资金能力，覆盖 `ACC-WEB-001-AC3/AC4`。

## 4. 执行与覆盖边界

上述场景尚未实现和执行；实施时补齐 account 领域入口及逐项 AC 证据。

macOS、Windows 分别验证浏览器唤起、回跳、凭据存储及剪贴板；凭据保护不可用时不能明文回退，同一本地目录运行不同发行包时不串用账号或清除个人数据，补证 `ACC-LOGIN-001-AC4`、`ACC-SESSION-001-AC1`、`ACC-ACCESS-001-AC2`、`ACC-WEB-001-AC4`。平台联调按需执行；本计划的证据限于桌面与公开接口行为。
