# NCurator-Desktop AI 重构与迭代规划

本文只记录未来准备推进的 AI 重构与迭代思路，不承载当前正式设计；已实现并确认的内容必须同步到正式文档。

## 1. 使用原则

- 本文档只记录“准备怎么改”，不记录“现在已经是什么”。
- 本文档写法以最新目标为准，不写“旧架构 vs 新架构”的历史对照。
- 某项规划一旦落地并被确认，就应从本文档移除，并同步到对应正式文档。
- 如果某项规划同时涉及目录归位、测试方案或文档入口，也要同步更新 `project-structure.md`、相关测试文档和 `AGENTS.md`。

## 2. 规划模板

新增规划时，建议按下面结构书写：

```md
## 规划主题

### 背景

### 目标

### 范围

### 方案概要

### 影响的文档与代码

### 风险与代价

### 验证方式

### 未决项

### 建议推进顺序
```

## 3. 当前候选规划

### 3.1 `artifacts` 前端消费与展示协议

#### 背景

- 如果后续要让 `artifacts` 被前端直接消费、展示或在 markdown 中稳定引用，就需要先补充对应协议。

#### 目标

- 明确哪些 `artifacts` 需要在 UI 中直接展示。
- 明确 markdown 是否需要稳定引用 `artifacts`。
- 明确前后端对 `artifactRole`、草稿引用与审阅引用的展示边界。

#### 影响的文档与代码

- `doc/ai-design/implementation-spec.md`
- `doc/ai-design/data-definition-and-flow.md`
- UI 相关文档与前端消费实现

#### 未决项

- 哪些 artifact 类型对用户可见，哪些只保留为系统内部引用。
- 是否需要在 `deliveryMarkdown` 中引入稳定的 artifact 引用协议。

#### 建议推进顺序

1. 先明确展示目标与边界。
2. 再补充数据契约与实现规范文档。
3. 最后修改前端消费与展示实现。
