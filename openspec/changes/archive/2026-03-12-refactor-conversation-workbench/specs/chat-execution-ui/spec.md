## MODIFIED Requirements

### Requirement: Render retrieval and artifact panels
聊天执行界面的右侧工作区 MUST 提供可回溯的时间线与检查器，用于展示检索结果、文档片段、工具输出、文件产物、草稿预览和最终提交结果，而不是只保留最新一次工具输出的覆盖式面板。

#### Scenario: 用户回看上一步读取内容
- **WHEN** 用户在一次运行完成后切换到较早的某个读取或检索步骤
- **THEN** 右侧检查器 MUST 展示该步骤对应的文档片段或检索结果，而不会被最新步骤内容覆盖

#### Scenario: 产物与预览在检查器中可交互
- **WHEN** 某个步骤生成了文件产物或草稿预览
- **THEN** 右侧检查器 MUST 展示对应的打开、定位或预览入口，并明确区分预览产物与最终提交产物

### Requirement: Chat 执行界面 MUST 暴露稳定的自动化定位契约
聊天执行界面的关键交互点与关键状态区域 MUST 暴露稳定的自动化定位契约，以支撑 renderer contract 与 renderer e2e 测试；这些定位契约 MUST 覆盖发送入口、模式切换、计划区、时间线列表、审批交互、工作区阻塞交互、右侧检查器、草稿审阅区、逐块确认入口与最终提交入口。

#### Scenario: 自动化定位模式切换与时间线
- **WHEN** 测试在统一工作台中切换 `AI 对话` 与 `纯搜索` 模式，并展开一次运行的时间线
- **THEN** 自动化框架 MUST 能稳定定位模式切换控件、时间线列表和当前选中步骤

#### Scenario: 自动化定位审批与工作区阻塞交互
- **WHEN** 运行时发出 `approval_required` 或 `workspace_required`
- **THEN** 自动化框架 MUST 能稳定定位审批按钮、继续运行入口和阻塞原因区域，而不依赖脆弱的 AntD 内部 DOM 结构

#### Scenario: 自动化定位草稿审阅交互
- **WHEN** 运行完成并进入草稿审阅阶段
- **THEN** 自动化框架 MUST 能稳定定位审阅入口、文档列表、变更单元操作和最终提交按钮

### Requirement: Chat 执行界面 MUST 对关键运行时状态提供确定性测试可观测性
聊天执行界面对模式切换、计划、时间线、右侧检查器、草稿审阅和最终提交的关键状态切换 MUST 具备确定性的测试可观测性，避免测试只能依赖模糊文案猜测界面状态。

#### Scenario: 搜索模式结果与检查器更新
- **WHEN** 用户在 `纯搜索` 模式提交查询并获得结果
- **THEN** 自动化测试 MUST 能确定性判断当前回合处于搜索模式、结果列表已生成且右侧检查器可查看对应结果

#### Scenario: 运行完成进入审阅状态
- **WHEN** 一次 AI 编辑运行结束并产生待确认的草稿修改
- **THEN** 自动化测试 MUST 能确定性判断该回合已从执行态切换到审阅待处理态

#### Scenario: 最终提交结果可观测
- **WHEN** 用户触发最终提交且提交成功或失败
- **THEN** 自动化测试 MUST 能确定性观察到提交结果状态，而不是依赖瞬时消息提示猜测提交是否完成

## ADDED Requirements

### Requirement: 统一会话工作台 MUST 同时承载 AI 对话与纯搜索模式
聊天执行界面 MUST 将 `AI 对话` 与 `纯搜索` 放在同一会话工作台中，用户在两种模式间切换时 MUST 保持同一会话上下文，而不是跳转到独立页面。

#### Scenario: 用户在同一会话中切换搜索与对话
- **WHEN** 用户在统一工作台中先执行一次纯搜索，再切换到 `AI 对话` 继续提问
- **THEN** 系统 MUST 在同一会话中保留这两个回合，而不是创建新的独立页面上下文

### Requirement: 纯搜索模式 MUST 以对话形式呈现且不依赖 LLM
聊天执行界面在 `纯搜索` 模式下 MUST 以对话回合形式展示检索请求与固定回复摘要，并 MUST 不依赖 LLM 配置或模型可用性。

#### Scenario: 未配置 LLM 时仍可执行纯搜索
- **WHEN** 用户未配置任何 LLM，但在统一工作台中切换到 `纯搜索` 模式并提交查询
- **THEN** 系统 MUST 正常返回本地检索结果与对话式摘要回复，而不会要求先配置模型

### Requirement: 编辑运行期间 MUST 不弹出逐块确认
聊天执行界面在 AI 编辑运行期间 MUST 只展示执行进展、步骤叙事和检查器内容，而 MUST NOT 在每次小块编辑完成后打断流程要求用户即时确认；若本次运行产生可提交修改，系统 MUST 在整次运行结束后再进入统一草稿审阅阶段。

#### Scenario: 多块编辑在运行中连续完成
- **WHEN** AI 在一次运行中连续完成多次文档块修改
- **THEN** UI MUST 持续展示执行进展，并在整次运行完成后才展示统一审阅入口

### Requirement: 右侧时间线 MUST 支持回溯查看历史步骤
统一工作台的右侧时间线 MUST 允许用户回溯查看前一步、后一步或任意已完成步骤的检查器内容，以便理解 AI 执行路径和证据链。

#### Scenario: 用户切换查看不同步骤
- **WHEN** 用户在同一回合中依次点击某个读取步骤、某个编辑步骤和最终提交步骤
- **THEN** 右侧检查器 MUST 分别展示对应步骤的详情，而不会丢失已完成步骤的可访问性
